In grade 13, computer science is taught in the profile subject **KIT** (Technology) and in the **compulsory elective subject Computer Science** (*Wahlpflichtfach Informatik*, all branches of study); KIWI only exists in grade 12. Klonk can be used primarily in the programming learning areas of the compulsory elective subject, in particular object-oriented analysis and programming, and in project work. In KIT 13, it can only be used as a supplement in mechatronics and project work.

::warning
KIT 13 only applies from the school year **2028/29**. Until then, grade 13 in Technology is still taught *Technologie 13* according to the previous curriculum (including optional modules on network technology, modelling and mechatronics, without a dedicated programming learning area).
::

### 3 Mechatronics

**Content (summary):** *Sensors, actuators, transducers, interfaces; programming simple open-loop and closed-loop control processes (e.g. traffic light control)*

#### Use of Klonk

This learning area targets real hardware; Klonk does not replace it. For the **control logic**, however, the character can serve as a model: sensors (`isWall()`, `isMark()`, `brickCount()`) provide inputs, and commands take the role of the actuators. A traffic light control, for example, can be programmed as a sequence of states with marks in three colors and `sleep()` before it is transferred to the microcontroller.

### 10 Advanced Competence-Oriented Project Work

#### Use of Klonk

Projects on future technologies such as robotics are possible: several characters sharing a corridor, a plan from a file, test worlds for every case. [Projects](/en/klonk-script/projects) with several files allow division of labour in the team.

### Learning areas 1, 2, 4 to 9

Klonk does not cover machine learning with frameworks (k-nearest neighbours, decision tree, k-means), networks, control and electrical engineering, civil engineering and strength of materials, or system dynamics modelling.

### Object-Oriented Analysis and Programming

**Content (summary):** *Determining requirements; deriving objects, attributes, methods and associations; class diagram; dynamic models in graphical form; base class and derived class*

#### Use of Klonk

[Java](/en/klonk-script/java) or [C#](/en/klonk-script/csharp) can be used.

Klonk is suitable for the entire path from requirement to program: the requirement "A winter service vehicle drives along a road and grits it" leads to a class diagram with `Vehicle` and the specialisation `GrittingVehicle`, and the process leads to a sequence diagram. Both models are then implemented and checked in the world.

| Competence expectation (summary) | Implementation in Klonk |
|---|---|
| Derive objects, attributes, methods from requirements | A vehicle *has* a character and a distance driven, it *can* drive |
| Create a class diagram | `Vehicle` – `character: Klonk`, `distance: int` – `drive()`, `getDistance()` |
| Dynamic models | Sequence diagram: `main` → `GrittingVehicle.drive()` → `Klonk.setMark()`/`step()` |
| Use objects of given classes | `new Klonk()` is the first character in the world |
| Derive custom classes, specialisation | `GrittingVehicle extends Vehicle` overrides `drive()` |

```java
import klonk.Klonk;
import static klonk.Klonk.*;

class Vehicle {                           // base class from the class diagram
    protected final Klonk character;
    protected int distance = 0;

    Vehicle(Klonk character) { this.character = character; }

    void drive() {
        while (!character.isWall()) {
            character.step();
            distance++;
        }
    }

    int getDistance() { return distance; }
}

class GrittingVehicle extends Vehicle {   // specialisation
    GrittingVehicle(Klonk character) { super(character); }

    @Override
    void drive() {
        while (!character.isWall()) {
            character.setMark(YELLOW);        // grit
            character.step();
            distance++;
        }
        character.setMark(YELLOW);
    }
}

public class Main {
    public static void main(String[] args) {
        Vehicle v = new GrittingVehicle(new Klonk());
        v.drive();
        System.out.println("Gritted " + (v.getDistance() + 1) + " cells");
    }
}
```

::note
The class `Klonk` is `final` – custom subclasses are created via a **custom** base class that holds the character as an attribute. This can be used to illustrate the distinction between association ("has a character") and inheritance ("is a vehicle").
::

### Fundamentals of Software Development and Procedural Programming

For students who only start the subject in grade 13, the notes on [Grade 12](/en/teaching/germany/bavaria/fos-bos/grade-12#computer-science-compulsory-elective) apply: start with control structures using the character, then decompose into custom functions.

### IT Project

#### Use of Klonk

As in grade 12, a Klonk [project](/en/klonk-script/projects) with several files, test worlds from the [world editor](/en/world/editor) and a process model (e.g. Scrum) is suitable – for example a winter service with several vehicles that divide the roads between them.

## Matching learning modules

The [learning modules](/en/teaching/modules/overview) contain tasks in blocks or Klonk-Script with automatic checking that students can work on independently – in class or at home. For students who only start the elective subject in grade 13, they are suitable for the introduction via control structures with the character and the subsequent decomposition into custom subroutines; the tasks themselves are not set in Java or C#:

- [Repetition with a fixed count](/en/teaching/modules/repeat) – count-controlled loops
- [Conditional repetition](/en/teaching/modules/while) – condition-controlled loops
- [Branching](/en/teaching/modules/conditions) – branching
- [Your own procedures](/en/teaching/modules/procedures) – decomposition into custom subroutines

## Notes for lesson planning

- **Linking model and program:** Class and sequence diagrams can be compared directly with the run in the world. For assessment, tasks in which the classes for a given class diagram are to be implemented (or vice versa) are suitable.
- **Test worlds:** Prepared worlds from the [world editor](/en/world/editor) are distributed as files; a program should work correctly in all intended cases.
- **License:** More than one character requires a license with the appropriate character quota (see [License](/en/administration/license)).
