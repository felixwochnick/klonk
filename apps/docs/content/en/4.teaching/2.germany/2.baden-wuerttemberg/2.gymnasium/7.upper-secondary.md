## Structured and object-oriented programming

*Variables, data types, type conversion, strings; classes, attributes, methods, references, access modifiers, encapsulation, constructors, inheritance; structogram, pseudocode, UML class diagram. LF only: among others polymorphism, abstract classes, generic data types, collections, lambda expressions*

**Tool:** [Java](/en/klonk-script/java) (or [Python](/en/klonk-script/python), [C#](/en/klonk-script/csharp)). Every character is an object of the class `Klonk`; custom classes hold a character as an **attribute** (association), since `Klonk` itself is `final`.

- **Class diagram first:** `BuildingCrew` *has a* `Klonk` character, `TowerBuilder` *is a* `BuildingCrew` – draw it as UML, then implement it.
- **Encapsulation:** attributes `private`, access via methods; a counter for placed bricks can only be changed via `place()`.
- **LF – polymorphism and collections:** Process an `ArrayList<Worker>` with different subclasses that all override `work()` in a `for` loop. Several characters require a [license](/en/administration/license).

Detailed examples can be found at [Bavaria, grade 9](/en/teaching/germany/bavaria/gymnasium/grade-9) and [grade 10](/en/teaching/germany/bavaria/gymnasium/grade-10).

## Data structures: stack and queue

*Stack (LIFO), queue (FIFO); graph as adjacency matrix and adjacency list; nodes, edges, degree, cycle*

A brick stack **is** a stack: `placeBrick(color)` = *push*, `pickBrick()` = *pop*, `isBrick(color)` checks the top element (*top*), `brickCount()` returns the size. The learners encapsulate this in their own class `BrickStack` and compare it with an implementation based on an array.

A maze world becomes a **graph**: cells are nodes, walkable neighboring cells are edges. The adjacency matrix is first set up by hand, and in the LF then generated by the character while exploring.

## Algorithms on data structures

*Linear and binary search; bubble sort, selection sort, insertion sort, one recursive sorting algorithm; running time (big O notation); Dijkstra by hand. LF only, among others: breadth-first and depth-first search on graphs, spanning trees, greedy*

- **Visible sorting:** A row of brick stacks is sorted by height. The heights are stored in an array; the character rebuilds every swap in the world – count comparisons and swaps.
- **Binary search:** In a sorted row, find the first position with height ≥ k – the character only walks to the cells that the search actually checks. The difference to linear search becomes visible as the number of steps.
- **LF – breadth-first search:** Compute the shortest path through the maze and walk it, leaving marks.
- **Dijkstra by hand:** Stack heights as edge weights; then implement it in the LF if desired.

## Recursion

*Base case and recursive step, e.g. Towers of Hanoi; divide and conquer; implementation. LF only: call tree/call stack, comparison iterative – recursive, backtracking*

The education plan explicitly names the **Towers of Hanoi** – with Klonk they become real towers: three stacks stand to the east, north and south of the character, the disks are bricks of different colors.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    static final String[] DISK = { YELLOW, GREEN, BLUE };   // small ... large
    static Klonk k;
    static int facing = 0;   // quarter turns to the left: 0 = east, 1 = north, 3 = south

    static void faceTowards(int direction) {
        while (facing != direction) {
            k.turnLeft();
            facing = (facing + 1) % 4;
        }
    }

    static void hanoi(int n, int from, int to, int via) {
        if (n == 0) return;                 // base case
        hanoi(n - 1, from, via, to);        // move smaller towers out of the way
        faceTowards(from);
        k.pickBrick();                      // take the top disk
        faceTowards(to);
        k.placeBrick(DISK[n - 1]);          // and put it down
        hanoi(n - 1, via, to, from);
    }

    public static void main(String[] args) {
        k = new Klonk();
        for (int i = DISK.length - 1; i >= 0; i--) {
            k.placeBrick(DISK[i]);          // build the starting tower in the east
        }
        hanoi(DISK.length, 0, 1, 3);        // from east to north via south
    }
}
```

- **Call stack (LF):** Set a breakpoint on `k.pickBrick()` – at every stop, the variable view shows `n`, `from` and `to` of the current call. Draw the call tree for three disks on paper beforehand.
- **Iterative vs. recursive (LF):** Solve "to the wall and back" once with a loop and once recursively.
- **Backtracking (LF):** The character recursively searches for a path through the maze, marks visited cells and turns back at dead ends.

## Automata and formal languages

*Finite automata with and without output (e.g. Mealy machine), state diagram and transition table; in the LF, among others, further automata and grammars*

The character as a **Mealy machine**: inputs are sensor values (`isWall()`, `isMark()`), outputs are actions (`step()`, `turnLeft()`, `setMark()`). A state diagram "along the right-hand wall" becomes a transition table and then a program with a variable `state`. For grammars, [Klonk-Script](/en/klonk-script/introduction) is suitable as a small, manageable language.

## Project management

*Project brief, phases, requirements, acceptance; process models (waterfall, agile); requirements specification, functional specification, user stories; prototype*

- **Multi-file projects:** [Projects](/en/klonk-script/projects) with several Java files in packages, as a real folder or a browser project.
- **User stories:** "As the site manager, I want the character to implement a building plan in JSON format" – with `JsonObject` from Klonk's Java library.
- **Acceptance:** Test worlds from the [world editor](/en/world/editor) as acceptance criteria; the program must deliver the expected result in every world.
