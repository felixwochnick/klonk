With the **Model Context Protocol (MCP)**, AI assistants such as Claude, ChatGPT, GitHub Copilot or Cursor use Klonk on behalf of an account. Teachers can set things up in a conversation, for example:

- “Split 7a into groups of four, each group works in a shared world.”
- “Release module E4 for 7a and 7b, blocks only.”
- “Which modules fit grade 8 according to the curriculum?”
- “Create the classes 5a to 5d and assign them to grade 5.”

Klonk has two MCP servers:

| Server | Address | Content |
|---|---|---|
| **Learning app** | `https://app.<your-domain>/mcp` | Teaching: classes you lead, learning modules and curriculum recommendations, releases, subgroups (teams), learning progress |
| **Administration** | `https://admin.<your-domain>/mcp` | Organization (state, school form), accounts, classes and groups, members |

The exact addresses are shown in Klonk under **Settings → AI assistants (MCP)**.

## Enabling

Access for AI assistants is part of the [license](/en/administration/license) (feature “External AI assistants (MCP)”). Without it the MCP servers only offer the account query, and no new connections can be created.

Access is **off** for every account at first. Admins of the organization enable it under **Administration → Accounts → ⋯ → AI access (MCP)** – per account with a level (also for their own account):

| Level | The AI assistant may |
|---|---|
| **Off** | nothing; existing connections are disconnected immediately |
| **Read only** | view classes, accounts, learning modules and progress |
| **Read and change** | also create and change: classes, members, releases, teams |
| **Full** | also delete, lock accounts, create accounts and set passwords |

An AI assistant can never do more than the account itself: a teacher with level “Full” still only manages the classes they lead and only resets passwords of learners. Every connection also has its own level; the lower one applies. Platform operators set the level for private accounts under **Administration → Private accounts**.

## Connecting

### Claude, ChatGPT and other assistants with sign-in

Add the address of the MCP server as a connector or MCP server in your AI assistant – in Claude for example under **Settings → Connectors → Add custom connector**. The assistant then forwards you to the Klonk sign-in. Afterwards Klonk asks what the assistant may do; the choice goes at most up to the level of the account.

Each server needs its own connection. Connected assistants are listed under **Settings → AI assistants (MCP)** and can be revoked there at any time.

### Personal tokens

For programs without a sign-in dialog (scripts, older versions of development environments) create a token under **Settings → AI assistants (MCP) → Personal token** – with name, level and validity (30, 90 or 365 days). The token is shown only once and works for both servers. Example for Claude Code:

```bash
claude mcp add --transport http klonk https://app.<your-domain>/mcp --header "Authorization: Bearer klonk_pat_…"
```

Treat tokens like passwords.

## Tools

| Server | Tool | Level |
|---|---|---|
| both | account and level of the connection | Read only |
| Learning app | teaching overview, learning modules (with curriculum recommendation), module details, class, learning progress | Read only |
| Learning app | release or withdraw learning modules, create subgroups, split a class randomly into teams, change a subgroup | Read and change |
| Learning app | delete a subgroup | Full |
| Administration | organization, accounts, classes and groups, members of a group | Read only |
| Administration | set school form (admins), create and change groups, add members, change accounts (admins) | Read and change |
| Administration | remove members, delete groups, create and lock accounts, reset passwords | Full |

Klonk does not hand out sample solutions of learning modules via MCP.

## Data protection

Whatever the AI assistant requests – such as names of learners or the progress of a class – goes to the provider of the assistant. Before enabling access, check whether the service is approved for this (data processing agreement, location) and only grant the level that is actually needed. Learners usually do not need access.

## Self-hosting

The MCP servers run in the app and the administration under `/mcp`. Sign-in uses OAuth 2.1 (authorization code with PKCE, programs register themselves); the authorization server is the [central sign-in](/en/administration/sign-in) `auth.*`, without it each app itself. Klonk stores tokens only as hashes. If an access gate is active in front of the proxy (`KLONK_GATE`), `/mcp`, `/.well-known/oauth-*`, `/oauth/token` and `/oauth/register` stay reachable – they check access themselves; the consent page `/oauth/authorize` stays behind the gate.
