title: Diagrams
description: Structograms, class and object diagrams are drawn automatically from your program – ER diagrams from your database.
---

Klonk draws diagrams for your code by itself – you don't have to draw anything by hand. They live in the editor on the right, in the **Diagram** tab next to World and Docs, and update while you type.

| Diagram | Shows | Languages |
|---|---|---|
| **Structogram** | how a program runs (Nassi-Shneiderman, DIN 66261) | all: Klonk-Script, blocks, JavaScript/TypeScript, Python, Java, C# |
| **Class diagram** | classes with attributes and methods, inheritance, relationships (UML) | JavaScript/TypeScript, Python, Java, C# |
| **Object diagram** | objects with their values and references at one moment (UML) | JavaScript/TypeScript, Python, Java, C# |
| **ER diagram** | tables and relationships of a database | SQLite, PostgreSQL |

Clicking an element jumps to the matching line of code. The download button saves a diagram as **SVG** or **PNG**, e.g. for a worksheet or a presentation. Exports are always light.

## Structogram

Every statement becomes a box, every branch a triangle with the branches *true* and *false*, every loop a frame:

- **Pre-test loop:** `repeat 3 times`, `repeat while …`, `while`, `for`
- **Post-test loop:** `do … while`
- **Endless loop:** `repeat forever`, `while (true)`
- **Case selection:** `switch` or `match`
- **Call** of your own subroutine: box with double side lines
- **Exit:** `break`, `return`

The main program and every procedure, function or method you write get a structogram of their own. At the top you choose *All structograms* or a single one.

While the program runs or pauses in the debugger, the current line is highlighted in the structogram. You can watch the program move through loops and branches.

```klonk
repeat while not isWall
  if isBrick then
    pickBrick
  else
    step
  end
end
```

## Class diagram

Klonk reads the classes from your code:

- **Attributes** and **methods** with visibility: `+` public, `-` private, `#` protected, `~` package.
- **Static** members are underlined, **abstract** ones italic. `«interface»`, `«abstract»` and `«enumeration»` appear above the name.
- **Inheritance** (arrow with a hollow triangle) and **implementation** (dashed).
- **Associations:** when a class has an attribute whose type is another class, an arrow points there, labelled with the attribute name. Lists and arrays get the multiplicity `*`.

If your code uses the class `Klonk` or `Database`, it appears dashed as a library class.

In a project you choose *This file* or *Whole project* at the top. Clicking a class from another file opens that file.

Where the code has no types (Python, JavaScript), Klonk derives them from the assignment: `self.points = 0` becomes `points: int`, `this.robot = new Klonk()` becomes `robot: Klonk`. In Python, names starting with `_` count as protected and with `__` as private.

## Object diagram

The object diagram shows the objects that exist **right now**:

1. Set a **breakpoint** (click left of the line number).
2. Run the program.
3. When it pauses, the *Object diagram* tab shows all objects that can be reached from the variables.

Every object is a box `name : Class` (underlined) with its attribute values. References to other objects are arrows labelled with the attribute name. If two variables point to the **same** object, there is only one box. This makes visible what an assignment like `b = a` really does.

Lists and arrays appear as objects of their own with the entries `[0]`, `[1]` … Characters (`Klonk`) also show their position and direction in the world. With *Step* you can watch new objects appear and references change. When the program continues, the diagram keeps the state of the last pause.

```python
from klonk import Klonk

class Account:
    def __init__(self, owner):
        self.owner = owner
        self.balance = 0

a = Account("Mia")
b = a           # no new object – b points to the same account
b.balance = 10
print(a.balance) # breakpoint here: the object diagram shows one account with a, b
```

## ER diagram

Open a database (`.sqlite.sql` or `.postgres.sql`) and switch from *SQL* to **ER diagram** at the top. Klonk draws the diagram from the tables:

- **Tables** become entities, their columns attributes. The primary key is underlined.
- **Foreign keys** (`REFERENCES`) become relationships. A unique foreign key (`UNIQUE`) makes a 1:1 relationship, otherwise it is 1:n.
- **Junction tables** whose primary key consists of two foreign keys become n:m relationships. Their other columns are attached to the relationship.

Choose the notation at the top:

| Notation | Looks like |
|---|---|
| **Chen (1:n)** | entities as rectangles, attributes as ellipses, relationships as diamonds, cardinalities 1, n, m |
| **Chen (min,max)** | as above, with (min,max) pairs such as `(0,1)` and `(0,*)` |
| **Crow's foot** | tables with all columns (PK/FK), lines with crow's-foot ends |
| **Relational schema** | text such as `students(id, first_name, ↑class_id)`: keys underlined, foreign keys marked with ↑ |

Clicking a table shows its rows in the SQL console. Relationships only appear when the schema contains foreign keys:

```sql
CREATE TABLE students (
  id INTEGER PRIMARY KEY,
  first_name TEXT NOT NULL,
  class_id INTEGER NOT NULL REFERENCES classes(id)  -- NOT NULL ⇒ (1,1) instead of (0,1)
);
```
