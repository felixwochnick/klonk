## Rekursion und Backtracking

*Iterative und rekursive Algorithmen; Teilen und Herrschen; Backtracking (LK)*

Mit Klonk lässt sich Rekursion **beobachten**: Jeder Aufruf bewegt die Figur, der Rückweg läuft die Aufrufe in umgekehrter Reihenfolge ab.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    /** Rekursiv bis zur Wand und denselben Weg zurück; liefert den Abstand zur Wand. */
    static int hinUndZurueck(Klonk figur) {
        if (figur.isWall()) {                 // Abbruchbedingung
            figur.setMark(RED);
            figur.turnLeft();
            figur.turnLeft();
            return 0;
        }
        figur.step();
        int abstand = hinUndZurueck(figur) + 1;   // rekursiver Aufruf
        figur.step();                             // läuft erst auf dem Rückweg
        return abstand;
    }

    public static void main(String[] args) {
        Klonk klonk = new Klonk();
        System.out.println("Abstand zur Wand: " + hinUndZurueck(klonk));
    }
}
```

Ideen für den Unterricht:

- **Rekursiv vs. iterativ:** Dieselbe Aufgabe mit Schleife und rekursiv lösen und im Einzelschritt vergleichen.
- **Backtracking im Labyrinth (LK):** Ein Labyrinth aus Quadern im [Welt-Editor](/de/world/editor) bauen. Die Figur probiert rekursiv jede Richtung, merkt sich besuchte Felder in einem zweidimensionalen Feld `besucht[x][y]` (Position über `positionX()`/`positionY()`) und kehrt in Sackgassen um – die Marken bleiben als sichtbare Spur.
- **Graphen (LK, neuer Lehrplan):** Die Welt als Gittergraph – freie Felder sind Knoten, Nachbarfelder ohne Quader sind Kanten. Breitensuche mit einer Schlange findet den kürzesten Weg, den die Figur danach abläuft.

## Datenstrukturen und Abiturklassen

Klonk bringt die Klassen des Zentralabiturs (`List`, `Stack`, `Queue`, `BinaryTree` …) **nicht** mit. Möglich sind:

- **Selbst implementieren:** Eine einfache Schlange oder ein Stapel als eigene Klasse – im LK verlangt der Lehrplan ohnehin, Operationen dynamischer Datenstrukturen zu implementieren.
- **Als Projektdateien:** Den Quelltext der Abiturklassen als eigene `.java`-Dateien in ein [Projekt](/de/klonk-script/projects) legen. Mehrere Java-Dateien in einem Projekt brauchen eine Lizenz.

Beispiel: Eine `Queue` von Aufträgen („baue Mauer“, „markiere Reihe“) wird von einer Figur abgearbeitet; mit einem `Stack` merkt sich die Figur ihren Weg und läuft ihn rückwärts zurück.

## Objektorientierte Modellierung

*Abstrakte Klassen, Vererbung, Polymorphie, Assoziationen mit Multiplizitäten, Implementationsdiagramme*

Eine abstrakte Klasse `Arbeiter` mit den Unterklassen `Maurer` und `Markierer`, die eine `Baustelle` (1:n) in einer Schleife aufruft, zeigt Polymorphie mit sichtbarem Ergebnis – vgl. das Beispiel unter [Bayern, Klasse 10](/de/teaching/germany/bavaria/gymnasium/grade-10). Die Klasse `Klonk` ist `final`; eigene Hierarchien entstehen über Klassen, die eine Figur als Attribut haben. Mehr als eine Figur braucht eine Lizenz (siehe [Lizenz](/de/administration/license)).

## Projekte und Entwicklungsumgebung

Der Lehrplan verlangt den Einsatz einer **didaktisch orientierten Entwicklungsumgebung** zum Entwerfen, Implementieren und Testen. Klonk bietet dafür Haltepunkte, Einzelschritt und Variablenansicht sowie [Projekte](/de/klonk-script/projects) mit Packages. Testwelten als Dateien im Projekt prüfen Sonderfälle (leere Welt, Welt ohne Ausgang, Figur direkt vor der Wand).

## Was Klonk nicht abdeckt

Datenbanken und SQL, Rechneraufbau und Netzwerke, Client-Server-Kommunikation, Verschlüsselung, künstliche neuronale Netze sowie Datenschutz. Für Automaten und Grammatiken taugt Klonk nur als Beispiel (z. B. die Syntax von Klonk-Script als kleine formale Sprache).
