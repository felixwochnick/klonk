Klonk ships its own reverse proxy (Caddy). All you need is a server with Docker and **one DNS record**: `*.klonk.example` and `klonk.example` point to the server. The proxy routes requests:

| Address | Service |
|---|---|
| `app.klonk.example` | Learning app |
| `admin.klonk.example` | Admin area |
| `auth.klonk.example` | Central sign-in |
| `docs.klonk.example` | Documentation |
| `klonk.example` | Redirect to the app |

On startup every instance checks whether the database schema is up to date and applies missing migrations automatically.

## Installation

Prebuilt images for `amd64` and `arm64` are published to the GitHub Container Registry (`ghcr.io/felixwochnick/klonk-app`, `-admin`, `-auth`, `-proxy`):

```bash
git clone https://github.com/felixwochnick/klonk.git
cd klonk
cp docker/.env.example docker/.env   # set domain, TLS mode, secrets and KLONK_VERSION
docker compose --env-file docker/.env -f docker/docker-compose.yml up -d
```

On first visit to `admin.klonk.example` you create your school or company and the first admin account.

### Choosing a version and updating

`KLONK_VERSION` selects the images: a fixed version (`0.1.0`), the latest patch of a series (`0.1`) or `latest`. All versions are listed under [Releases](https://github.com/felixwochnick/klonk/releases).

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yml pull
docker compose --env-file docker/.env -f docker/docker-compose.yml up -d
```

To build the images yourself, add `--build` to the start command.

## SSL certificates

Choose the mode with `KLONK_TLS`:

| Mode | Description |
|---|---|
| `http` | Let's Encrypt via HTTP challenge. Ports 80 and 443 must be reachable from the internet. Set `KLONK_ACME_EMAIL`. |
| `ionos` | Let's Encrypt via DNS challenge using the IONOS API – works behind firewalls/NAT too. Set `KLONK_ACME_EMAIL` and `IONOS_API_TOKEN` (format `<prefix>.<secret>`, created at developer.hosting.ionos.de). |
| `internal` | Self-signed certificates from a local CA – for testing. |
| `off` | Plain HTTP when another proxy already terminates TLS (keep `KLONK_PUBLIC_SCHEME=https`). |

Certificates are renewed automatically and stored in the `caddy-data` volume.

::callout{icon="i-lucide-shield" color="warning"}
Keep `KLONK_ENCRYPTION_KEY` safe – it encrypts SSO secrets in the database. If it is lost, OIDC and LDAP credentials have to be entered again.
::

## Important variables (`docker/.env`)

| Variable | Description |
|---|---|
| `KLONK_VERSION` | Image version, e.g. `0.1.0`, `0.1` or `latest` |
| `KLONK_DOMAIN` | Main domain, e.g. `klonk.example` |
| `KLONK_TLS`, `KLONK_ACME_EMAIL`, `IONOS_API_TOKEN` | Certificates (see above) |
| `KLONK_APP_SECRET` | Seals the session cookies |
| `KLONK_ENCRYPTION_KEY` | Encrypts SSO secrets |
| `POSTGRES_PASSWORD` | Database password |
| `KLONK_WEBSITE_URLS` | Further sites allowed to query the sign-in status |
| `KLONK_AI_*` | Optional default for the [AI assistant](/en/administration/ai) |
| `KLONK_CLOUD_USER_QUOTA_MB`, `KLONK_CLOUD_GROUP_QUOTA_MB` | [Klonk Cloud](/en/klonk-script/cloud) storage per account and group folder (default 50 / 200 MB) |
| `KLONK_ID_*`, `KLONK_GOOGLE_*`, … | Optional sign-in providers, see [Private accounts & operators](/en/administration/private-accounts) |

## Central sign-in

All services share one sign-in via `auth.klonk.example`: once signed in there, you are signed in everywhere, and signing out applies everywhere too. Do not host third-party content on these subdomains, as they receive the session cookie.

Other sites on the same domain (e.g. your own website) query the sign-in status like this:

```js
const { user } = await fetch('https://auth.klonk.example/api/session', { credentials: 'include' }).then(r => r.json())
```

## Try everything locally (`*.klonk.localhost`)

For testing there is a complete stack with self-signed certificates plus a test LDAP and a test identity provider:

```bash
pnpm stack:up      # build and start
pnpm stack:down    # stop
pnpm stack:reset   # stop and delete data
```

Addresses under `.localhost` always point to your own machine – no `/etc/hosts` entry is needed. Once, make the local root CA known to the browser (Chrome/Chromium on Linux):

```bash
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "Klonk Local CA" -i docker/local/klonk-local-ca.crt
```

Test accounts in the test IdP and test LDAP: `tim`, `lisa` (teachers group), `anna` (admins group), password `<name>-pass`. Use them in the admin area to try LDAP (`ldap://glauth:3893`, bind `cn=service,ou=svcaccts,dc=klonk,dc=test` / `service-pass`, base DN `dc=klonk,dc=test`, filter `(&(objectClass=posixAccount)(cn={{username}}))`) and OIDC (`https://sso.klonk.localhost/dex`, client `klonk` / `klonk-dev-secret`). `anna` signs in as owner via Klonk ID.

### Local test mode

On your own machine – i.e. under `localhost` or `*.localhost` – **all features are unlocked**, even without a license token. The app then shows "Local test mode" at the top. It only unlocks when both the server and the browser see a local name; anyone accessing via a real domain always gets the regular license. Running Klonk for real requires a [license token](/en/administration/license) – circumventing the check (e.g. through a proxy) is prohibited by the [license](/en/self-hosting/license). Turn the mode off with `NUXT_LICENSE_LOCAL_MODE=off`.
