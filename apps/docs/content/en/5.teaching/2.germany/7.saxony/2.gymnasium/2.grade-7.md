Grade 7 is the start of the new compulsory subject. Programming only takes place in the short learning area 3 – according to the curriculum in a **didactically reduced programming environment** (*didaktisch reduzierte Programmierumgebung*) with a block-based language. In addition, there are concepts of object orientation (learning area 1) and the IPO model (input–processing–output, *EVA-Modell*, learning area 2), for which the Klonk character is a vivid example.

## 3 Algorithms

*Know algorithmic processes from everyday life and describe them verbally; solve simple problems in a block-based language or visual programming environment; turn verbal descriptions into programs*

**Tool:** [Blocks](/en/klonk-script/blocks). They are a block-based language in the sense of the curriculum, run in the browser and show which block is currently running during execution. Those who are faster can switch to the generated [Klonk-Script](/en/klonk-script/introduction).

### Lesson sequence (6 lessons)

| Lesson | Content | Task in Klonk |
|---|---|---|
| 1 | Algorithms in everyday life | Directions through the classroom – then the same description for the character |
| 2 | Verbal description ⇒ program | “Walk three cells, place a brick, turn around” as a block program |
| 3 | Repetition with a fixed count | Build a tower of five bricks, walk around a square |
| 4 | Repetition with a condition | Walk to the wall – in worlds of different sizes |
| 5 | Conditional statement | Place a brick only on marked cells |
| 6 | Small final task | Rebuild a given brick figure, compare solutions |

```klonk
// "Walk to the wall and mark every cell you walk over."
setMark(yellow)
repeat while not isWall
  step
  setMark(yellow)
end
```

Control structures are only covered completely in grade 8 – in grade 7 it is enough if the learners know the building blocks and can turn verbal descriptions into programs.

## 1 Information and data

*Distinguish information and data, binary representation, units; create digital media; object orientation: class and object, attribute and method; automation with spreadsheets; separation of content and design*

The learning area mainly deals with application software (graphics, spreadsheets, presentations) – Klonk is not intended for that. For the **object orientation** part, however, the character is a good example that comes back later in grade 10 and in upper secondary:

| Concept | Example in Klonk |
|---|---|
| Object | the character “Klonk” in the world |
| Class | all characters have the same properties and abilities |
| Attribute and attribute value | name = “Klonk”, position = cell 1\|3, viewing direction = east, look |
| Method | `step`, `turnLeft`, `placeBrick`, `setMark` |

An object card of the character before and after a program run shows: methods change attribute values.

## 2 Computer systems

*Hardware components; transfer the IPO model to real systems, describe input and output processes with graphs (state diagram, transition graph); operating systems, file type and application*

Hardware and operating systems are not a topic for Klonk. The character is still useful as a model:

- **IPO:** input = sensors (`isWall`, `isBrick`, `isMark`), processing = program, output = movement, bricks and marks.
- **State diagram:** The viewing direction as the states *north, east, south, west*; the transitions are `turnLeft` and `turnRight`. The learners draw the transition graph and check it in Klonk.
- **File type and application:** Name worlds (`.klonkworld.json`) and programs (`.blocks`, `.klonk`) sensibly in a [project](/en/klonk-script/projects) and store them in folders.
