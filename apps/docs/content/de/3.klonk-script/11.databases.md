Klonk bringt zwei Datenbanken mit, die vollständig im Browser laufen – ohne Server, auch offline:

- **SQLite** – klein und schnell, wie in vielen Schulbüchern und in *DB Browser for SQLite*.
- **PostgreSQL** (über PGlite) – eine „große“ Datenbank, wie sie in Unternehmen läuft. Sie wird erst geladen, wenn du sie zum ersten Mal brauchst.

## Datenbank anlegen

Im Projekt über **Neue Datei** → **Datenbank (SQLite)** oder **Datenbank (PostgreSQL)**. Neue Datenbanken enthalten ein kleines Beispiel mit den Tabellen `klassen` und `schueler`.

Eine Datenbank ist eine Datei im Projekt: `schule.sqlite.sql` bzw. `schule.postgres.sql`. Darin steht die ganze Datenbank als SQL-Text (Tabellen und Daten). Nach jeder Änderung speichert Klonk sie automatisch. Weil es eine normale Projektdatei ist, wandert sie mit in die [Klonk Cloud](/de/klonk-script/cloud) – Lehrkräfte können Datenbanken so auch als Aufgabe verteilen.

**SQLite-Datei importieren …** übernimmt eine vorhandene SQLite-Datei (`.db`, `.sqlite`), z. B. aus *DB Browser for SQLite*. Umgekehrt lädt **Als SQLite-Datei herunterladen** eine SQLite-Datenbank als `.db`-Datei herunter.

## SQL-Konsole

Ein Klick auf die Datenbank öffnet sie:

- **Links** stehen die Tabellen mit ihren Spalten (🔑 = Primärschlüssel) und der Zahl der Zeilen. Ein Klick auf eine Tabelle zeigt ihre ersten Zeilen.
- **Rechts** schreibst du SQL. **Strg+Enter** (oder **Ausführen**) führt alles aus – oder nur den markierten Teil. Beim Tippen schlägt der Editor Tabellen und Spalten vor.
- **Unten** erscheinen die Ergebnisse als Tabelle, bei Änderungen die Zahl der geänderten Zeilen. Fehler zeigen die Zeile an.

```sql
SELECT s.vorname, k.name AS klasse
FROM schueler s
JOIN klassen k ON k.id = s.klasse_id
ORDER BY k.name, s.vorname;
```

SQLite prüft in Klonk auch Fremdschlüssel (`REFERENCES`) – wie andere Datenbanken.

Oben wechselst du von **SQL** zum **ER-Diagramm**: Klonk zeichnet die Tabellen und ihre Beziehungen aus den Fremdschlüsseln – in Chen-Notation (1:n oder (min,max)), als Krähenfuß-Diagramm oder als Relationenschema. Mehr dazu unter [Diagramme](/de/klonk-script/diagrams#er-diagramm).

Für Abfragen, die du aufheben willst, gibt es **Neue Datei** → **SQL-Abfrage** (`.sql`). Oben wählst du, auf welcher Datenbank sie läuft – auch die Welt.

## Die Welt als Datenbank

Jede `.sql`-Abfrage kann statt einer Datenbank die **Welt** befragen – mit SQLite oder PostgreSQL. Die Welt erscheint dabei als Tabellen:

| Tabelle | Spalten |
|---|---|
| `welt` | `breite`, `tiefe`, `hoehe` |
| `figuren` | `name`, `x`, `y`, `richtung` (`norden` …), `aussehen` (`männlich`, `weiblich`, `divers`) |
| `ziegel` | `x`, `y`, `ebene` (1 = unten), `farbe` |
| `marken` | `x`, `y`, `farbe` (`gelb`, `rot`, `blau`, `grün`) |
| `quader` | `x`, `y` |

Felder zählen ab 1, wie bei `positionX()`. Mit englischer Oberfläche heißen Tabellen und Werte englisch (`bricks`, `color = 'red'` …).

```sql
-- Wie viele Ziegel liegen je Farbe?
SELECT farbe, count(*) AS anzahl FROM ziegel GROUP BY farbe ORDER BY anzahl DESC;

-- Eine Mauer bauen und Klonk umdrehen
INSERT INTO ziegel (x, y, ebene, farbe) VALUES (3, 1, 1, 'rot'), (3, 2, 1, 'rot'), (3, 3, 1, 'rot');
UPDATE figuren SET richtung = 'osten' WHERE name = 'Klonk';
```

Abfragen sehen die Welt, wie sie gerade angezeigt wird – auch nach einem Programmlauf („Wie viele Ziegel hat Klonk gelegt?“). Änderungen erscheinen sofort in der 3D-Ansicht. **Als Startwelt speichern** übernimmt sie in die Projektwelt; sonst setzt der nächste Programmlauf die Welt wieder zurück. Ungültige Werte (z. B. die Farbe `pink`) lehnt die Datenbank selbst ab.

## Datenbanken in Programmen

In JavaScript/TypeScript, Python, Java und C# öffnet `Database` eine Datenbank des Projekts (Dateiname ohne Endung) oder legt eine leere nur für diesen Lauf an:

| | |
|---|---|
| `Database.open("schule")` | Datenbank `schule.sqlite.sql` bzw. `schule.postgres.sql` des Projekts |
| `Database.memory()` / `Database.memory("postgres")` | neue, leere Datenbank nur für diesen Lauf |
| `query(sql, parameter)` | Abfrage ⇒ Zeilen (Spalte ⇒ Wert) |
| `queryOne(sql, parameter)` | erste Zeile oder nichts |
| `execute(sql, parameter)` | INSERT, UPDATE, DELETE, CREATE … ⇒ Zahl geänderter Zeilen |
| `tables()` | Namen der Tabellen |

Werte setzt du über **Platzhalter** ein, nie durch Zusammenkleben von Text: in SQLite `?`, in PostgreSQL `$1`, `$2` … Änderungen aus Programmen werden wie in der Konsole in der Datei gespeichert.

::code-group
```python [Python]
from klonk import Database, DatabaseError

db = Database.open("schule")
for s in db.query("SELECT vorname FROM schueler WHERE klasse_id = ?", (1,)):
    print(s["vorname"])
db.execute("INSERT INTO schueler (id, vorname, klasse_id) VALUES (?, ?, ?)", (4, "Eva", 2))
print(db.query_one("SELECT count(*) AS n FROM schueler")["n"])

try:
    db.query("SELECT nix FROM schueler")
except DatabaseError as fehler:
    print("Fehler:", fehler)
```

```js [JavaScript]
import { Database } from 'klonk'

const db = Database.open('schule')
for (const s of db.query('SELECT vorname FROM schueler WHERE klasse_id = ?', [1]))
  console.log(s.vorname)
db.execute('INSERT INTO schueler (id, vorname, klasse_id) VALUES (?, ?, ?)', [4, 'Eva', 2])
console.log(db.queryOne('SELECT count(*) AS n FROM schueler').n)
```

```java [Java]
import klonk.Database;
import klonk.DatabaseException;
import klonk.Row;

public class Main {
    public static void main(String[] args) {
        Database db = Database.open("schule");
        for (Row s : db.query("SELECT vorname FROM schueler WHERE klasse_id = ?", 1))
            System.out.println(s.getString("vorname"));
        db.execute("INSERT INTO schueler (id, vorname, klasse_id) VALUES (?, ?, ?)", 4, "Eva", 2);
        System.out.println(db.queryOne("SELECT count(*) AS n FROM schueler").getInt("n"));
    }
}
```

```csharp [C#]
using klonk;

var db = Database.Open("schule");
foreach (var s in db.Query("SELECT vorname FROM schueler WHERE klasse_id = ?", 1))
    Console.WriteLine(s.GetString("vorname"));
db.Execute("INSERT INTO schueler (id, vorname, klasse_id) VALUES (?, ?, ?)", 4, "Eva", 2);
Console.WriteLine(db.QueryOne("SELECT count(*) AS n FROM schueler")!.GetInt("n"));
```
::

Die Schreibweise folgt der Sprache: Python `query_one`, C# `Query`/`QueryOne`/`Execute`/`Tables`. Zeilen sind in Python `dict`s, in JavaScript Objekte, in Java und C# `Row`-Objekte mit `getString`/`getInt`/`getDouble`/`isNull` (C#: `GetString` …). SQL-Fehler lassen sich abfangen: `DatabaseError` (JavaScript, Python) bzw. `DatabaseException` (Java, C#).

Datenbanken und Figuren lassen sich verbinden – etwa ein Programm, das Aufträge aus einer Tabelle liest und die Figur Ziegel legen lässt:

```python
from klonk import Database, Klonk

db = Database.memory()
db.execute("CREATE TABLE auftrag (nr INTEGER PRIMARY KEY, farbe TEXT)")
db.execute("INSERT INTO auftrag (farbe) VALUES ('red'), ('blue'), ('yellow')")

klonk = Klonk()
for auftrag in db.query("SELECT farbe FROM auftrag ORDER BY nr"):
    klonk.place_brick(auftrag["farbe"])  # ein Turm in den Farben der Aufträge
```

Klonk-Script und Blöcke greifen nicht auf Datenbanken zu – dafür gibt es die Welt als Datenbank in der SQL-Konsole.
