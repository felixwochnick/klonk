## Context

In grade 12 (*Jahrgangsstufe 12*) there are three courses: computer science at **advanced** (eA, *erhöhtes Anforderungsniveau*) and **basic** level (gA, *grundlegendes Anforderungsniveau*), plus the gA course following **late-starting computer science** (*spät beginnende Informatik*). Common to all of them are the learning areas on recursion and practical software development; Klonk is particularly suited to these. The course following late-starting computer science adds object orientation and graphs. Klonk is not intended for trees, computer architecture and information security.

## Recursion

**Curriculum reference (short version):** *Recursive call, base case, linear and branching recursion; depth-first search*

**Using Klonk:** Recursion becomes **visible** in Klonk: every call moves the character, and on the way back the calls are completed in reverse order.

```klonk
// Linear recursion: to the wall and back the same way
procedure thereAndBack
  if isWall then
    setMark            // base case: turn around
    turnLeft
    turnLeft
  else
    step
    thereAndBack       // recursive call
    step               // only runs on the way back
  end
end

thereAndBack
```

Possible teaching ideas:

- **Recursive vs. iterative:** Solve the same task with a loop and recursively, and compare both solutions step by step.
- **Pyramid:** `pyramid(n)` builds a layer of width `n` and calls itself with `n - 2`.
- **Depth-first search in a maze:** The character recursively tries every direction, marks visited cells and backs out of dead ends (backtracking) – visible as a trail of marks. In Java or Python with an array `visited[x][y]`.
- **Infinite recursion:** If the base case is missing, Klonk reports the error in an understandable way instead of crashing.

## Graphs (gA following late-starting computer science)

As in [grade 11 (NTG)](/en/teaching/germany/bavaria/gymnasium/grade-11#_1-graphs): the world as a grid graph, here with **depth-first search** and Dijkstra.

## Concurrency

Several characters trying to reach the same cell illustrate **critical sections** and **deadlocks** (two characters blocking each other in a narrow corridor). Klonk runs the characters of a program one after another – the model is therefore suited to thinking through and simulating, not to real threads.

## Practical software development, project

**Curriculum reference (short version):** *Library classes; MVC, observer; project planning, waterfall, agile; tests, debugging; refactoring; documentation*

**Using Klonk:**

- **Projects with several files and packages** ([projects](/en/klonk-script/projects)), as a real folder on the computer or as a browser project.
- **Library classes:** In Java `JsonObject`, `Yaml`, `Xml`, in C# Newtonsoft.Json – e.g. to read building plans from files.
- **Debugging:** breakpoints, single steps and the variables view in all languages.
- **Agile:** user stories such as "As the site manager, I want the characters to build a plan from a file", sprints with a working intermediate state.
- **Testing:** test worlds as files in the project; each world checks one case.

## Notes for lesson planning

- **Plan for a license:** Concurrency with several characters, projects with several characters and imports between project files require a [license](/en/administration/license).
- **Project folders:** Real folders on the computer can be opened in Chrome and Edge; browser projects are available in other browsers.
- **Assessment:** In the project, for example, the project plan, test worlds with documented test cases and the working program can be assessed. Klonk has no submission or grading function; projects are exchanged as files.
