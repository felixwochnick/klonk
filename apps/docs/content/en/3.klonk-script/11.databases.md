Klonk ships two databases that run entirely in the browser – no server needed, offline too:

- **SQLite** – small and fast, as used in many textbooks and in *DB Browser for SQLite*.
- **PostgreSQL** (via PGlite) – a "big" database as used in companies. It is only loaded the first time you need it.

## Creating a database

In a project via **New file** → **Database (SQLite)** or **Database (PostgreSQL)**. New databases contain a small example with the tables `classes` and `students`.

A database is a file in the project: `school.sqlite.sql` or `school.postgres.sql`. It holds the whole database as SQL text (tables and data). Klonk saves it automatically after every change. Since it is a regular project file, it syncs through the [Klonk Cloud](/en/klonk-script/cloud) – teachers can hand out databases as assignments.

**Import SQLite file …** takes an existing SQLite file (`.db`, `.sqlite`), e.g. from *DB Browser for SQLite*. The other way round, **Download as SQLite file** saves an SQLite database as a `.db` file.

## SQL console

Clicking the database opens it:

- **On the left** are the tables with their columns (🔑 = primary key) and the number of rows. Clicking a table shows its first rows.
- **On the right** you write SQL. **Ctrl+Enter** (or **Run**) runs everything – or just the selection. The editor suggests tables and columns as you type.
- **Below** the results appear as a table, for changes the number of changed rows. Errors show the line.

```sql
SELECT s.first_name, c.name AS class
FROM students s
JOIN classes c ON c.id = s.class_id
ORDER BY c.name, s.first_name;
```

In Klonk, SQLite also checks foreign keys (`REFERENCES`) – like other databases.

For queries you want to keep there is **New file** → **SQL query** (`.sql`). At the top you choose the database it runs on – the world, too.

## The world as a database

Every `.sql` query can ask the **world** instead of a database – with SQLite or PostgreSQL. The world appears as tables:

| Table | Columns |
|---|---|
| `world` | `width`, `depth`, `height` |
| `characters` | `name`, `x`, `y`, `direction` (`north` …), `look` (`male`, `female`, `diverse`) |
| `bricks` | `x`, `y`, `level` (1 = bottom), `color` |
| `marks` | `x`, `y`, `color` (`yellow`, `red`, `blue`, `green`) |
| `blocks` | `x`, `y` |

Cells count from 1, like `positionX()`. With the German interface, tables and values are German (`ziegel`, `farbe = 'rot'` …).

```sql
-- How many bricks of each color?
SELECT color, count(*) AS total FROM bricks GROUP BY color ORDER BY total DESC;

-- Build a wall and turn Klonk around
INSERT INTO bricks (x, y, level, color) VALUES (3, 1, 1, 'red'), (3, 2, 1, 'red'), (3, 3, 1, 'red');
UPDATE characters SET direction = 'east' WHERE name = 'Klonk';
```

Queries see the world as it is currently shown – also after a program ran ("How many bricks did Klonk place?"). Changes appear in the 3D view right away. **Save as start world** keeps them in the project world; otherwise the next program run resets the world. The database itself rejects invalid values (e.g. the color `pink`).

## Databases in programs

In JavaScript/TypeScript, Python, Java and C#, `Database` opens a database of the project (file name without extension) or creates an empty one just for this run:

| | |
|---|---|
| `Database.open("school")` | database `school.sqlite.sql` or `school.postgres.sql` of the project |
| `Database.memory()` / `Database.memory("postgres")` | new, empty database just for this run |
| `query(sql, parameters)` | query ⇒ rows (column ⇒ value) |
| `queryOne(sql, parameters)` | first row or nothing |
| `execute(sql, parameters)` | INSERT, UPDATE, DELETE, CREATE … ⇒ number of changed rows |
| `tables()` | names of the tables |

Pass values through **placeholders**, never by gluing text together: `?` in SQLite, `$1`, `$2` … in PostgreSQL. Changes made by programs are saved to the file just like in the console.

::code-group
```python [Python]
from klonk import Database, DatabaseError

db = Database.open("school")
for s in db.query("SELECT first_name FROM students WHERE class_id = ?", (1,)):
    print(s["first_name"])
db.execute("INSERT INTO students (id, first_name, class_id) VALUES (?, ?, ?)", (4, "Eva", 2))
print(db.query_one("SELECT count(*) AS n FROM students")["n"])

try:
    db.query("SELECT nothing FROM students")
except DatabaseError as error:
    print("Error:", error)
```

```js [JavaScript]
import { Database } from 'klonk'

const db = Database.open('school')
for (const s of db.query('SELECT first_name FROM students WHERE class_id = ?', [1]))
  console.log(s.first_name)
db.execute('INSERT INTO students (id, first_name, class_id) VALUES (?, ?, ?)', [4, 'Eva', 2])
console.log(db.queryOne('SELECT count(*) AS n FROM students').n)
```

```java [Java]
import klonk.Database;
import klonk.DatabaseException;
import klonk.Row;

public class Main {
    public static void main(String[] args) {
        Database db = Database.open("school");
        for (Row s : db.query("SELECT first_name FROM students WHERE class_id = ?", 1))
            System.out.println(s.getString("first_name"));
        db.execute("INSERT INTO students (id, first_name, class_id) VALUES (?, ?, ?)", 4, "Eva", 2);
        System.out.println(db.queryOne("SELECT count(*) AS n FROM students").getInt("n"));
    }
}
```

```csharp [C#]
using klonk;

var db = Database.Open("school");
foreach (var s in db.Query("SELECT first_name FROM students WHERE class_id = ?", 1))
    Console.WriteLine(s.GetString("first_name"));
db.Execute("INSERT INTO students (id, first_name, class_id) VALUES (?, ?, ?)", 4, "Eva", 2);
Console.WriteLine(db.QueryOne("SELECT count(*) AS n FROM students")!.GetInt("n"));
```
::

Names follow the language: Python `query_one`, C# `Query`/`QueryOne`/`Execute`/`Tables`. Rows are `dict`s in Python, objects in JavaScript and `Row` objects in Java and C# with `getString`/`getInt`/`getDouble`/`isNull` (C#: `GetString` …). SQL errors can be caught: `DatabaseError` (JavaScript, Python) or `DatabaseException` (Java, C#).

Databases and characters work together – for example a program that reads orders from a table and lets the character place bricks:

```python
from klonk import Database, Klonk

db = Database.memory()
db.execute("CREATE TABLE orders (nr INTEGER PRIMARY KEY, color TEXT)")
db.execute("INSERT INTO orders (color) VALUES ('red'), ('blue'), ('yellow')")

klonk = Klonk()
for order in db.query("SELECT color FROM orders ORDER BY nr"):
    klonk.place_brick(order["color"])  # a tower in the colors of the orders
```

Klonk-Script and blocks do not access databases – use the world as a database in the SQL console instead.
