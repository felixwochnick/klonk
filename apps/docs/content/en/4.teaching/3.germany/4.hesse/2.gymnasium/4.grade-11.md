**Subject:** Computer science, introductory phase (*Einführungsphase*) "Introduction to computer science" (E1/E2) · **Applies to:** students who take computer science in the upper secondary level (G9: grade 11, G8: grade 10) · [Full KCGO text](https://kultus.hessen.de/sites/kultus.hessen.de/files/2025-10/kernkurriculum_gymnasiale_oberstufe-informatik.pdf)

## Overview

The basis is the **KCGO computer science, 2024 edition** (core curriculum for the upper secondary level, *Kerncurriculum gymnasiale Oberstufe*; as of 1 August 2025). It has applied to the introductory phase since the change of half-year in 2024/25 and is the basis for the state-wide Abitur exam (*Landesabitur*) for the first time in 2027.

Topic areas E.1 to E.3 are binding, together about **24 teaching weeks**; the remaining time is used for consolidation or for E.4 or E.5. As an example, the KCGO gives 3, 5 and 16 weeks for E.1, E.2 and E.3. Klonk is suitable for E.3 and the computer science project E.4; it does not cover E.1, E.2 and E.5.

## E.3 Basics of programming

**Reference to the KCGO (short version):** *Integer, floating-point number, Boolean, character, string, array; variables, operations, logical expressions, type conversion; statement, control structures, structogram; methods with and without return value, parameters; graphical user interfaces and event handling*

The KCGO requires an **object-oriented language**, without object-oriented modeling being the focus yet; the department (*Fachkonferenz*) chooses the language within the framework of the decree. In the state-wide Abitur, the algorithmics task is set in **Java** and **Python** – both languages run in Klonk in the browser, each with a debugger. The KCGO explicitly also names **robots** as possible contexts.

### Use of Klonk

| Content (short version) | Implementation in Klonk |
|---|---|
| Data types, variables, operations | Count steps (`int`), color as a `String`, sensor value as a `boolean` |
| Logical expressions | `!k.isWall() && !k.isBrick()` – walk as long as the way is clear and there is no brick |
| Control structures, structogram | Structogram first, then Java/Python; check with single step |
| Methods with/without return value, parameters | `buildStack(k, height)` builds, `countToWall(k)` returns a number |
| Array | Building plan as `int[]`: height of each stack |
| Type conversion | Include `positionX()` (number) in an output, read numbers from text |
| Graphical user interface, events | – (Klonk has no windows or buttons of its own; use a GUI library of the chosen language for that) |

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    // Method with parameters: build a stack to the left of the character
    static void buildStack(Klonk k, int height) {
        k.turnLeft();
        for (int i = 0; i < height; i++) {
            k.placeBrick(BLUE);
        }
        k.turnRight();
    }

    public static void main(String[] args) {
        Klonk k = new Klonk();
        int[] plan = {1, 3, 2, 3, 1};   // array with five stack heights
        int sum = 0;
        for (int i = 0; i < plan.length; i++) {
            buildStack(k, plan[i]);
            sum = sum + plan[i];
            if (!k.isWall()) {
                k.step();
            }
        }
        System.out.println(sum + " bricks used");
    }
}
```

### Teaching ideas

- **Building plan from an array:** As in the example – then calculate the maximum, sum or average of the heights. This prepares the searching and sorting algorithms in Q1.
- **Return value:** `int countToWall(Klonk k)` walks to the wall and returns the number of steps; the result controls the next building task.
- **Debugger:** Breakpoint in `buildStack` – at every stop, the variable view shows `height` and `i`; this makes the difference between a parameter and a local variable visible.
- **Python instead of Java:** The same program with a list instead of an array; the [Python introduction](/en/klonk-script/python) shows the notation (`k.place_brick(blue)`).

## E.4 Computer science project

**Reference to the KCGO (short version):** *Project tasks from E.1–E.3; division of labor, agreements, deadlines, merging into one product*

- **Building site in a team:** Each group programs a part of a building as its own method; at the end, everything is merged in one `main`.
- **Projects with several files:** In a [project](/en/klonk-script/projects), programs and worlds are stored as files; with a [license](/en/administration/license), classes from other files can be used.
- **Obstacle course:** Group A builds a world in the [world editor](/en/world/editor), group B writes the program that crosses it.

## E.1, E.2, E.5

Klonk does not cover computer networks, HTML/CSS and cryptology.

## Notes for lesson planning

- **Choose the language with the Abitur in mind:** Since the department sets the language and the state-wide Abitur offers Java and Python, Klonk can be used in the chosen language consistently from the introductory phase through to Q4.
- **Plan graphical user interfaces separately:** For graphical user interfaces and event handling, a GUI library of the chosen language outside Klonk should be planned.
- **Assessment:** Possible formats include writing a program for a given world, or implementing a structogram in Java or Python.
