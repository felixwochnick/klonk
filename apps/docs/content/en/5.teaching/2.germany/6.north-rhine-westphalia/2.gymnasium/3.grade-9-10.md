## Algorithms and variables

*Algorithmic properties (finiteness, unambiguity, termination); representations; variables of different types; modularisation; parameters; comment, modify and extend source code; targeted testing; appropriateness to the problem*

**Tool:** [Python](/en/klonk-script/python) – the language for unit IV in the example curriculum anyway – or [Klonk-Script](/en/klonk-script/introduction) in German first. The characters from grades 5/6 return, now as the object `Klonk()`.

| Competence expectation (short version) | Implementation in Klonk |
|---|---|
| Process data with logical and arithmetic operations | Count steps, add up bricks, combine conditions with `and`/`or`/`not` |
| Choose suitable data types | Number (steps), Boolean (`is_wall()`), text (color, name) |
| Algorithms with variables and modularisation | custom functions instead of long sequences of commands |
| Passing values with parameters | `walk_and_count(character, color)` – the same function for different characters and colors |
| Check termination | A loop without `step()` runs forever – pause it in the debugger and explain why it never ends |
| Comment, modify and extend source code | extend a given program with a function |
| Test in a targeted way | start the same program in several prepared worlds |

```python
from klonk import Klonk, green

def walk_and_count(character, color):
    """Walks to the wall, marks every cell and returns the number of steps."""
    steps = 0                            # integer
    while not character.is_wall():       # Boolean
        character.set_mark(color)
        character.step()
        steps += 1
    return steps

klonk = Klonk()
count = walk_and_count(klonk, green)
print(klonk.name + " walked " + str(count) + " steps")
```

With breakpoints and the variables view, the learners see how `steps` changes in every iteration and what value the parameter `color` has.

## Automata and formal languages

*Syntax and semantics; analyse source code for syntactic correctness; analyse and develop automata with a state transition diagram*

- **Syntax vs. semantics:** The editor underlines syntax errors while you type. A syntactically correct program that sends the character in the wrong direction shows the difference: written correctly, but with the wrong meaning.
- **Translating:** Klonk-Script can be translated between German and English – the keywords change, the structure (syntax) stays the same.
- **Character as an automaton:** As with Kara in example unit I, the characters have sensors and actions. The learners draw a state transition diagram (e.g. states “searching for the wall”, “building”, “done”) and implement it with a variable `state` and conditional statements. Klonk does not have a graphical automaton editor like Kara.

## Artificial intelligence

Only as a thought experiment: **reinforcement learning** – a character tries out paths in a maze and gets a “reward” when it reaches the goal. The learners play this through by hand and discuss which paths it would remember.

## What Klonk does not cover

Encryption, web pages (HTML as a document description language), logic circuits, license models, data protection and data security belong in other tools.
