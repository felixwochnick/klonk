## Context

Grade 7 is the grade in which Klonk can cover the largest share of the Gymnasium curriculum: learning area (*Lernbereich*) 2.3 requires describing processes as algorithms with control structures and implementing them with a programming tool – the purpose for which Robot Karol and Klonk are designed. The project in learning area 2.4 can also be carried out with Klonk. Klonk is not intended for learning areas 2.1 and 2.2.

## 2.3 Describing processes with algorithms

**Curriculum reference (short version):** *Concept of an algorithm; statement, sequence, one- and two-sided conditional statement, repetition with a fixed count and with a condition*

**Competence expectations (*Kompetenzerwartungen*, short version):** structure everyday problems, develop solution algorithms and describe them with control structures · implement simple algorithms with a programming tool.

**Using Klonk:** [Blocks](/en/klonk-script/blocks) to get started, then [Klonk-Script](/en/klonk-script/introduction) in German. The two representations can be compared at any time, as blocks generate Klonk-Script.

### Lesson sequence

The following lesson sequence introduces the control structures in the order of the curriculum:

| Step | Control structure | Task in Klonk |
|---|---|---|
| 1 | Statement, sequence | Lead the character to a target cell, build a wall of three bricks |
| 2 | Repetition with a fixed count | Walk around a square, build stairs (`repeat 4 times`) |
| 3 | Repetition with a condition | Walk to the wall – no matter how big the world is (`repeat while not isWall`) |
| 4 | One-sided conditional statement | On the way, place a brick only on marked cells |
| 5 | Two-sided conditional statement | Pick up a brick if there is one, otherwise place one |
| 6 | Nesting | Work through a whole area: row by row, turning at the edge |

```klonk
// Steps 3 + 5: walk to the wall and "flip" bricks
repeat while not isWall
  if isBrick then
    pickBrick
  else
    placeBrick(blue)
  end
  step
end
```

## 2.4 Project

**Curriculum reference (short version):** *Develop a hypertext structure or an algorithmic solution in a team; save intermediate states, document the work process*

**Using Klonk** – possible project topics:

- **Building site:** Each group builds a building (house, bridge, pyramid) out of bricks with a program.
- **Obstacle course:** One group builds a world with obstacles, another writes the program that gets through it – and vice versa.
- **Several characters:** With `create` and `switch`, several characters work together (e.g. one places bricks, the other sets marks). More than one character requires a [license](/en/administration/license).

With a [project](/en/klonk-script/projects), each group saves programs and worlds as files; this also covers the requirement to *save intermediate states*.

## Matching learning modules

The [learning modules](/en/teaching/modules/overview) contain tasks in blocks or Klonk-Script with automatic checking that students can work on independently – in class or at home. The following modules fit learning area 2.3 – in the order of the lesson sequence:

- **First steps: instructions** – instruction and sequence (step 1)
- **Repetition with a fixed count** – repetition with a fixed count, including nesting (steps 2 and 6)
- **Conditional repetition** – repetition with a condition (step 3)
- **Branching** – one- and two-sided conditional statements, also inside repetitions (steps 4 to 6)

## Notes for lesson planning

- **Structogram and program side by side:** Students first design a structogram (Nassi–Shneiderman diagram), then the block code. Blocks closely resemble structograms, so the transition requires little additional explanation. Afterwards, they compare their design with the [structogram](/en/klonk-script/diagrams#structogram) that Klonk automatically generates from the program in the *Diagram* tab; it can be exported as SVG or PNG, e.g. for worksheets.
- **Structogram while stepping:** During single-stepping, the structure block currently being executed is highlighted in the structogram. This shows how often the body of a loop is run and which branch of a conditional is taken.
- **Make the process visible:** With the speed slider and **Step** (F10), everyone can see which statement is currently being executed – with blocks, the current block is highlighted.
- **Check generality:** The same solution is started in a larger world or one built differently. Whether it still works there makes the difference between a fixed count and a condition tangible.
- **Prepare worlds:** Task worlds built in the [world editor](/en/world/editor) can be saved as files and handed out to the class.
- **Differentiation:** Students who progress faster can switch from block code to Klonk-Script or solve the same task in a more demanding world.
- **Assessment:** Options include, for example, a program for a given world or translating a structogram into a program (and vice versa). Since Klonk generates structograms itself, the direction program ⇒ structogram should be completed without access to Klonk. Submissions can be collected via [Klonk Cloud](/en/klonk-script/cloud) (distribute an assignment in the group folder, view submissions); Klonk has no grading function.
