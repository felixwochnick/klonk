## Algorithms: basic algorithmic building blocks

*Statement; loop with a fixed count and with a condition; branch; expressions with arithmetic and comparison operators; data types string, number, Boolean; passing and returning values; implementation in a (e.g. block-based) language; representing the flow of code sections*

The advanced course (3.1.2) adds: **variables as changeable value stores** (e.g. score, lap counter), designing algorithms, explaining graphical representations (flowchart) and examining code step by step. For level E, the reading guide explicitly names the movement path of a figure as an example.

**Tool:** [Blocks](/en/klonk-script/blocks) to get started, then [Klonk-Script](/en/klonk-script/introduction) in German – blocks generate Klonk-Script, and the two can be compared at any time.

| Competence (short version) | Implementation in Klonk |
|---|---|
| Loop with a fixed count | Walk around a square, build a wall (`repeat 4 times`) |
| Loop with a condition | Walk to the wall – no matter how big the world is (`repeat while not isWall`) |
| Branch | Pick up a brick if there is one, otherwise walk on (`if … then … else`) |
| Assigning data types | `isWall` returns a Boolean, `brickCount` a number, `print("…")` needs a string |
| Expressions with operators | `steps + 1`, `brickCount > 2` |
| Variable as a counter | Count steps or picked-up bricks and print them |
| Passing and returning values | `procedure stairs(levels)` with a parameter; `function` with `return` |
| Influence of passed values | Compare `stairs(2)` and `stairs(4)` – what changes? |
| Representing the flow | Draw the movement path on squared paper first, check it with **Step** (F10); the variable view shows the counter values |

```klonk
// Collect bricks and count them – loop, branch, variable
var collected = 0
var steps = 0
repeat while not isWall
  if isBrick then
    pickBrick
    collected = collected + 1
  else
    step
    steps = steps + 1
  end
end
print(steps + " steps, " + collected + " bricks")
```

### Tips

- **Flowchart first:** The learners draw a program flowchart, then implement it in blocks. The other way round: represent a finished program as a flowchart.
- **Check generality:** The advanced course requires that an algorithm also works with other starting values. Start the same program in several prepared worlds from the [world editor](/en/world/editor) – with many, few or no bricks at all.
- **Find errors:** Hand out deliberately faulty programs (e.g. `step` is missing in the loop). With single step and pause, the learners find the cause.
- **Not just sequences:** The guiding principles of the advanced course warn against stopping at purely linear animations – tasks with conditions are the norm in Klonk, because the world can look different every time.

## Information and data: basics of digital data

*Designing an encoding rule for text, ASCII; breaking a black-and-white image into pixels and encoding it as a bit sequence; bit, byte, prefixes*

Only as an application example: the world is a grid like a pixel graphic. The learners draw a small black-and-white image as a bit sequence, and another group "prints" it into the world with marks – first by hand in the world editor, later with a program.
