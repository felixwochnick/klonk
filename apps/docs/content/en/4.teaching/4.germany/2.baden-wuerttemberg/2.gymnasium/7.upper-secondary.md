## Overview

The subject plan is published as **Computer Science (pilot program)** (*Informatik (Schulversuch)*) and applies jointly to the basic and the advanced subject; sub-competences that only concern the advanced subject are marked in the plan. It does not specify hours per area. Klonk is suited above all to programming, recursion and project management, and in part to data structures, algorithms on data structures, relational database systems and automata; it does not cover the bit level, networks or the information society.

## Structured and object-oriented programming

**Curricular reference (short version):** *Variables, data types, type conversion, strings; classes, attributes, methods, references, access modifiers, encapsulation, constructors, inheritance; structogram, pseudocode, UML class diagram. LF only: among others polymorphism, abstract classes, generic data types, collections, lambda expressions*

**Tool:** [Java](/en/klonk-script/java) (or [Python](/en/klonk-script/python), [C#](/en/klonk-script/csharp)). Every character is an object of the class `Klonk`; custom classes hold a character as an **attribute** (association), since `Klonk` itself is `final`.

### Use of Klonk

- **Class diagram first:** `BuildingCrew` *has a* `Klonk` character, `TowerBuilder` *is a* `BuildingCrew` – first draw it as UML, then implement it. Afterwards, the design is compared with the [class diagram](/en/klonk-script/diagrams#class-diagram) that Klonk generates from the code (visibility, inheritance, association with multiplicity).
- **Structogram and references:** The automatically generated [structogram](/en/klonk-script/diagrams#structogram) of a method serves as a cross-check for the students' own design. At a breakpoint, the [object diagram](/en/klonk-script/diagrams#object-diagram) shows which objects exist and what references point to – for example, that after `BuildingCrew b = a;` there is only one object.
- **Encapsulation:** attributes `private`, access via methods; a counter for placed bricks can only be changed via `place()`.
- **LF – polymorphism and collections:** Process an `ArrayList<Worker>` with different subclasses that all override `work()` in a `for` loop. Several characters require a [license](/en/administration/license).

Detailed examples can be found at [Bavaria, grade 9](/en/teaching/germany/bavaria/gymnasium/grade-9) and [grade 10](/en/teaching/germany/bavaria/gymnasium/grade-10).

## Data structures: stack and queue

**Curricular reference (short version):** *Stack (LIFO), queue (FIFO); graph as adjacency matrix and adjacency list; nodes, edges, degree, cycle*

A brick stack **is** a stack: `placeBrick(color)` = *push*, `pickBrick()` = *pop*, `isBrick(color)` checks the top element (*top*), `brickCount()` returns the size. Students encapsulate this in their own class `BrickStack` and compare it with an implementation based on an array.

A maze world can be treated as a **graph**: cells are nodes, walkable neighboring cells are edges. The adjacency matrix is first set up by hand, and in the LF then generated by the character while exploring.

## Relational database systems

**Use of Klonk:** [Databases](/en/klonk-script/databases) with SQLite or PostgreSQL in the browser – table overview, SQL console with suggestions for table and column names, databases as files in the project. From a database's schema, Klonk generates an [ER diagram](/en/klonk-script/diagrams#er-diagram) (Chen, (min,max), crow's foot) and the relational schema. Designing the data model before implementation still takes place on paper or in a modelling tool; Klonk does not include an editor that creates tables from a drawn ER model. This results in the ★★ rating.

- **Starting with the world:** The current world is available as a database (`characters`, `bricks`, `marks`, `blocks`, `world`). A question such as “On which cells are more than two bricks stacked?” leads to grouping and `HAVING`: `SELECT x, y, MAX(level) AS height FROM bricks GROUP BY x, y HAVING MAX(level) > 2;`
- **Implementing a schema:** A model designed on paper (e.g. a school library with books, people and loans) is created with primary and foreign keys and evaluated with queries across several tables. The ER diagram generated by Klonk serves as a check: do the cardinalities and the n:m relationship via the junction table match the design?
- **Database in a program:** A Java program reads building orders from a table with `Database.open("plan")` and `query(…)` and has the character carry them out – an alternative to the construction plan in JSON format under *Project management*.

## Algorithms on data structures

**Curricular reference (short version):** *Linear and binary search; bubble sort, selection sort, insertion sort, one recursive sorting algorithm; running time (big O notation); Dijkstra by hand. LF only, among others: breadth-first and depth-first search on graphs, spanning trees, greedy*

- **Making sorting visible:** A row of brick stacks is sorted by height. The heights are stored in an array; the character rebuilds every swap in the world – comparisons and swaps are counted.
- **Binary search:** In a sorted row, find the first position with height ≥ k – the character only walks to the cells that the search actually checks. The difference to linear search can be read off from the number of steps.
- **LF – breadth-first search:** Compute the shortest path through the maze and walk it, leaving marks.
- **Dijkstra by hand:** Stack heights as edge weights; then implement it in the LF if desired.

## Recursion

**Curricular reference (short version):** *Base case and recursive step, e.g. Towers of Hanoi; divide and conquer; implementation. LF only: call tree/call stack, comparison iterative – recursive, backtracking*

The education plan explicitly names the **Towers of Hanoi**. In Klonk they are represented as brick towers: three stacks stand to the east, north and south of the character, and the disks are bricks of different colors.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    static final String[] DISK = { YELLOW, GREEN, BLUE };   // small ... large
    static Klonk k;
    static int facing = 0;   // quarter turns to the left: 0 = east, 1 = north, 3 = south

    static void faceTowards(int direction) {
        while (facing != direction) {
            k.turnLeft();
            facing = (facing + 1) % 4;
        }
    }

    static void hanoi(int n, int from, int to, int via) {
        if (n == 0) return;                 // base case
        hanoi(n - 1, from, via, to);        // move smaller towers out of the way
        faceTowards(from);
        k.pickBrick();                      // take the top disk
        faceTowards(to);
        k.placeBrick(DISK[n - 1]);          // and put it down
        hanoi(n - 1, via, to, from);
    }

    public static void main(String[] args) {
        k = new Klonk();
        for (int i = DISK.length - 1; i >= 0; i--) {
            k.placeBrick(DISK[i]);          // build the starting tower in the east
        }
        hanoi(DISK.length, 0, 1, 3);        // from east to north via south
    }
}
```

- **Call stack (LF):** Set a breakpoint on `k.pickBrick()` – at every stop, the variable view shows `n`, `from` and `to` of the current call. Draw the call tree for three disks on paper beforehand.
- **Iterative vs. recursive (LF):** Solve "to the wall and back" once with a loop and once recursively.
- **Backtracking (LF):** The character recursively searches for a path through the maze, marks visited cells and turns back at dead ends.

## Automata and formal languages

**Curricular reference (short version):** *Finite automata with and without output (e.g. Mealy machine), state diagram and transition table; in the LF, among others, further automata and grammars*

The character can be modeled as a **Mealy machine**: inputs are sensor values (`isWall()`, `isMark()`), outputs are actions (`step()`, `turnLeft()`, `setMark()`). A state diagram "along the right-hand wall" is converted into a transition table and then into a program with a variable `state`. For grammars, [Klonk-Script](/en/klonk-script/introduction) is suitable as a small, manageable language.

## Project management

**Curricular reference (short version):** *Project brief, phases, requirements, acceptance; process models (waterfall, agile); requirements specification, functional specification, user stories; prototype*

- **Multi-file projects:** [Projects](/en/klonk-script/projects) with several Java files in packages, as a folder on the computer or as a browser project.
- **User stories:** "As the site manager, I want the character to implement a building plan in JSON format" – with `JsonObject` from Klonk's Java library.
- **Acceptance:** Test worlds from the [world editor](/en/world/editor) serve as acceptance criteria; the program must deliver the expected result in every world.

## Notes for lesson planning

- **Choice of language:** Java, Python and C# use the same object API (`Klonk`); the subject department can therefore decide on the language independently of the task worlds.
- **Consider licensing:** Tasks with several characters (e.g. polymorphism with different workers) require a [license](/en/administration/license); with one character, stack, recursion and automata remain fully feasible.
- **Assessment:** Possible formats include writing a program for a given world, predicting a call tree, or converting a state diagram into a program.
