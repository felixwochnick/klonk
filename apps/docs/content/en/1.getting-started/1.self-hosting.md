---
title: Self-hosting
description: Run Klonk on your own server with Docker Compose.
---

Klonk consists of the app (`app.klonk.*`), the admin area (`admin.klonk.*`), central sign-in (`auth.klonk.*`) and a Postgres database. On startup every instance checks whether the database schema is up to date and applies missing migrations automatically.

```bash
git clone https://github.com/felixwochnick/klonk.git
cd klonk
export KLONK_APP_SECRET=$(openssl rand -base64 32)
export KLONK_ENCRYPTION_KEY=$(openssl rand -base64 32)
POSTGRES_PASSWORD=secret docker compose -f docker/docker-compose.yml up -d
```

The app is then available at `http://localhost:3000`, the admin area at `http://localhost:3001` and sign-in at `http://localhost:3002`. On first visit to the admin area you create your school or company and the first admin account.

::callout{icon="i-lucide-shield" color="warning"}
Keep `KLONK_ENCRYPTION_KEY` safe – it encrypts SSO secrets in the database. If it is lost, OIDC and LDAP credentials have to be entered again.
::

## Environment variables

| Variable | Description |
|---|---|
| `NUXT_DATABASE_URL` | Connection URL of the Postgres database. The user must be allowed to create roles (row level security). |
| `NUXT_APP_SECRET` | Seals the session cookies – use the same value for app and admin |
| `NUXT_ENCRYPTION_KEY` | Key used to encrypt SSO secrets |
| `NUXT_SESSION_COOKIE_DOMAIN` | e.g. `.klonk.example` – one sign-in then works for all subdomains |
| `NUXT_PUBLIC_APP_URL`, `NUXT_PUBLIC_ADMIN_URL` | Public addresses of app and admin area |
| `NUXT_PUBLIC_AUTH_URL` | Address of central sign-in. Empty = app and admin each have their own sign-in page |
| `NUXT_PUBLIC_WEBSITE_URLS` | Further sites (comma-separated) allowed to query `/api/session` and to be redirected back to after sign-in |
| `NUXT_MIGRATIONS_DIR` | Folder containing the SQL migrations (already set in the image) |

Cookies are marked `Secure` – run Klonk behind HTTPS (e.g. with a reverse proxy).

## Central sign-in (single sign-on)

With `NUXT_PUBLIC_AUTH_URL` set, app and admin redirect to sign-in on `auth.*`. Once signed in there, you are signed in everywhere – and signing out applies everywhere too. Requirement: all services run under the same domain and `NUXT_SESSION_COOKIE_DOMAIN` is set. Do not host third-party content on these subdomains, as they receive the session cookie.

Other sites on the same domain (e.g. a website) query the sign-in status like this:

```js
const { user } = await fetch('https://auth.klonk.example/api/session', { credentials: 'include' }).then(r => r.json())
```
