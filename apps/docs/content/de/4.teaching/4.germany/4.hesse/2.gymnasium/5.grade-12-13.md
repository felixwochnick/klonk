## Q1.1 Klassen und Objekte

**Bezug zum KCGO (Kurzfassung):** *Objekt als Instanz, Klasse als Bauplan; Attribut, Methode, Konstruktor; Feld/Liste von Objekten mit Bibliotheksklassen; Geheimnisprinzip, get/set; UML-Klassendiagramm, Assoziation, Aggregation – LK: Vererbung, abstrakte Klasse, Polymorphie*

### Einsatz von Klonk

- **Sichtbare Objekte:** `new Klonk("Klara")` ist ein Objekt, das in der Welt steht; Methodenaufrufe verändern seinen Zustand sichtbar.
- **Assoziation:** Eine eigene Klasse `Bautrupp` *hat* eine Figur als Attribut (die Klasse `Klonk` ist `final`, eigene Klassen nutzen sie also über Assoziation, nicht über Vererbung). Im UML-Klassendiagramm: `Bautrupp` → `Klonk`.
- **Feld/Liste von Objekten:** `Klonk.all()` liefert alle Figuren; eine `ArrayList<Bautrupp>` (Java) bzw. Liste (Python) verwaltet mehrere Trupps. Mehrere Figuren setzen eine [Lizenz](/de/administration/license) voraus.
- **Geheimnisprinzip:** Das Attribut `gelegt` ist privat und nur über `getGelegt()` lesbar.
- **LK – Polymorphie:** abstrakte Klasse `Bauauftrag` mit `baue()`, Unterklassen `Mauer`, `Turm`, `Treppe`; eine Liste von Aufträgen wird abgearbeitet, jede Klasse baut anders.

Ein ausführliches Java-Beispiel mit Konstruktor, Getter und Vererbung findet sich auf der Seite [Bayern, Klasse 9](/de/teaching/germany/bavaria/gymnasium/grade-9).

## Q1.2 Such- und Sortieralgorithmen

**Bezug zum KCGO (Kurzfassung):** *Lineare und binäre Suche, einfache Sortierverfahren mit quadratischer Laufzeit, Laufzeitanalyse – LK: ein effizientes Sortierverfahren*

- **Lineare Suche in der Welt:** Die Figur läuft eine Reihe von Ziegelstapeln ab und hält am ersten Stapel einer bestimmten Höhe (`brickCount()`). Gezählte Schritte entsprechen den Vergleichen.
- **Sortieren:** Stapelhöhen in ein Feld bzw. eine Liste einlesen, mit Selection- oder Bubblesort sortieren und die Reihe sortiert neu bauen. Optional schichtet die Figur die Ziegel tatsächlich um – dann wird die Zahl der Vertauschungen unmittelbar anschaulich.
- **Laufzeit:** Dieselbe Aufgabe mit 3, 6 und 12 Stapeln ausführen und die Vergleiche zählen.

## Q1.3 Rekursion

**Bezug zum KCGO (Kurzfassung):** *Terminationsbedingung, Parameterübergabe, einfache und mehrfache Rekursion, Visualisierung; Rekursion vs. Iteration – LK: Backtracking*

Das KCGO nennt ausdrücklich die **Visualisierung**. In Klonk ist jeder rekursive Aufruf ein sichtbarer Schritt; auf dem Rückweg werden die Aufrufe in umgekehrter Reihenfolge abgeschlossen. Für den GK 2027 ist Rekursion zugleich das Q4-Thema.

```python
from klonk import Klonk


def hin_und_zurueck(figur):
    """Läuft rekursiv bis zur Wand und zählt die Felder auf dem Rückweg."""
    if figur.is_wall():                # Terminationsbedingung
        figur.set_mark()
        figur.turn_left()
        figur.turn_left()
        return 0
    figur.step()
    felder = hin_und_zurueck(figur)    # rekursiver Aufruf
    figur.step()                       # läuft erst auf dem Rückweg
    return felder + 1


print(hin_und_zurueck(Klonk()), "Felder bis zur Wand")
```

- **Rekursion vs. Iteration:** Dieselbe Aufgabe mit einer `while`-Schleife lösen; im Einzelschritt vergleichen, welche Variablen jeweils existieren.
- **Mehrfache Rekursion:** `pyramide(n)` baut eine Stufe der Breite `n` und ruft sich mit `n - 2` auf; rekursiv erzeugte Muster aus Marken als „rekursive Grafik“.
- **LK – Backtracking:** Die Figur sucht den Weg durch ein Labyrinth aus Quadern, markiert besuchte Felder und kehrt in Sackgassen um. Eine eigene Tabelle `besucht[x][y]` (Java) bzw. ein `set` (Python) speichert die besuchten Felder.

## Q1.4 Listen und Q1.5 Graphen

- **Listen (★):** Eine selbst implementierte Warteschlange von Bauaufträgen, die die Figur nacheinander abarbeitet – die Welt zeigt das Ergebnis, die Datenstruktur selbst bleibt im Code.
- **Graphen, LK (★★):** Eine Welt ist ein Gittergraph – freie Felder sind Knoten, Nachbarfelder ohne Quader Kanten. Die Figur erkundet ein Labyrinth (Tiefensuche), baut eine Adjazenzliste auf und läuft anschließend den per Breitensuche gefundenen kürzesten Weg ab.

## Q3 Maschinenmodelle

Klonk ist kein Automatensimulator. Da eine Figur jedoch nur Felder lesen und beschreiben kann, eignet sie sich, um Maschinenmodelle **nachzuspielen**:

- **Turingmaschine (★★):** Eine Reihe von Feldern ist das Band, Marken in verschiedenen Farben sind die Symbole (`istMarke(rot)` lesen, `markieren(blau)` schreiben, `markeLöschen`), die Figur ist der Schreib-Lese-Kopf, eine Variable `zustand` der Zustand. So lassen sich etwa ein „Binärzähler“ oder „Wort verdoppeln“ veranschaulichen. Das Band ist allerdings durch die Weltgröße begrenzt.
- **Registermaschine (★★):** Jeder Ziegelstapel ist ein Register: `hinlegen` = Inkrement, `aufheben` = Dekrement, `istZiegel` = Test auf null. Ein Programm, das zwei Register addiert, wird als Umschichten von Ziegeln sichtbar.
- **Endliche Automaten (★):** Eine Reihe farbiger Marken ist das Eingabewort; die Figur liest es Feld für Feld und wechselt nach einer Übergangstabelle den Zustand – am Ende akzeptiert sie (z. B. Marke setzen) oder nicht.

Formale Sprachen, Grammatiken und Kellerautomaten deckt Klonk nicht ab.

## Q2 Datenbanken und Q4

**Q2 (★★):** Klonk enthält SQLite und PostgreSQL im Browser ([Datenbanken](/de/klonk-script/databases)). Damit lässt sich das in Q2 entworfene Schema mit `CREATE TABLE`, Primär- und Fremdschlüsseln umsetzen, und SQL-Abfragen über mehrere Tabellen lassen sich formulieren und überprüfen. Die Operationen der Relationenalgebra (Selektion, Projektion, Verbund) können jeweils einer SQL-Abfrage gegenübergestellt und am Ergebnis nachvollzogen werden. Nicht enthalten sind ein Editor für ER-Diagramme, eine Webdatenbank (Zugriff über eine Webseite) und Unterrichtsmaterial zum Datenschutz.

- **Schemaentwurf überprüfen:** Das auf Papier erstellte ER-Modell wird in Tabellen überführt; Fremdschlüssel werden auch in SQLite geprüft, sodass Fehler im Schema beim Einfügen von Testdaten auffallen.
- **Datenbank aus einem Programm:** Ein Java- oder Python-Programm greift mit `Database.open("schule")` auf die Projektdatenbank zu. Platzhalter (`?` in SQLite, `$1` in PostgreSQL) übergeben Werte getrennt vom SQL-Text – ein Anknüpfungspunkt, um SQL-Injection bei Webdatenbanken zu besprechen.

```java
import klonk.Database;
import klonk.Row;

public class Main {
    public static void main(String[] args) {
        Database db = Database.open("schule");   // Projektdatei schule.sqlite.sql
        String klasse = "7a";
        String sql = "SELECT s.vorname FROM schueler s "
                   + "JOIN klassen k ON s.klasse_id = k.id WHERE k.name = ?";
        for (Row s : db.query(sql, klasse)) {
            System.out.println(s.getString("vorname"));
        }
    }
}
```
