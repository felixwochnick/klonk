## 3 Objektorientierte Modellierung und Programmierung

**Lehrplanbezug (Kurzfassung):** *Variablenarten (Parameter, lokal, Attribut); Methodenkopf und -rumpf, Konstruktor, Getter/Setter; Struktogramm, Pseudocode; Datentypen; Ober- und Unterklasse, Vererbung, Überschreiben*

**Einsatz von Klonk:** [Java](/de/klonk-script/java) (oder [Python](/de/klonk-script/python)). Die Figuren aus Jahrgangsstufe 7 erscheinen jetzt als **Objekte**: `new Klonk()` ist die erste Figur, `new Klonk("Klara")` die Figur mit diesem Namen.

| Kompetenzerwartung (Kurzfassung) | Umsetzung in Klonk |
|---|---|
| Alltagsobjekte analysieren, zu Klassen abstrahieren | Klasse `Klonk` mit ihren Methoden (`step()`, `isWall()` …) im Editor erkunden – die Vorschläge beim Tippen zeigen alle Methoden mit Erklärung |
| Klassen mit Attributen und Methoden deklarieren | eigene Klasse `Bautrupp` mit Attributen (Figur, Farbe, Anzahl) |
| Wertzuweisung als Zustandsänderung | Attribut `gelegt` zählt mit; im Debugger live beobachten |
| Algorithmen mit Kontrollstrukturen formulieren | Struktogramm aus Klasse 7 jetzt in Java umsetzen |
| Methoden implementieren, Definition und Aufruf | `baueReihe(int laenge)` definieren und aufrufen |
| Fremde Algorithmen lesen und anpassen | vorgegebenes Programm in einer neuen Welt zum Laufen bringen |
| Generalisierung, Vererbung, Überschreiben | `Turmbauer extends Bautrupp` überschreibt `baue()` |

```java
import klonk.Klonk;
import static klonk.Klonk.*;

class Bautrupp {
    protected Klonk figur;   // Attribut: eine Referenz auf ein Objekt
    protected String farbe;
    private int gelegt = 0;

    Bautrupp(String name, String farbe) {   // Konstruktor
        this.figur = new Klonk(name);
        this.farbe = farbe;
    }

    int getGelegt() { return gelegt; }       // Getter

    void lege() {
        figur.placeBrick(farbe);
        gelegt = gelegt + 1;                 // Zustandsänderung
    }

    void baue() {                            // wird in der Unterklasse überschrieben
        while (!figur.isWall()) {
            figur.turnLeft();
            lege();
            figur.turnRight();
            figur.step();
        }
    }
}

class Turmbauer extends Bautrupp {
    Turmbauer(String name) { super(name, RED); }

    @Override
    void baue() {
        for (int i = 0; i < 5; i++) lege();
    }
}

public class Main {
    public static void main(String[] args) {
        Bautrupp a = new Bautrupp("Klonk", BLUE);
        Bautrupp b = new Turmbauer("Klara");
        a.baue();
        b.baue();
        System.out.println(a.getGelegt() + " und " + b.getGelegt() + " Ziegel gelegt");
    }
}
```

::tip
Die Klasse `Klonk` selbst ist `final` – eigene Unterklassen entstehen wie oben über eine **eigene** Oberklasse, die eine Figur als Attribut hat. Das zeigt nebenbei, dass Attribute auch Objekte sein können (Vorgriff auf Jahrgangsstufe 10).
::

::note
Das Beispiel verwendet zwei Figuren („Klonk“ und „Klara“). Mehr als eine Figur setzt eine [Lizenz](/de/administration/license) voraus.
::

### Debugger im Unterricht

Lehrkräfte können einen Haltepunkt in `lege()` setzen und das Programm mit **Weiter** (F5) durchlaufen lassen: Die Variablenansicht zeigt bei jedem Halt den aktuellen Wert von `gelegt`. So wird der Unterschied zwischen **lokaler Variable**, **Parameter** und **Attribut** sichtbar.

## 2 Grundlagen der Datenmodellierung und relationaler Datenbanksysteme

**Einsatz von Klonk:** [Datenbanken](/de/klonk-script/databases) im Klonk-Editor. Klonk enthält die Datenbanksysteme SQLite und PostgreSQL; beide laufen vollständig im Browser, ohne Datenbankserver und auch offline. Eine Datenbank ist eine Datei im [Projekt](/de/klonk-script/projects) (z. B. `schule.sqlite.sql`) und wird als lesbarer SQL-Text gespeichert. Beim Öffnen zeigt Klonk eine Tabellenübersicht (Tabellen, Spalten, Primärschlüssel, Anzahl der Datensätze) und eine SQL-Konsole, die Ergebnisse als Tabelle und Fehlermeldungen mit Zeilennummer ausgibt.

Das Datenmodell selbst entwerfen die Schülerinnen und Schüler auf Papier oder in einem Modellierungswerkzeug; einen grafischen Editor für Diagramme enthält Klonk nicht. Klonk dient dazu, das entworfene Schema umzusetzen und abzufragen. Daraus ergibt sich die Einstufung ★★.

- **Einstieg über die Welt:** Die aktuelle Welt steht in Klonk als Datenbank zur Verfügung, mit den Tabellen `welt`, `figuren`, `ziegel`, `marken` und `quader`. Nach dem Lauf eines Bauprogramms beantworten die Schülerinnen und Schüler Fragen mit SQL, z. B. „Wie viele Ziegel welcher Farbe hat Klonk gelegt?“ (siehe unten).
- **Beispieldatenbank erkunden:** Jede neue Datenbank enthält ein kleines Beispiel mit den Tabellen `klassen` und `schueler`, die über einen Fremdschlüssel verbunden sind. Daran lassen sich Tabelle, Datensatz, Attribut, Datentyp und Primärschlüssel benennen.
- **Eigenes Modell umsetzen:** Ein auf Papier entworfenes Modell (z. B. Schulbibliothek oder Sportverein) wird mit `CREATE TABLE` angelegt, mit `INSERT` gefüllt und mit `SELECT … WHERE … ORDER BY` abgefragt. Die Datenbank lässt sich wie andere Projektdateien an die Klasse verteilen.

```sql
-- Abfrage an die Welt: Ziegel je Farbe
SELECT farbe, COUNT(*) AS anzahl
FROM ziegel
GROUP BY farbe
ORDER BY anzahl DESC;

-- Abfrage an die Beispieldatenbank
SELECT vorname
FROM schueler
WHERE klasse_id = 1
ORDER BY vorname;
```

## Hinweise für die Unterrichtsplanung

- **Anknüpfen an Jahrgangsstufe 7:** Struktogramme und Aufgabenwelten aus Jahrgangsstufe 7 lassen sich wiederverwenden und nun in Java umsetzen.
- **Fremden Code lesen:** Vorgegebene Programme und Welten können als Dateien verteilt werden; die Schülerinnen und Schüler passen sie an eine neue Welt an.
- **Leistungsfeststellung:** Denkbar sind z. B. die Ergänzung einer Methode in einer vorgegebenen Klasse oder die Übertragung eines Struktogramms in Java-Code. Abgaben lassen sich über die [Klonk Cloud](/de/klonk-script/cloud) einsammeln (Aufgabe im Gruppenordner verteilen, Abgaben ansehen); eine Bewertungsfunktion enthält Klonk nicht.
