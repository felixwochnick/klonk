title: Selbst hosten

Klonk bringt einen eigenen Reverse-Proxy (Caddy) mit. Du brauchst nur einen Server mit Docker und **einen DNS-Eintrag**: `*.klonk.example` und `klonk.example` zeigen auf den Server. Der Proxy verteilt die Anfragen:

| Adresse | Dienst |
|---|---|
| `app.klonk.example` | Lern-App |
| `admin.klonk.example` | Verwaltung |
| `auth.klonk.example` | Zentrale Anmeldung |
| `docs.klonk.example` | Dokumentation |
| `klonk.example` | Weiterleitung zur App |

Beim Start prüft jede Instanz automatisch, ob das Datenbankschema aktuell ist, und spielt fehlende Migrationen ein.

## Installation

```bash
git clone https://github.com/felixwochnick/klonk.git
cd klonk
cp docker/.env.example docker/.env   # Domain, TLS-Modus und Secrets eintragen
docker compose --env-file docker/.env -f docker/docker-compose.yml up -d --build
```

Beim ersten Aufruf von `admin.klonk.example` legst du deine Schule bzw. dein Unternehmen und das erste Admin-Konto an.

## SSL-Zertifikate

Der Modus wird mit `KLONK_TLS` gewählt:

| Modus | Beschreibung |
|---|---|
| `http` | Let's Encrypt per HTTP-Challenge. Ports 80 und 443 müssen aus dem Internet erreichbar sein. `KLONK_ACME_EMAIL` setzen. |
| `ionos` | Let's Encrypt per DNS-Challenge über die IONOS-API – funktioniert auch hinter Firewall/NAT. `KLONK_ACME_EMAIL` und `IONOS_API_TOKEN` (Format `<prefix>.<secret>`, erstellt unter developer.hosting.ionos.de) setzen. |
| `internal` | Selbst signierte Zertifikate einer lokalen CA – zum Testen. |
| `off` | Nur HTTP, wenn bereits ein anderer Proxy TLS übernimmt (`KLONK_PUBLIC_SCHEME=https` beibehalten). |

Zertifikate werden automatisch erneuert und im Volume `caddy-data` gespeichert.

::callout{icon="i-lucide-shield" color="warning"}
Bewahre `KLONK_ENCRYPTION_KEY` sicher auf – damit werden SSO-Secrets in der Datenbank verschlüsselt. Geht der Schlüssel verloren, müssen OIDC- und LDAP-Zugangsdaten neu eingegeben werden.
::

## Wichtige Variablen (`docker/.env`)

| Variable | Beschreibung |
|---|---|
| `KLONK_DOMAIN` | Hauptdomain, z. B. `klonk.example` |
| `KLONK_TLS`, `KLONK_ACME_EMAIL`, `IONOS_API_TOKEN` | Zertifikate (siehe oben) |
| `KLONK_APP_SECRET` | Versiegelt die Session-Cookies |
| `KLONK_ENCRYPTION_KEY` | Verschlüsselt SSO-Secrets |
| `POSTGRES_PASSWORD` | Passwort der Datenbank |
| `KLONK_WEBSITE_URLS` | Weitere Seiten, die den Anmeldestatus abfragen dürfen |
| `KLONK_AI_*` | Optionaler Standard für den [KI-Assistenten](/de/administration/ai) |
| `KLONK_ID_*`, `KLONK_GOOGLE_*`, … | Optionale Anmeldeanbieter, siehe [Privatkonten & Betreiber](/de/administration/private-accounts) |

## Zentrale Anmeldung

Alle Dienste teilen sich eine Anmeldung über `auth.klonk.example`: Wer dort angemeldet ist, ist es überall, und eine Abmeldung gilt ebenfalls überall. Auf den Subdomains dürfen keine fremden Inhalte liegen, da sie das Anmelde-Cookie erhalten.

Andere Seiten derselben Domain (z. B. eine eigene Website) fragen den Anmeldestatus so ab:

```js
const { user } = await fetch('https://auth.klonk.example/api/session', { credentials: 'include' }).then(r => r.json())
```

## Alles lokal ausprobieren (`*.klonk.localhost`)

Für Tests gibt es einen Komplett-Stack mit selbst signierten Zertifikaten sowie einem Test-LDAP und einem Test-Identity-Provider:

```bash
pnpm stack:up      # bauen und starten
pnpm stack:down    # stoppen
pnpm stack:reset   # stoppen und Daten löschen
```

Adressen unter `.localhost` zeigen immer auf den eigenen Rechner – ein Eintrag in `/etc/hosts` ist nicht nötig. Einmalig die lokale Root-CA dem Browser bekannt machen (Chrome/Chromium unter Linux):

```bash
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "Klonk Local CA" -i docker/local/klonk-local-ca.crt
```

Test-Konten im Test-IdP und Test-LDAP: `tim`, `lisa` (Lehrkräfte-Gruppe), `anna` (Admin-Gruppe), Passwort jeweils `<name>-pass`. In der Verwaltung lassen sich damit LDAP (`ldap://glauth:3893`, Bind `cn=service,ou=svcaccts,dc=klonk,dc=test` / `service-pass`, Base DN `dc=klonk,dc=test`, Filter `(&(objectClass=posixAccount)(cn={{username}}))`) und OIDC (`https://sso.klonk.localhost/dex`, Client `klonk` / `klonk-dev-secret`) ausprobieren. `anna` meldet sich per Klonk ID als Besitzerin an.

### Lokaler Testmodus

Auf dem eigenen Rechner – also unter `localhost` oder `*.localhost` – sind **alle Funktionen freigeschaltet**, auch ohne Lizenz-Token. Oben in der App steht dann „Lokaler Testmodus“. Freigeschaltet wird nur, wenn sowohl der Server als auch der Browser einen lokalen Namen sehen; wer über eine echte Domain zugreift, bekommt immer die normale Lizenz. Für den Betrieb ist ein [Lizenz-Token](/administration/license) nötig – das Umgehen der Prüfung (z. B. über einen Proxy) verbietet die [Lizenz](/getting-started/license). Abschalten lässt sich der Modus mit `NUXT_LICENSE_LOCAL_MODE=off`.
