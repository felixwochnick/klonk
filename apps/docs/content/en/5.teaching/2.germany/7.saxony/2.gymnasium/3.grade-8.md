## 1 Algorithms

*Concept of an algorithm and properties of algorithms; transfer the properties to everyday examples; solve simple problems in a block-based language – forms of representation (block representation, verbal description), sequence, conditional statement, counting loop, pre-test or post-test loop; importance of algorithms in society*

**Tool:** [Blocks](/en/klonk-script/blocks) and [Klonk-Script](/en/klonk-script/introduction) alternately – blocks generate Klonk-Script, so two forms of representation of the same algorithm are right next to each other.

| Curriculum content | Implementation in Klonk |
|---|---|
| Properties (unambiguity, finiteness, executability …) | Start a program in three different worlds: does it always end? Does it always do the same thing? |
| Sequence | Lead the character to a target cell, build a small wall |
| Conditional statement | `if isBrick then … else … end` – pick up or place a brick |
| Counting loop | `repeat 4 times` – walk around a square, build a tower |
| Pre-test loop | `repeat while not isWall` or `repeat until isMark` |
| Post-test loop | does not exist as a separate block in Klonk; recreate it with `repeat forever` and `break` at the end of the body – a good opportunity to discuss the difference |
| Forms of representation | verbal description ⇒ structogram ⇒ blocks ⇒ Klonk-Script |

```klonk
// Repair the fence: add missing bricks to the left of the path
setMark(green)
repeat while not isWall    // pre-test loop
  turnLeft
  if not isBrick then      // conditional statement
    placeBrick(red)
  end
  turnRight
  step
end
repeat 2 times             // counting loop: turn around
  turnRight
end
setMark(green)
```

### Tips

- **Step** (F10) and the speed slider make every loop iteration visible; with blocks, the block currently running lights up.
- **Generality:** Build several test worlds in the [world editor](/en/world/editor) (fence complete, with gaps, not there at all). A good solution works in all of them.
- **Algorithms in society:** The character only “decides” based on its sensors – a simple way into the question of which rules recommendation algorithms or smart home devices use to decide.

## 3 Complex task

*Combine the learning areas of grades 7 and 8 in a project, implement the solution in a team, reflect on the work process*

The curriculum names several options (including a wiki/blog, setting up a mobile device, programming hardware). Those who choose the algorithmic option can implement it with Klonk:

- **Building site:** Each group programs a building (house, bridge, pyramid) and documents the algorithm as a structogram.
- **Course swap:** One group builds a world with obstacles, another writes the program that gets through it.
- **Teamwork:** A [project](/en/klonk-script/projects) keeps worlds and programs together as files.

## Elective area 3 Computer games

*Simple and advanced game mechanics, implementing a game, collision detection, computer-controlled opponents; risk of addiction*

A small game can be built in Klonk-Script: one character collects bricks, a second one wanders around randomly as an “opponent” (`random`). The program detects collisions by comparing `positionX` and `positionY` of both characters (switching between the characters with `switch`).

::note
More than one character requires a license with the appropriate character quota (see [License](/en/getting-started/license)). Without a license, a one-character game works: collect bricks before a counter runs out.
::
