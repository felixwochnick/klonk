## Context

The core curriculum describes the competences at the **end of the qualification phase** and does not divide them between Q1 and Q2. Students who entered the EF before 1 August 2027 are taught according to the 2013 core curriculum; the new core curriculum reaches Q1 in a phased manner from 2028/29. According to the requirements for 2029, the **centralised Abitur** (*Zentralabitur*) assumes **Java** and **SQL**, plus documented Abitur classes (including `List`, `Stack`, `Queue`, `BinaryTree`, `DatabaseConnector`); there is no computer in the written examination. Klonk should therefore be seen as a tool for developing content in lessons, not as part of the examination environment. It is suitable above all for objects and classes, iterative and recursive algorithms, and project work; for databases it serves as an SQL environment in which schemas are implemented and queries are tried out.

## Core curriculum 2026 (Q1 from 2028/29)

The new curriculum keeps the content fields *data and their structuring*, *algorithms*, *formal languages and automata* and *computer science, people and society* and adds **artificial intelligence and machine learning** (including neural networks, evaluating AI models). Relevant for the use of Klonk:

- **Algorithms:** iterative and recursive, modularisation, divide and conquer, in the LK additionally **backtracking**; data structures array (GK two-dimensional, LK multi-dimensional), stack, queue, list, tree, in the LK also **graph**; testing including special cases.
- **Data and their structuring:** class modelling with polymorphism and abstract classes, in the LK additionally interfaces.

## Recursion and backtracking

**Curriculum reference (short version):** *Iterative and recursive algorithms; divide and conquer; backtracking (LK)*

**Use of Klonk:** With Klonk, recursion can be **observed**: every call moves the character, and on the way back the calls are completed in reverse order.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    /** Recursively to the wall and back the same way; returns the distance to the wall. */
    static int thereAndBack(Klonk character) {
        if (character.isWall()) {                 // base case
            character.setMark(RED);
            character.turnLeft();
            character.turnLeft();
            return 0;
        }
        character.step();
        int distance = thereAndBack(character) + 1;   // recursive call
        character.step();                             // only runs on the way back
        return distance;
    }

    public static void main(String[] args) {
        Klonk klonk = new Klonk();
        System.out.println("Distance to the wall: " + thereAndBack(klonk));
    }
}
```

**Lesson sequence:**

- **Recursive and iterative:** The same task is solved with a loop and recursively; both solutions are compared in single-step mode.
- **Backtracking in a maze (LK):** A maze of blocks is built in the [world editor](/en/world/editor). The character recursively tries every direction, remembers visited cells in a two-dimensional array `visited[x][y]` (position via `positionX()`/`positionY()`) and turns back at dead ends; the marks remain as a visible trail.
- **Graphs (LK, new curriculum):** The world is treated as a grid graph – free cells are nodes, neighbouring cells without blocks are edges. A breadth-first search with a queue determines the shortest path, which the character then walks.

## Data structures and Abitur classes

Klonk does **not** include the classes of the centralised Abitur (`List`, `Stack`, `Queue`, `BinaryTree` …). Options:

- **Own implementation:** A simple queue or stack as a custom class – in the LK the curriculum requires implementing operations of dynamic data structures anyway.
- **As project files:** The source code of the Abitur classes is placed as separate `.java` files in a [project](/en/klonk-script/projects). Several Java files in one project require a license.

Example: a `Queue` of jobs (“build wall”, “mark row”) is worked through by a character; with a `Stack`, the character remembers its path and walks it back in reverse.

## Object-oriented modelling

**Curriculum reference (short version):** *Abstract classes, inheritance, polymorphism, associations with multiplicities, implementation diagrams*

An abstract class `Worker` with the subclasses `Mason` and `Marker`, called in a loop by a `Site` (1:n), shows polymorphism with a visible result – see the example under [Bavaria, grade 10](/en/teaching/germany/bavaria/gymnasium/grade-10). The class `Klonk` is `final`; custom hierarchies are created via classes that have a character as an attribute. More than one character requires a license (see [License](/en/administration/license)).

In its form, the [class diagram](/en/klonk-script/diagrams#class-diagram) generated by Klonk corresponds to an implementation diagram (data types, visibility, abstract classes in italics, associations with multiplicity `*` for arrays and lists). It can be compared with the design diagram created beforehand. At a breakpoint, the [object diagram](/en/klonk-script/diagrams#object-diagram) shows the objects of the site and their references.

## Projects and development environment

The curriculum provides for the use of an **educational development environment** (*didaktisch orientierte Entwicklungsumgebung*) for designing, implementing and testing. For this, Klonk offers breakpoints, single-step mode and the variables view as well as [projects](/en/klonk-script/projects) with packages. Test worlds stored as files in the project check special cases (empty world, world without an exit, character directly in front of the wall).

## Databases and SQL

**Curriculum reference (short version):** *ER model, normal forms, SQL*

**Use of Klonk:** [Databases](/en/klonk-script/databases) with SQLite or PostgreSQL in the browser. Klonk is used to implement a schema and run SQL queries; the ER model and normalisation are worked out on paper or in a modelling tool; Klonk does not include an editor that creates tables from a drawn ER model. From the implemented schema, Klonk generates an [ER diagram](/en/klonk-script/diagrams#er-diagram) and the relational schema, which are used to check the design. Klonk does not provide the Abitur class `DatabaseConnector`; Java programs access databases via the class `Database`. Since no computer is available in the Abitur examination, queries should also be practised in writing.

- **Trying out queries:** SQL tasks can be run on a rebuilt database or on one imported as an SQLite file (`.db`). The result of every query appears as a table, and error messages state the line.
- **Checking normalisation:** A table in first normal form is decomposed step by step; after each step, a query with `JOIN` shows that the original data can be reconstructed. The relational schema (e.g. `students(id, first_name, ↑class_id)`) and the ER diagram show the new structure after each step.
- **Java and databases:** A program reads a list of `Row` objects with `db.query("SELECT * FROM students WHERE class_id = ?", 1)` and processes them with `getString(…)` or `getInt(…)`; SQL errors can be caught as `DatabaseException`.

## What Klonk does not cover

Computer architecture and networks, client–server communication, encryption, artificial neural networks and data protection; for databases, graphical ER design and the Abitur class `DatabaseConnector`. For automata and grammars, Klonk can only be used as an example (e.g. the syntax of Klonk-Script as a small formal language).

## Notes for lesson planning

- **Abitur preparation:** Since no computer is available in the written examination, it is advisable to combine Klonk tasks with tasks without a computer, for example by first tracing a recursive process by hand and only then checking it in single-step mode.
- **License:** Several characters and several Java files in one project (e.g. Abitur classes as project files) require a license; this should be taken into account when planning project phases.
