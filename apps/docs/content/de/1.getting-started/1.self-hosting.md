---
title: Selbst hosten
description: Klonk mit Docker Compose auf dem eigenen Server betreiben.
---

Klonk besteht aus der App (`app.klonk.*`), der Verwaltung (`admin.klonk.*`), der zentralen Anmeldung (`auth.klonk.*`) und einer Postgres-Datenbank. Beim Start prüft jede Instanz automatisch, ob das Datenbankschema aktuell ist, und spielt fehlende Migrationen ein.

```bash
git clone https://github.com/felixwochnick/klonk.git
cd klonk
export KLONK_APP_SECRET=$(openssl rand -base64 32)
export KLONK_ENCRYPTION_KEY=$(openssl rand -base64 32)
POSTGRES_PASSWORD=geheim docker compose -f docker/docker-compose.yml up -d
```

Danach ist die App unter `http://localhost:3000`, die Verwaltung unter `http://localhost:3001` und die Anmeldung unter `http://localhost:3002` erreichbar. Beim ersten Aufruf der Verwaltung legst du deine Schule bzw. dein Unternehmen und das erste Admin-Konto an.

::callout{icon="i-lucide-shield" color="warning"}
Bewahre `KLONK_ENCRYPTION_KEY` sicher auf – damit werden SSO-Secrets in der Datenbank verschlüsselt. Geht der Schlüssel verloren, müssen OIDC- und LDAP-Zugangsdaten neu eingegeben werden.
::

## Umgebungsvariablen

| Variable | Beschreibung |
|---|---|
| `NUXT_DATABASE_URL` | Verbindungs-URL zur Postgres-Datenbank. Der Nutzer muss Rollen anlegen dürfen (Row Level Security). |
| `NUXT_APP_SECRET` | Versiegelt die Session-Cookies – für App und Verwaltung identisch setzen |
| `NUXT_ENCRYPTION_KEY` | Schlüssel für die Verschlüsselung von SSO-Secrets |
| `NUXT_SESSION_COOKIE_DOMAIN` | z. B. `.klonk.example` – eine Anmeldung gilt dann für alle Subdomains |
| `NUXT_PUBLIC_APP_URL`, `NUXT_PUBLIC_ADMIN_URL` | Öffentliche Adressen von App und Verwaltung |
| `NUXT_PUBLIC_AUTH_URL` | Adresse der zentralen Anmeldung. Leer = App und Verwaltung haben je eine eigene Login-Seite |
| `NUXT_PUBLIC_WEBSITE_URLS` | Weitere Seiten (kommagetrennt), die `/api/session` abfragen und nach dem Login zurückleiten dürfen |
| `NUXT_MIGRATIONS_DIR` | Ordner mit den SQL-Migrationen (im Image bereits gesetzt) |

Die Cookies sind als `Secure` markiert – betreibe Klonk daher hinter HTTPS (z. B. mit einem Reverse-Proxy).

## Zentrale Anmeldung (Single Sign-on)

Mit `NUXT_PUBLIC_AUTH_URL` leiten App und Verwaltung zur Anmeldung auf `auth.*` weiter. Wer dort angemeldet ist, ist es überall – und eine Abmeldung gilt ebenfalls überall. Voraussetzung: Alle Dienste laufen unter derselben Domain und `NUXT_SESSION_COOKIE_DOMAIN` ist gesetzt. Auf diesen Subdomains dürfen keine fremden Inhalte liegen, da sie das Anmelde-Cookie erhalten.

Andere Seiten derselben Domain (z. B. eine Website) fragen den Anmeldestatus so ab:

```js
const { user } = await fetch('https://auth.klonk.example/api/session', { credentials: 'include' }).then(r => r.json())
```
