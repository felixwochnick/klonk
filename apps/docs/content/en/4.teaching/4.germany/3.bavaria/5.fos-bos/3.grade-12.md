In grade 12, computer science is taught in three subjects, depending on the branch of study (*Ausbildungsrichtung*). Klonk can be used primarily in the learning areas on programming: in the KIT learning area "Fundamentals of programming" and in the programming learning areas of the compulsory elective subject Computer Science. In KIWI 12, it can be used within project work. In the database learning areas of the compulsory elective subject, Klonk serves as an SQL environment. Klonk is not intended for networks, ERP systems or training AI models.

| Subject | Applies to | Klonk |
|---|---|---|
| [KIT 12](#kit-12) | profile subject Technology (FOS and BOS) | ★★★ |
| [KIWI 12](#kiwi-12) | profile subject Business and Administration, International Business | ★★ |
| [Computer Science](#computer-science-compulsory-elective) | compulsory elective subject, all branches of study except Business and Administration | ★★★ |

::warning
KIT 12 and KIWI 12 only apply from the school year **2027/28**. In the school year 2026/27, grade 12 is still taught according to the previous curricula: in Technology *Technologie 12* (without a dedicated programming learning area), in Business and Administration *Informatik* as a profile subject (curriculum as for the [compulsory elective subject](#computer-science-compulsory-elective)).
::

### 1 Fundamentals of Programming

**Content (summary):** *Program-oriented representation (structogram, flowchart); simple data types, assignment, input and output; single and multiple branching, loops; comments and documentation; test cases; language e.g. Python or Java*

#### Use of Klonk

With around 12 hours, the time allotted to this learning area is limited. Klonk shortens the path from structogram to running program: the character shows immediately whether a loop runs too often or too rarely.

[Python](/en/klonk-script/python) is a suitable language (named as an example in the curriculum and needed again in learning area 2); alternatively [Java](/en/klonk-script/java). For groups with no prior knowledge at all, a double lesson of [Klonk-Script](/en/klonk-script/introduction) can be scheduled beforehand.

| Competence expectation (summary) | Implementation in Klonk |
|---|---|
| Model solutions with a structogram or flowchart | Draw a structogram for "walk to the wall and check along the way", then implement it |
| Use the control structures of a programming language | `while` with a sensor, `if`/`elif`/`else` as multiple branching |
| Clear, commented program code | Comments for each section; suggestions and hover in the editor explain the commands |
| Check programs with test cases | Run the same program in several prepared worlds: empty, full, edge cases |

```python
from klonk import Klonk, green, yellow, red

klonk = Klonk()
checked = 0

# Traffic light for every stack to the left of the path
while not klonk.is_wall():
    klonk.turn_left()
    height = klonk.brick_count()
    klonk.turn_right()
    if height == 0:
        klonk.set_mark(green)      # free
    elif height < 3:
        klonk.set_mark(yellow)     # low
    else:
        klonk.set_mark(red)        # high
    klonk.step()
    checked += 1

print(checked, "cells checked")
```

**Test cases:** world without bricks (all green), a stack exactly 3 high (edge case red), character already standing in front of the wall (0 cells checked). The worlds are created in the [world editor](/en/world/editor) and stored as files in the [project](/en/klonk-script/projects).

### 2 Learning about AI – Fundamentals

**Content (summary):** *Perceptron (weights, activation function, delta learning rule, training and test data); neural networks; implementation with a framework, e.g. in Python*

#### Use of Klonk

The curriculum provides for a framework for neural networks; Klonk does not offer one. As a **preliminary stage**, however, a single perceptron can be programmed by hand in Python: the inputs are sensor values of the character (e.g. `is_wall()`, `is_mark()` as 0/1), and the output decides between "step" and "turn". This shows the effect of weights and threshold before the class switches to the actual tool.

### 9 Competence-Oriented Project Work

#### Use of Klonk

A project related to a future technology is possible, e.g. an **autonomous warehouse vehicle**: characters collect bricks and sort them by color. In [projects](/en/klonk-script/projects) made of several files, each group works on its own part; the requirements specification and test worlds are part of the documentation.

::note
More than one character requires a license with the appropriate character quota (see [License](/en/administration/license)).
::

### 2 Developing Computer Science Systems

**Content (summary):** *Project work in the modelling cycle (problem definition, modelling, implementation, testing); topics include software development and programming, AI systems, web development, databases, ERP systems, simulation, future technologies such as robotics*

#### Use of Klonk

The learning area leaves the choice of computer science system open. Klonk relates to three of the topics mentioned:

- **Software development and programming:** fundamentals of algorithms and programming in a business situation – e.g. a **warehouse** in which characters store goods (bricks), count them and sort them by color. Students model the process, implement it in [Python](/en/klonk-script/python) and test it with warehouse worlds.
- **Robotics as a future technology:** prototype control of warehouse robots as a simulation; this can be used to discuss the opportunities and risks of automation.
- **Databases:** implementing the warehouse as a relational database (items, orders) in Klonk's [database environment](/en/klonk-script/databases) and evaluating it with SQL; a Python program can read the orders and have a character carry them out (see [Relational Databases](#relational-databases)).

Klonk does not cover web development, ERP systems or training AI models.

### Fundamentals of Software Development

**Content (summary):** *Application-related problems; structogram, flowchart; data types, input and output; single, two-way and multiple branching, counter- and condition-controlled loops; simple test cases; language e.g. C, C++, Java, Python, JavaScript*

#### Use of Klonk

In terms of content, the learning area corresponds to KIT learning area 1, with twice the time allotted: counting loops (`for`) are suitable for building tasks of a fixed size (wall of length 4, staircase), conditional loops for tasks that depend on the world. Klonk offers Python, Java and [JavaScript/TypeScript](/en/klonk-script/javascript) for this – but not C or C++.

### Relational Databases

#### Use of Klonk

Klonk includes the database systems SQLite and PostgreSQL; both run in the browser without a server and without installation. A database is a project file (`warehouse.sqlite.sql` or `warehouse.postgres.sql`) stored as readable SQL text. The table overview and SQL console show tables, columns, primary keys and query results; foreign keys are enforced. Students work out the ER model and normalisation on paper or in a modelling tool – Klonk does not include a graphical editor for this. Also not provided are a database server for several users at the same time and the MySQL dialect. This results in the ★★ rating (see also [Databases](/en/klonk-script/databases)).

- **Implementation:** The modelled schema of a warehouse (items, storage locations, orders) is implemented with `CREATE TABLE`, primary and foreign keys and `CHECK` constraints, and filled with `INSERT`.
- **Data management:** Evaluations with joins, grouping and aggregate functions; changes with `UPDATE` and `DELETE`. Update anomalies can be demonstrated directly with a non-normalised table design.
- **Existing data:** A teacher's SQLite file (`.db`) can be imported; via [Klonk Cloud](/en/klonk-script/cloud), a database can be handed out to the class as an assignment.
- **Database and program:** A [Python](/en/klonk-script/python) program reads the open orders, has the character build a stack with the ordered number of bricks for each order and then marks the orders as done:

```python
from klonk import Klonk, Database

k = Klonk()
db = Database.open("warehouse")   # project file warehouse.sqlite.sql
for o in db.query("SELECT amount FROM orders WHERE done = 0 ORDER BY id"):
    k.turn_left()
    for i in range(o["amount"]):
        k.place_brick()
    k.turn_right()
    k.step()
db.execute("UPDATE orders SET done = 1 WHERE done = 0")
```

### Procedural Programming

**Content (summary):** *Decomposition into sub-problems, custom functions, local and global variables*

#### Use of Klonk

Building tasks lend themselves to decomposition into sub-problems: `wall(length)`, `corner()`, `square(side)` made of `wall` and `corner`. In the debugger, local variables are only visible during the function call, global ones throughout.

### Object-Oriented Programming and Analysis

**Content (summary):** *Class and object, attributes, methods, encapsulation; UML class diagram; inheritance (base class, derived class); language e.g. C#, Java*

#### Use of Klonk

- **Using objects of given classes:** Every character is an object of the class `Klonk`; the introduction via the use of objects of given classes provided for in the curriculum is therefore directly possible.
- **Custom classes according to a class diagram:** e.g. `WarehouseVehicle` with the attributes `character`, `load` and the methods `store()`, `getLoad()`.
- **Inheritance:** `Forklift` extends `WarehouseVehicle`. The class `Klonk` itself is `final` in Java – custom classes hold the character as an attribute.
- In addition to [Java](/en/klonk-script/java), [C#](/en/klonk-script/csharp) is also available.

A Java example with a class diagram and inheritance can be found under [Grade 13](/en/teaching/germany/bavaria/fos-bos/grade-13).

### IT Project

**Content (summary):** *Project organisation, requirements/functional specification, Gantt chart; process models (waterfall, V-model, spiral model, Scrum)*

#### Use of Klonk

A Klonk [project](/en/klonk-script/projects) with several files (e.g. Java packages) and test worlds is suitable for teams with a division of labour. One possible topic is a "Smart Warehouse": several characters store bricks according to a plan from a JSON file; each iteration (Scrum sprint) delivers a working intermediate state.

## Matching learning modules

The [learning modules](/en/teaching/modules/overview) contain tasks in blocks or Klonk-Script with automatic checking that students can work on independently – in class or at home. For groups without prior knowledge – in KIT learning area 1 and in the elective subject Computer Science – they are suitable as an introduction before switching to Python or Java; the tasks themselves are not set in these languages:

- **Repetition with a fixed count** – count-controlled loops
- **Conditional repetition** – condition-controlled loops
- **Branching** – single and two-way branching
- **Your own procedures** – decomposition into subproblems and custom subroutines (procedural programming)
- **Variables and counting** – assignment and output

## Notes for lesson planning

- **Preparing test worlds:** For test cases (empty, full, edge cases), it is advisable to create the worlds in advance in the [world editor](/en/world/editor) and distribute them to the class as files.
- **Assessment:** Suitable tasks include writing the program for a given structogram (or vice versa), or requiring a program to work correctly in several given worlds.
- **License:** Projects with several characters and including project files require a [license](/en/administration/license).
