## Strukturierte und objektorientierte Programmierung

**Lehrplanbezug (Kurzfassung):** *Variablen, Datentypen, Typumwandlung, Zeichenketten; Klassen, Attribute, Methoden, Referenzen, Zugriffsmodifikatoren, Kapselung, Konstruktoren, Vererbung; Struktogramm, Pseudocode, UML-Klassendiagramm. Nur LF: u. a. Polymorphie, abstrakte Klassen, generische Datentypen, Collections, Lambda-Ausdrücke*

**Werkzeug:** [Java](/de/klonk-script/java) (oder [Python](/de/klonk-script/python), [C#](/de/klonk-script/csharp)). Jede Figur ist ein Objekt der Klasse `Klonk`; eigene Klassen halten eine Figur als **Attribut** (Assoziation), da `Klonk` selbst `final` ist.

### Einsatz von Klonk

- **Klassendiagramm zuerst:** `Bautrupp` *hat eine* `Klonk`-Figur, `Turmbauer` *ist ein* `Bautrupp` – zunächst als UML zeichnen, dann implementieren.
- **Kapselung:** Attribute `private`, Zugriff über Methoden; ein Zähler für gelegte Ziegel lässt sich nur über `lege()` ändern.
- **LF – Polymorphie und Collections:** Eine `ArrayList<Arbeiter>` mit verschiedenen Unterklassen, die alle `arbeite()` überschreiben, in einer `for`-Schleife abarbeiten. Mehrere Figuren setzen eine [Lizenz](/de/administration/license) voraus.

Ausführliche Beispiele dazu finden sich bei [Bayern, Klasse 9](/de/teaching/germany/bavaria/gymnasium/grade-9) und [Klasse 10](/de/teaching/germany/bavaria/gymnasium/grade-10).

## Datenstrukturen: Stack und Queue

**Lehrplanbezug (Kurzfassung):** *Stack (LIFO), Queue (FIFO); Graph als Adjazenzmatrix und -liste; Knoten, Kanten, Grad, Zyklus*

Ein Ziegelstapel **ist** ein Stack: `placeBrick(farbe)` = *push*, `pickBrick()` = *pop*, `isBrick(farbe)` prüft das oberste Element (*top*), `brickCount()` liefert die Größe. Die Schülerinnen und Schüler kapseln dies in einer eigenen Klasse `ZiegelStack` und vergleichen sie mit einer Implementierung über ein Array.

Eine Labyrinthwelt lässt sich als **Graph** auffassen: Felder sind Knoten, begehbare Nachbarfelder Kanten. Die Adjazenzmatrix wird zunächst von Hand aufgestellt, im LF anschließend von der Figur beim Erkunden erzeugt.

## Relationale Datenbanksysteme

**Einsatz von Klonk:** [Datenbanken](/de/klonk-script/databases) mit SQLite oder PostgreSQL im Browser – Tabellenübersicht, SQL-Konsole mit Vorschlägen für Tabellen- und Spaltennamen, Datenbanken als Dateien im Projekt. Das Datenmodell entsteht auf Papier oder in einem Modellierungswerkzeug; Klonk enthält keinen Diagrammeditor. Daraus ergibt sich die Einstufung ★★.

- **Einstieg über die Welt:** Die aktuelle Welt steht als Datenbank zur Verfügung (`figuren`, `ziegel`, `marken`, `quader`, `welt`). Eine Frage wie „Auf welchen Feldern liegen mehr als zwei Ziegel übereinander?“ führt zu Gruppierung und `HAVING`: `SELECT x, y, MAX(ebene) AS hoehe FROM ziegel GROUP BY x, y HAVING MAX(ebene) > 2;`
- **Schema umsetzen:** Ein auf Papier entworfenes Modell (z. B. Schulbibliothek mit Büchern, Personen und Ausleihen) wird mit Primär- und Fremdschlüsseln angelegt und mit Abfragen über mehrere Tabellen ausgewertet.
- **Datenbank im Programm:** Ein Java-Programm liest Bauaufträge mit `Database.open("bauplan")` und `query(…)` aus einer Tabelle und lässt die Figur sie ausführen – eine Alternative zum Bauplan im JSON-Format unter *Projektmanagement*.

## Algorithmen auf Datenstrukturen

**Lehrplanbezug (Kurzfassung):** *Lineare und binäre Suche; Bubblesort, Selectionsort, Insertionsort, ein rekursives Sortierverfahren; Laufzeit (O-Notation); Dijkstra von Hand. Nur LF u. a.: Breiten- und Tiefensuche auf Graphen, Spannbäume, Greedy*

- **Sortieren sichtbar machen:** Eine Reihe von Ziegelstapeln wird nach Höhe sortiert. Die Höhen stehen in einem Array; jede Vertauschung baut die Figur in der Welt nach – Vergleiche und Vertauschungen werden gezählt.
- **Binäre Suche:** In einer sortierten Reihe die erste Stelle mit Höhe ≥ k finden – die Figur läuft nur die Felder ab, die die Suche tatsächlich prüft. Der Unterschied zur linearen Suche wird an der Schrittzahl ablesbar.
- **LF – Breitensuche:** Den kürzesten Weg durch das Labyrinth berechnen und mit Marken ablaufen.
- **Dijkstra von Hand:** Stapelhöhen als Kantengewichte; im LF anschließend ggf. implementieren.

## Rekursion

**Lehrplanbezug (Kurzfassung):** *Rekursionsbasis und Rekursionsschritt, z. B. Türme von Hanoi; Divide and Conquer; Implementierung. Nur LF: Aufrufbaum/Call-Stack, Vergleich iterativ – rekursiv, Backtracking*

Die **Türme von Hanoi** nennt der Bildungsplan ausdrücklich. In Klonk werden sie als Ziegeltürme dargestellt: Drei Stapel stehen im Osten, Norden und Süden der Figur, die Scheiben sind Ziegel verschiedener Farbe.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    static final String[] SCHEIBE = { YELLOW, GREEN, BLUE };   // klein ... groß
    static Klonk k;
    static int blick = 0;   // Vierteldrehungen nach links: 0 = Osten, 1 = Norden, 3 = Süden

    static void schaueZu(int richtung) {
        while (blick != richtung) {
            k.turnLeft();
            blick = (blick + 1) % 4;
        }
    }

    static void hanoi(int n, int von, int nach, int ueber) {
        if (n == 0) return;                 // Rekursionsbasis
        hanoi(n - 1, von, ueber, nach);     // kleinere Türme aus dem Weg
        schaueZu(von);
        k.pickBrick();                      // oberste Scheibe nehmen
        schaueZu(nach);
        k.placeBrick(SCHEIBE[n - 1]);       // und ablegen
        hanoi(n - 1, ueber, nach, von);
    }

    public static void main(String[] args) {
        k = new Klonk();
        for (int i = SCHEIBE.length - 1; i >= 0; i--) {
            k.placeBrick(SCHEIBE[i]);       // Startturm im Osten aufbauen
        }
        hanoi(SCHEIBE.length, 0, 1, 3);     // von Osten nach Norden über Süden
    }
}
```

- **Call-Stack (LF):** Einen Haltepunkt auf `k.pickBrick()` setzen – bei jedem Halt zeigt die Variablenansicht `n`, `von` und `nach` des aktuellen Aufrufs. Den Aufrufbaum für drei Scheiben zuvor auf Papier zeichnen.
- **Iterativ vs. rekursiv (LF):** „Bis zur Wand und zurück“ einmal mit Schleife, einmal rekursiv lösen.
- **Backtracking (LF):** Die Figur sucht rekursiv einen Weg durch das Labyrinth, markiert besuchte Felder und kehrt in Sackgassen um.

## Automaten und formale Sprachen

**Lehrplanbezug (Kurzfassung):** *Endliche Automaten mit und ohne Ausgabe (z. B. Mealy-Automat), Zustandsdiagramm und Übergangstabelle; im LF u. a. weitere Automaten und Grammatiken*

Die Figur lässt sich als **Mealy-Automat** modellieren: Eingaben sind Sensorwerte (`isWall()`, `isMark()`), Ausgaben Aktionen (`step()`, `turnLeft()`, `setMark()`). Ein Zustandsdiagramm „an der rechten Wand entlang“ wird in eine Übergangstabelle und dann in ein Programm mit einer Variable `zustand` überführt. Für Grammatiken eignet sich [Klonk-Script](/de/klonk-script/introduction) als kleine, überschaubare Sprache.

## Projektmanagement

**Lehrplanbezug (Kurzfassung):** *Projektauftrag, Phasen, Anforderungen, Abnahme; Vorgehensmodelle (Wasserfall, agil); Lastenheft, Pflichtenheft, User Stories; Prototyp*

- **Mehrdateiprojekte:** [Projekte](/de/klonk-script/projects) mit mehreren Java-Dateien in Packages, als Ordner auf dem Rechner oder als Browser-Projekt.
- **User Stories:** „Als Bauleitung möchte ich, dass die Figur einen Bauplan im JSON-Format umsetzt“ – mit `JsonObject` aus der Java-Bibliothek von Klonk.
- **Abnahme:** Testwelten aus dem [Welt-Editor](/de/world/editor) dienen als Abnahmekriterien; das Programm muss in jeder Welt das erwartete Ergebnis liefern.

## Hinweise für die Unterrichtsplanung

- **Sprachwahl:** Java, Python und C# verwenden dieselbe Objekt-API (`Klonk`); die Fachschaft kann die Sprache daher unabhängig von den Aufgabenwelten festlegen.
- **Lizenz berücksichtigen:** Aufgaben mit mehreren Figuren (z. B. Polymorphie mit verschiedenen Arbeitern) setzen eine [Lizenz](/de/administration/license) voraus; mit einer Figur bleiben Stack, Rekursion und Automaten vollständig umsetzbar.
- **Leistungsfeststellung:** Möglich sind etwa Aufgaben, bei denen zu einer vorgegebenen Welt ein Programm zu schreiben, ein Aufrufbaum vorherzusagen oder ein Zustandsdiagramm in ein Programm zu überführen ist.
