## 1.1 Objektorientiertes Programmieren

**Inhalte zu den Kompetenzen (Kurzfassung):** *Objektorientierte Modelle in standardisierter Notation (z. B. Klassendiagramm, Programmablaufplan, Struktogramm, Aktivitätsdiagramm); Algorithmen für Methoden; objektorientierte Programme implementieren, testen und verbessern*

### Einsatz von Klonk

Als Sprache kommen [Java](/de/klonk-script/java) oder [Python](/de/klonk-script/python) in Betracht. Jede Figur ist ein Objekt der Klasse `Klonk`; eigene Klassen nutzen eine Figur als **Attribut**.

| Kompetenz (Kurzfassung) | Umsetzung in Klonk |
|---|---|
| Aufgabe analysieren, objektorientiertes Modell erstellen | Klassendiagramm für einen „Maurer“: Attribute `figur`, `gelegt`; Methoden `mauer(farbe)`, `getGelegt()` |
| Lösungsansätze mit Algorithmen entwickeln | Struktogramm für die Methode `mauer` – bis zur Wand laufen und Ziegel legen |
| Implementieren, testen, verbessern | Klasse umsetzen, mit Haltepunkten prüfen, in verschiedenen Welten testen; das von Klonk erzeugte [Klassendiagramm](/de/klonk-script/diagrams#klassendiagramm) und [Struktogramm](/de/klonk-script/diagrams#struktogramm) mit dem eigenen Entwurf vergleichen |

```java
import klonk.Klonk;
import static klonk.Klonk.*;

class Maurer {
    private Klonk figur;      // Attribut: die gesteuerte Figur
    private int gelegt = 0;   // Attribut: Zähler

    Maurer(String name) {     // Konstruktor
        figur = new Klonk(name);
    }

    void mauer(String farbe) {
        while (!figur.isWall()) {
            figur.turnLeft();
            figur.placeBrick(farbe);
            gelegt++;
            figur.turnRight();
            figur.step();
        }
    }

    int getGelegt() {
        return gelegt;
    }
}

public class Main {
    public static void main(String[] args) {
        Maurer maurer = new Maurer("Klonk");
        maurer.mauer(GREEN);
        System.out.println("Gelegte Ziegel: " + maurer.getGelegt());
    }
}
```

::note
Die Klasse `Klonk` ist `final` – eigene Klassen erben nicht von ihr, sondern **haben** eine Figur als Attribut (wie `Maurer` oben). Mit einer [Lizenz](/de/administration/license) steuern mehrere Objekte mehrere Figuren gleichzeitig, z. B. `new Maurer("Klara")`.
::

## 1.2 Softwareprojekt

**Inhalte zu den Kompetenzen (Kurzfassung):** *Planungshilfen (z. B. Lasten- und Pflichtenheft), Projektphasen, Werkzeuge für die Teamarbeit, objektorientierte Programmiersprache*

### Einsatz von Klonk

Ein Klonk-Projekt eignet sich als überschaubares Teamprojekt: Die Gruppe verfasst ein Lastenheft (z. B. „Das Programm baut in jeder Welt ein Haus mit Tür und Dach“), teilt die Klassen untereinander auf und präsentiert am Ende das Ergebnis. Mehrere Dateien und Ordner werden im [Projekt-Explorer](/de/klonk-script/projects) verwaltet; das Einbinden von Klassen aus anderen Dateien setzt eine Lizenz voraus.

Der Lehrplan nennt als Beispiele auch Anwendungen mit Datenbank (digitales schwarzes Brett, Gästebuch). Die Datenhaltung solcher Anwendungen lässt sich in Klonk nachbilden: Ein Python- oder Java-Programm speichert Einträge in einer [Projektdatenbank](/de/klonk-script/databases) und gibt sie wieder aus. Eine Weboberfläche und die gemeinsame Nutzung durch mehrere Personen bietet Klonk jedoch nicht. Daraus ergibt sich die Einstufung ★★.

## 4.2 Robotik

**Inhalte zu den Kompetenzen (Kurzfassung):** *Aufbau und Funktionsweise von Robotern, Sensoren und Aktoren, Regeln und Steuern durch Sensorauswertung; einen Roboter bauen und programmieren (z. B. Linie folgen)*

### Einsatz von Klonk

Das Modul sieht einen **realen, von den Schülerinnen und Schülern selbst ausgestatteten Roboter** vor; dies kann Klonk nicht leisten. Als Vorübung ist Klonk dennoch einsetzbar: Die Figur verfügt über „Sensoren“ (`istWand`, `istMarke`, `istZiegel`) und reagiert darauf. Eine **Markenspur** im [Welt-Editor](/de/world/editor) dient als Linie, der die Figur folgen soll. So lässt sich das Programm planen und testen, bevor es auf die reale Hardware übertragen wird.
