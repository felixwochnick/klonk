This page summarises what school leaders, school authorities and education ministries need to know when deciding on the use of Klonk. The mapping to the curricula is found under [Germany](/en/teaching/germany/overview).

## Profile

- **Subject matter:** an introduction to algorithms and programming following the Robot Karol principle – students control characters made of building bricks in a 3D world.
- **Continuous progression:** from [blocks](/en/klonk-script/blocks) through the beginner language [Klonk-Script](/en/klonk-script/introduction) (German and English) to [Python](/en/klonk-script/python), [Java](/en/klonk-script/java) and [C#](/en/klonk-script/csharp). The characters' commands stay the same, so one tool can be used from lower secondary to upper secondary level.
- **Debugging as a teaching topic:** breakpoints, single-stepping and a variable view are available in every language.
- **No installation:** Klonk runs in the browser and can be installed as an app and used [offline](/en/klonk-script/offline).

## Operation

| Option | Suitable for |
|---|---|
| **Hosted platform** | Schools without their own server infrastructure |
| **[Self-hosted](/en/self-hosting/installation)** | School authorities and municipal or state data centres running Klonk on their own infrastructure (Docker Compose) |

The source code is publicly available ([source code license](/en/self-hosting/license)). One installation can manage several schools as separate organisations; their data is isolated from each other in the database.

## Data protection

- **Programs run on the device**, not on the server. Klonk stores programs, worlds and projects in the browser or in a folder on the device or school network – not on the Klonk server.
- **The server** holds the accounts (username, display name, role, organisation) and the school's settings.
- **No third-party content:** the learning app loads fonts, images and scripts exclusively from its own server.
- **AI assistant (optional):** the school decides whether to use it and with which language model – its own OpenAI-compatible service (e.g. in its own data centre) or a model that runs entirely in the browser. It can be switched off completely. Details: [AI assistant](/en/administration/ai).

::note
The data protection assessment (e.g. the record of processing activities, or a data processing agreement for the hosted platform) is the responsibility of the school or school authority. When self-hosting, all data remains within your own infrastructure.
::

## Sign-in and roles

- **Use of existing accounts:** single sign-on via OpenID Connect (e.g. Microsoft 365, Google Workspace, IServ, Keycloak) or LDAP/Active Directory; alternatively local accounts. Several methods can be active at the same time. See [Configure sign-in](/en/administration/sign-in).
- **Roles:** students, teachers, admins. Teachers can reset students' passwords.
- Klonk has **no class or assignment management** and no grading function. Tasks are distributed as world or project files, e.g. via the school network or the school's learning platform.

## Devices

- A current browser (Chrome, Edge, Firefox, Safari) on school computers, laptops or tablets. For tablets there is a view in which the code takes up the full width.
- Working directly in a folder (e.g. network drive, USB stick) is possible in Chrome and Edge; browser projects are available in all browsers.
- Python, Java and C# load their runtime once on first use; it is then cached in the browser.
- An AI model in the browser requires WebGPU and downloads about 1–2 GB once.

## License

The free version includes up to 10 accounts, one character per world and sign-in with password or LDAP. Use across a school usually requires a license; among other things it unlocks more accounts, several characters, single sign-on via OIDC, libraries and the AI assistant. Overview: [License](/en/administration/license).
