This section is intended for **teachers, subject departments, school leaders and education authorities**. It maps Klonk to the curricula and shows in which subjects, grades and learning areas its use is pedagogically justified.

Klonk follows the Robot Karol principle: students control characters in a 3D world made of building bricks and see immediately what their program does. This makes Klonk suitable for learning areas in which a curriculum provides for **algorithms, control structures and programming** – from the first sequence of steps in the lower grades to recursion in upper secondary. Klonk also includes a [database environment](/en/klonk-script/databases) with SQLite and PostgreSQL, so learning areas on relational databases and SQL can be covered as well. For the forms of representation required by the curricula, Klonk generates [diagrams](/en/klonk-script/diagrams) automatically: structograms from code in all languages, UML class diagrams and – at a breakpoint – UML object diagrams from Java, Python, C# and JavaScript/TypeScript programs, as well as ER diagrams and relational schemas from databases. The diagrams are derived from existing code or an existing schema; Klonk does not include an editor in which a model is drawn first and code or tables are generated from it.

[Learning modules](/en/teaching/modules/overview) are available for lesson planning: a basic course from the first instruction to variables, with tasks that Klonk checks automatically, sample solutions and notes for teachers. Teachers enable modules for their group and see the learning progress of the group. Your own tasks from Robot Karol (programs and worlds) can be [imported](/en/klonk-script/robot-karol).

Information on operation, data protection, sign-in and licensing is available under [For schools and school administration](/en/teaching/schools).

## How these pages are organised

In Germany, curricula are set by each state, and the same content goes by different names depending on the state and school type (*Schulform*) (e.g. *Natur und Technik*, *Informatik*, *Medienbildung*, *Wirtschaftsinformatik*). That is why this section is organised by where the teaching takes place:

**Country → State → School type → Grade**

For each grade you will find the learning areas (*Lernbereiche*) of the curriculum, an assessment of Klonk's suitability, a possible teaching sequence and notes for lesson planning.

| Fit | Meaning |
|---|---|
| ★★★ | Klonk covers the core of the learning area and can be used as the central tool. |
| ★★ | Klonk suits individual competence expectations or serves as an introduction or exercise. |
| ★ | Only as an application example or project topic. |
| – | Klonk is not intended for this (e.g. spreadsheets, network technology). |

## Which language for which level?

| Level | Recommendation |
|---|---|
| Beginners (e.g. grades 5–8) | [Blocks](/en/klonk-script/blocks) or [Klonk-Script](/en/klonk-script/introduction) in the students' language – without syntax hurdles, debugger on the block |
| Middle school with object-oriented programming | [Java](/en/klonk-script/java) or [Python](/en/klonk-script/python) – every character is an object of the class `Klonk` |
| Upper school | Java, Python, [C#](/en/klonk-script/csharp) or [JavaScript/TypeScript](/en/klonk-script/javascript) with [projects](/en/klonk-script/projects) made of several files |

::note
The mappings are pedagogical suggestions and do not replace the binding curriculum text. Every page links to the full text of the respective curriculum.
::
