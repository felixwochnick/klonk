## 2.6.1 Modelling and Coding Algorithms

*Concept of an algorithm; notations (structogram, pseudocode, flowchart); syntax and semantics; development environment (syntax highlighting, compilation, debugging); data types (numbers, characters, strings, Boolean values, arrays); functions with parameters and return values; structured debugging with breakpoints and variable values*

**Competence expectations (summary):** model processes – the curriculum gives the *conditional movement of a robot* as an example – with basic algorithmic building blocks · write source code from the model · program clearly with variables, data types, functions and comments · check programs and fix errors.

**Tool:** The curriculum calls for a **modern, text-based programming language**. In Klonk, that is [Python](/en/klonk-script/python) or [Java](/en/klonk-script/java) – both with the same world and the same tasks as in the foundation course. Klonk-Script works as a bridge, but has no arrays (lists); for those you need Python or Java.

| Content according to the curriculum | Implementation in Klonk |
|---|---|
| Algorithm, conditional movement of a robot | The character walks to the wall, avoids bricks, searches for a mark |
| Notations | first a structogram or flowchart, then code – the run in the world shows whether model and program match |
| Syntax and semantics | the editor underlines syntax errors while typing; runtime errors (the character walks into the wall) reveal errors in meaning |
| Development environment | syntax highlighting, suggestions while typing, compilation (Java), debugger – all in the browser |
| Data types | numbers (`brick_count()`), Boolean values (`is_wall()`), strings (`print`), arrays: a list of colors |
| Functions with parameters and return value | `def lay_row(robot, colors)` returns the number of bricks placed |
| Structured debugging | set a breakpoint, single step, variables view – exactly as described in the curriculum |

```python
from klonk import Klonk, red, blue, green

klonk = Klonk()


# Places bricks to the left of the path in the colors of the list
def lay_row(robot, colors):
    placed = 0
    for color in colors:
        if robot.is_wall():
            break
        robot.turn_left()
        robot.place_brick(color)
        robot.turn_right()
        robot.step()
        placed += 1
    return placed


count = lay_row(klonk, [red, blue, green, red])
print("Bricks placed:", count)
```

### Teaching ideas

- **From the foundation course to a text-based language:** Transfer a Klonk-Script or block program from module 1.2 to Python. The learners see: the same control structures, different syntax.
- **Debugging as a task:** Hand out a program with a built-in bug (e.g. a wrong termination condition). Using a breakpoint and the variables view, the learners find the point where `placed` or the position is no longer correct.
- **Testing in several worlds:** Run the same function in a small, a large and a cluttered world – does it work everywhere?
- **Exam preparation:** This module is one of the six modules of the voluntary IT final examination.

## 2.6.2 Object-Oriented Software Development

*Phases of software development; class diagram, activity diagram, structogram; structuring, modularisation; testing and optimisation*

**Tool:** [Java](/en/klonk-script/java) (or Python). Every character is an object of the class `Klonk` (`new Klonk("Klara")`) – this makes it easy to demonstrate object, attribute and method directly.

- **Class diagram of a custom class:** e.g. `BuildCrew` with the attributes *character*, *color*, *placed* and the methods `place()` and `build()`. The class `Klonk` is `final`; custom classes therefore hold a character as an attribute.
- **Modularisation:** With a [project](/en/klonk-script/projects), the learners spread their classes across several files.
- **Phases of software development:** analysis (what should be built?), design (class diagram), implementation, testing in several worlds, optimisation (fewer steps, shorter code).

::tip
More than one character at a time requires a license. Without a license, every object works with the same character – which is enough for custom classes.
::

## 2.7.2 Robotics and Embedded Systems

*Sensors and actuators; models for planning processes (flowchart, structogram, state transition diagram); closed-loop and open-loop control by evaluating sensors; testing and optimisation*

The module requires learners to equip and program a **real robot** or embedded system with components – Klonk cannot replace that. However, Klonk is suitable as a **simulation for preparation**:

- **State transition diagram:** Plan the behaviour of a character in states (*driving*, *avoiding*, *done*) and implement it as a program.
- **Line following in the simulation:** Lay a track of marks in the world editor; the character follows it with `is_mark()` – the curriculum's example, before moving on to hardware and real sensors.
- **Evaluating sensors:** Discuss the wall and brick sensors as a simplified model of real sensors – and what a real sensor does differently (measurement errors, measuring range).

## 2.8.5 IT Project

*Project phases; teamwork; example topics such as developing learning software*

Project ideas with Klonk:

- **Learning course:** A team builds task worlds for younger classes and writes model solutions in Klonk-Script.
- **Construction site:** A program builds a building out of bricks; several groups each take on one construction section.
- **Custom characters:** Characters designed in the [design editor](/en/world/designs) (license feature) appear in a project world.

## Other modules

Word processing, spreadsheets, database systems, CAD, data networks, logic circuits, artificial intelligence and multimedia are not covered by Klonk. For logic circuits, the operators `and`, `or`, `not` in conditions can at most be mentioned as a cross-reference – Klonk does not simulate circuits.
