---
title: Configure sign-in
description: Local accounts, single sign-on via OIDC or LDAP for your school or company.
---

Under **Admin → Sign-in** admins choose how the members of their organization sign in. Several methods can be active at the same time. Everyone signs in with `name@domain` – Klonk detects the organization from the domain and offers the matching methods.

## Accounts with password

Admins create accounts in the admin area and set an initial password that must be changed on first sign-in. Teachers and trainers can reset passwords of students.

## Single sign-on (OIDC)

Works with any OpenID Connect provider, e.g. Microsoft 365 (Entra ID), Google Workspace, IServ, Keycloak or Authentik.

1. Create an application at your identity provider and register the **redirect URI** shown in the admin area (with central sign-in only `https://auth.…/auth/oidc/callback`).
2. Enter issuer URL, client ID and client secret in Klonk and **test the connection**.
3. Optionally name a claim containing groups or roles (e.g. `groups`) and map which values are teachers or admins.

Accounts are created automatically on first sign-in.

## LDAP / Active Directory

Klonk looks up the user with a service account (bind DN) and verifies the password directly against the directory.

| Field | Example (Active Directory) |
|---|---|
| Server URL | `ldaps://dc.school.local:636` |
| Bind DN | `CN=klonk,OU=Services,DC=school,DC=local` |
| Base DN | `OU=Users,DC=school,DC=local` |
| User filter | `(&(objectClass=user)(sAMAccountName={{username}}))` |
| Username attribute | `sAMAccountName` |
| Name attribute | `displayName` |

Roles are mapped via groups (`memberOf`). Input is escaped for the filter, so special characters like `*` have no effect.

::callout{icon="i-lucide-lock"}
Client secret and bind password are stored encrypted and never shown again.
::
