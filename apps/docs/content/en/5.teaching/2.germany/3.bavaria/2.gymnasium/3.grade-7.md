## 2.3 Describing processes with algorithms

*Concept of an algorithm; statement, sequence, one- and two-sided conditional statement, repetition with a fixed count and with a condition*

**Competence expectations (*Kompetenzerwartungen*, short version):** structure everyday problems, develop solution algorithms and describe them with control structures · implement simple algorithms with a programming tool.

**Tool:** [Blocks](/en/klonk-script/blocks) to get started, then [Klonk-Script](/en/klonk-script/introduction) in German. The two can be compared at any time – blocks generate Klonk-Script.

### Lesson sequence

| Step | Control structure | Task in Klonk |
|---|---|---|
| 1 | Statement, sequence | Lead the character to a target cell, build a wall of three bricks |
| 2 | Repetition with a fixed count | Walk around a square, build stairs (`repeat 4 times`) |
| 3 | Repetition with a condition | Walk to the wall – no matter how big the world is (`repeat while not isWall`) |
| 4 | One-sided conditional statement | On the way, place a brick only on marked cells |
| 5 | Two-sided conditional statement | Pick up a brick if there is one, otherwise place one |
| 6 | Nesting | Work through a whole area: row by row, turning at the edge |

```klonk
// Steps 3 + 5: walk to the wall and "flip" bricks
repeat while not isWall
  if isBrick then
    pickBrick
  else
    placeBrick(blue)
  end
  step
end
```

### Tips

- **Structogram and program side by side:** The learners first design a structogram (Nassi–Shneiderman diagram), then the block code. Blocks closely resemble structograms.
- **Make the process visible:** With the speed slider and **Step** (F10), everyone sees which statement is currently running – with blocks, the block lights up.
- **Check generality:** Start the same solution in a larger world or one built differently. Does it still work? This makes the difference between a fixed count and a condition tangible.
- **Prepare worlds:** Save task worlds built in the [world editor](/en/world/editor) as files and hand them out to the class.

## 2.4 Project

*Develop a hypertext structure or an algorithmic solution in a team; save intermediate states, document the work process*

Project ideas with Klonk:

- **Building site:** Each group builds a building (house, bridge, pyramid) out of bricks with a program.
- **Obstacle course:** One group builds a world with obstacles, another writes the program that gets through it – and vice versa.
- **Several characters:** With `create` and `switch`, several characters work together (e.g. one places bricks, the other sets marks).

With a [project](/en/klonk-script/projects), each group saves programs and worlds as files – which also covers *saving intermediate states*.
