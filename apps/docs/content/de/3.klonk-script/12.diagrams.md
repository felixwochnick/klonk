Klonk zeichnet Diagramme zu deinem Code selbst – du musst nichts von Hand zeichnen. Sie stehen im Editor rechts im Tab **Diagramm** neben Welt und Doku und passen sich beim Tippen an.

| Diagramm | Wofür | Sprachen |
|---|---|---|
| **Struktogramm** | Ablauf eines Programms (Nassi-Shneiderman, DIN 66261) | alle: Klonk-Script, Blöcke, JavaScript/TypeScript, Python, Java, C# |
| **Klassendiagramm** | Klassen mit Attributen und Methoden, Vererbung, Beziehungen (UML) | JavaScript/TypeScript, Python, Java, C# |
| **Objektdiagramm** | Objekte mit ihren Werten und Verweisen in einem bestimmten Moment (UML) | JavaScript/TypeScript, Python, Java, C# |
| **ER-Diagramm** | Tabellen und Beziehungen einer Datenbank | SQLite, PostgreSQL |

Ein Klick auf ein Element springt zur passenden Zeile im Code. Mit dem Download-Knopf speicherst du ein Diagramm als **SVG** oder **PNG**, etwa für ein Arbeitsblatt oder eine Präsentation. Beim Export ist es immer hell.

## Struktogramm

Jede Anweisung wird ein Rechteck, jede Verzweigung ein Dreieck mit den Zweigen *wahr* und *falsch*, jede Schleife ein Rahmen:

- **Kopfgesteuerte Schleife:** `wiederhole 3 mal`, `wiederhole solange …`, `while`, `for`
- **Fußgesteuerte Schleife:** `do … while`
- **Endlosschleife:** `wiederhole immer`, `while (true)`
- **Fallauswahl:** `switch` bzw. `match`
- **Aufruf** eines eigenen Unterprogramms: Rechteck mit doppelten Seitenlinien
- **Aussprung:** `abbrechen`, `zurück`, `return`, `break`

Das Hauptprogramm und jede eigene Anweisung, Funktion oder Methode bekommen ein eigenes Struktogramm. Oben wählst du *Alle Struktogramme* oder ein einzelnes aus.

Während das Programm läuft oder im Debugger anhält, ist die gerade ausgeführte Zeile im Struktogramm markiert. So siehst du, wie das Programm durch Schleifen und Verzweigungen wandert.

## Klassendiagramm

Klonk liest die Klassen aus dem Code:

- **Attribute** und **Methoden** mit Sichtbarkeit: `+` öffentlich, `-` privat, `#` geschützt, `~` Paket.
- **Statische** Elemente sind unterstrichen, **abstrakte** kursiv. `«interface»`, `«abstract»` und `«enumeration»` stehen über dem Namen.
- **Vererbung** (Pfeil mit hohlem Dreieck) und **Implementierung** (gestrichelt).
- **Assoziationen:** Hat eine Klasse ein Attribut vom Typ einer anderen Klasse, zeigt ein Pfeil dorthin, beschriftet mit dem Attributnamen. Listen und Arrays bekommen die Multiplizität `*`.

Nutzt dein Code die Klasse `Klonk` oder `Database`, erscheint sie gestrichelt als Klasse aus der Bibliothek.

In einem Projekt wählst du oben *Diese Datei* oder *Ganzes Projekt*. Ein Klick auf eine Klasse aus einer anderen Datei öffnet diese Datei.

Wo der Code keine Typen angibt (Python, JavaScript), leitet Klonk sie aus der Zuweisung ab: `self.punkte = 0` wird `punkte: int`, `this.figur = new Klonk()` wird `figur: Klonk`. In Python gelten Namen mit `_` als geschützt und mit `__` als privat.

## Objektdiagramm

Das Objektdiagramm zeigt die Objekte, die es **gerade** gibt:

1. Setze einen **Haltepunkt** (Klick links neben die Zeilennummer).
2. Führe das Programm aus.
3. Hält es an, zeigt der Tab *Objektdiagramm* alle Objekte, die von den Variablen aus erreichbar sind.

Jedes Objekt erscheint als Kasten `name : Klasse` (unterstrichen) mit seinen Attributwerten. Verweise auf andere Objekte sind Pfeile, beschriftet mit dem Attributnamen. Zeigen zwei Variablen auf **dasselbe** Objekt, gibt es nur einen Kasten. So wird sichtbar, was eine Zuweisung wie `b = a` wirklich tut.

Listen und Arrays erscheinen als eigenes Objekt mit den Einträgen `[0]`, `[1]` … Figuren (`Klonk`) zeigen zusätzlich ihre Lage und Blickrichtung in der Welt. Mit *Einzelschritt* kannst du zusehen, wie neue Objekte entstehen und sich Verweise ändern. Läuft das Programm weiter, bleibt der Stand beim letzten Anhalten stehen.

```python
from klonk import Klonk

class Konto:
    def __init__(self, inhaber):
        self.inhaber = inhaber
        self.stand = 0

a = Konto("Mia")
b = a          # kein neues Objekt – b zeigt auf dasselbe Konto
b.stand = 10
print(a.stand) # Haltepunkt hier: im Objektdiagramm steht nur ein Konto mit a, b
```

## ER-Diagramm

Öffne eine Datenbank (`.sqlite.sql` oder `.postgres.sql`) und wechsle oben von *SQL* zu **ER-Diagramm**. Klonk zeichnet das Diagramm aus den Tabellen:

- **Tabellen** werden Entitäten, ihre Spalten Attribute. Der Primärschlüssel ist unterstrichen.
- **Fremdschlüssel** (`REFERENCES`) werden Beziehungen. Ist der Fremdschlüssel eindeutig (`UNIQUE`), ist es eine 1:1-Beziehung, sonst 1:n.
- **Zwischentabellen**, deren Primärschlüssel aus zwei Fremdschlüsseln besteht, werden n:m-Beziehungen. Ihre übrigen Spalten hängen an der Beziehung.

Oben wählst du die Darstellung:

| Darstellung | Aussehen |
|---|---|
| **Chen (1:n)** | Entitäten als Rechteck, Attribute als Ellipse, Beziehungen als Raute, Kardinalitäten 1, n, m |
| **Chen (min,max)** | wie oben, aber mit (min,max)-Angaben, z. B. `(0,1)` und `(0,*)` |
| **Krähenfuß** | Tabellen mit allen Spalten (PK/FK), Linien mit Krähenfuß-Enden |
| **Relationenschema** | Text wie `schueler(id, vorname, ↑klasse_id)`: Schlüssel unterstrichen, Fremdschlüssel mit ↑ |

Ein Klick auf eine Tabelle zeigt ihre Zeilen in der SQL-Konsole. Damit Beziehungen erscheinen, müssen Fremdschlüssel im Schema stehen:

```sql
CREATE TABLE schueler (
  id INTEGER PRIMARY KEY,
  vorname TEXT NOT NULL,
  klasse_id INTEGER NOT NULL REFERENCES klassen(id)  -- NOT NULL ⇒ (1,1) statt (0,1)
);
```
