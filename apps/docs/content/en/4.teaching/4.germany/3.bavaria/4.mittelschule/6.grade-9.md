**Subject:** Computer Science (*Informatik*) · **Applies to:** all students (compulsory subject, 1 lesson per week), regular class and intermediate certificate class · Full curriculum text: [regular class](https://www.lehrplanplus.bayern.de/fachlehrplan/mittelschule/9/informatik/regelklasse) · [M class](https://www.lehrplanplus.bayern.de/fachlehrplan/mittelschule/9/informatik/mittlere-reife-klasse)

In grade 9 – the final year for many students – applications are created **also in project form**, for example a self-designed game. Students are to structure the process with **sub-methods** (*Teilmethoden*). Klonk can be used in the learning area *Programming*, with the same limitation regarding data input as in grade 8; it is not intended for learning areas 1 and 2.

| Learning area (*Lernbereich*) | Klonk |
|---|---|
| 1 Digital Exchange of Information (networks, internet) | – |
| 2 Data Processing (spreadsheets, charts) | – |
| 3 Programming (*Programmieren*) | ★★ |

## 3 Programming

**Content related to the competences (summary):** *Algorithmic structures (e.g. methods, statement, sequence, condition, alternative, repetition and nesting thereof); variable concept (identifiers, data types, assignment)*

**Competence expectations (summary):** create objects and modify them with algorithmic building blocks · implement applications for the input and output of data – also as a project – (R: largely independently, M: independently), using sub-methods and improving the application.

### Use of Klonk

[Klonk-Script](/en/klonk-script/introduction) or [Python](/en/klonk-script/python) can be used. Python is particularly suitable in the M class: the character is an **object** there, and sub-methods are functions with `def`.

As in grade 8: Klonk does not read keyboard input; the "input" comes from the world (sensors) and from chance. This results in the ★★ rating – games controlled by keyboard or mouse need to be implemented with a different tool.

### Project ideas

| Project | Sub-methods (examples) |
|---|---|
| **Dice race:** The character rolls a die and walks – how many rounds does it need to reach the wall? | `roll_dice()`, `walk(cells)`, `goal_reached()` |
| **Treasure hunt:** Marks lie in a prepared world; the character searches for the red one and reports its cell | `check_cell()`, `next_row()` |
| **Master builder:** A program builds a house out of bricks – wall, door and roof as separate methods | `wall(length)`, `door()`, `roof()` |
| **Tidying up:** The character collects all bricks in a row and reports how many there were | `collect()`, `report(count)` |

```python
# Dice race: sub-methods structure the process
import random
from klonk import Klonk, green

klonk = Klonk()


def roll_dice():
    return random.randint(1, 3)


def walk(robot, cells):
    walked = 0
    while walked < cells and not robot.is_wall():
        robot.step()
        walked += 1
    return walked


round_no = 0
while not klonk.is_wall():
    round_no += 1
    roll = roll_dice()
    print("Round", round_no, "– rolled:", roll, "– walked:", walk(klonk, roll))
klonk.set_mark(green)
print("Goal reached after", round_no, "rounds")
```

### Matching learning modules

The [learning modules](/en/teaching/modules/overview) contain tasks in blocks or Klonk-Script with automatic checking that students can work on independently – in class or at home. The following modules fit learning area 3 Programming:

- **Your own procedures** – structuring the process with sub-methods
- **Variables and counting** – assignment, counting and output, e.g. for projects such as "tidying up"
- **Functions with return values** – sub-problems as functions whose result is used further

### Notes for lesson planning

- **Project planning:** The sub-methods are first defined as a list or structogram and then divided up – each group member writes one method.
- **Saving intermediate states:** In a [project](/en/klonk-script/projects), the program and world are saved as files.
- **Debugging:** A breakpoint in `walk` shows `cells` and `walked` in the variables view at every stop.
- **License:** Several game characters require a [license](/en/administration/license); `Klonk("Klara")` can then be created as a second object, and two characters compete against each other.

## 1 and 2 – Networks, internet, spreadsheets

Network components, IP addresses, HTTP/DNS as well as spreadsheets and charts are not covered by Klonk. Other tools are required for these (e.g. network simulation, spreadsheet program).
