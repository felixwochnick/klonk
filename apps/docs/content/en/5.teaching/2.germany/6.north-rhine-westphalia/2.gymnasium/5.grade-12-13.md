**Subject:** Computer Science (*Informatik*), basic course (GK, *Grundkurs*) or advanced course (LK, *Leistungskurs*) · **Applies to:** qualification phase (*Qualifikationsphase*) Q1 and Q2 (grades 12 and 13 in G9) · [Full curriculum text (2013)](https://lehrplannavigator.nrw.de/system/files/media/document/file/klp_gost_informatik.pdf) · [new curriculum (2026)](https://lehrplannavigator.nrw.de/system/files/media/document/file/gost_klp_if_2026_08_24.pdf)

The core curriculum describes the competences at the **end of the qualification phase** and does not divide them between Q1 and Q2. Students who entered the EF before 1 August 2027 are taught according to the 2013 core curriculum; the new core curriculum reaches Q1 in a phased manner from 2028/29. According to the requirements for 2029, the **centralised Abitur** (*Zentralabitur*) assumes **Java** and **SQL**, plus documented Abitur classes (including `List`, `Stack`, `Queue`, `BinaryTree`, `DatabaseConnector`); there is no computer in the written examination.

## Core curriculum 2026 (Q1 from 2028/29)

The new curriculum keeps the content fields *data and their structuring*, *algorithms*, *formal languages and automata* and *computer science, people and society* and adds **artificial intelligence and machine learning** (including neural networks, evaluating AI models). Relevant for Klonk:

- **Algorithms:** iterative and recursive, modularisation, divide and conquer, in the LK additionally **backtracking**; data structures array (GK two-dimensional, LK multi-dimensional), stack, queue, list, tree, in the LK also **graph**; testing including special cases.
- **Data and their structuring:** class modelling with polymorphism and abstract classes, in the LK additionally interfaces.

## Recursion and backtracking

*Iterative and recursive algorithms; divide and conquer; backtracking (LK)*

With Klonk, recursion can be **observed**: every call moves the character, and the way back runs through the calls in reverse order.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    /** Recursively to the wall and back the same way; returns the distance to the wall. */
    static int thereAndBack(Klonk character) {
        if (character.isWall()) {                 // base case
            character.setMark(RED);
            character.turnLeft();
            character.turnLeft();
            return 0;
        }
        character.step();
        int distance = thereAndBack(character) + 1;   // recursive call
        character.step();                             // only runs on the way back
        return distance;
    }

    public static void main(String[] args) {
        Klonk klonk = new Klonk();
        System.out.println("Distance to the wall: " + thereAndBack(klonk));
    }
}
```

Ideas for lessons:

- **Recursive vs. iterative:** Solve the same task with a loop and recursively and compare both in single-step mode.
- **Backtracking in a maze (LK):** Build a maze out of blocks in the [world editor](/en/world/editor). The character recursively tries every direction, remembers visited cells in a two-dimensional array `visited[x][y]` (position via `positionX()`/`positionY()`) and turns back at dead ends – the marks remain as a visible trail.
- **Graphs (LK, new curriculum):** The world as a grid graph – free cells are nodes, neighbouring cells without blocks are edges. Breadth-first search with a queue finds the shortest path, which the character then walks.

## Data structures and Abitur classes

Klonk does **not** ship the classes of the centralised Abitur (`List`, `Stack`, `Queue`, `BinaryTree` …). Options:

- **Implement them yourself:** A simple queue or stack as a custom class – in the LK the curriculum requires implementing operations of dynamic data structures anyway.
- **As project files:** Put the source code of the Abitur classes as separate `.java` files into a [project](/en/klonk-script/projects). Several Java files in one project require a license.

Example: a `Queue` of jobs (“build wall”, “mark row”) is worked through by a character; with a `Stack`, the character remembers its path and walks it back in reverse.

## Object-oriented modelling

*Abstract classes, inheritance, polymorphism, associations with multiplicities, implementation diagrams*

An abstract class `Worker` with the subclasses `Mason` and `Marker`, called in a loop by a `Site` (1:n), shows polymorphism with a visible result – see the example under [Bavaria, grade 10](/en/teaching/germany/bavaria/gymnasium/grade-10). The class `Klonk` is `final`; custom hierarchies are created via classes that have a character as an attribute. More than one character requires a license (see [License](/en/getting-started/license)).

## Projects and development environment

The curriculum requires the use of an **educational development environment** (*didaktisch orientierte Entwicklungsumgebung*) for designing, implementing and testing. For this, Klonk offers breakpoints, single-step mode and the variables view as well as [projects](/en/klonk-script/projects) with packages. Test worlds stored as files in the project check special cases (empty world, world without an exit, character directly in front of the wall).

## What Klonk does not cover

Databases and SQL, computer architecture and networks, client–server communication, encryption, artificial neural networks and data protection. For automata and grammars, Klonk is only useful as an example (e.g. the syntax of Klonk-Script as a small formal language).
