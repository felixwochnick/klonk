Klonk is suited above all to Q1 (algorithmics and object-oriented modeling) and in part to Q2 (databases: implementing the schema, SQL) and Q3 (machine models).

## Q1.1 Classes and objects

**Reference to the KCGO (short version):** *Object as an instance, class as a blueprint; attribute, method, constructor; array/list of objects with library classes; information hiding, get/set; UML class diagram, association, aggregation – LK: inheritance, abstract class, polymorphism*

### Use of Klonk

- **Visible objects:** `new Klonk("Klara")` is an object that stands in the world; method calls visibly change its state.
- **Association:** A custom class `BuildingCrew` *has* a character as an attribute (the class `Klonk` is `final`, so custom classes use it via association, not inheritance). In the UML class diagram: `BuildingCrew` → `Klonk`. The [class diagram](/en/klonk-script/diagrams#class-diagram) that Klonk generates from the code shows this association with the attribute name; lists of objects receive the multiplicity `*`.
- **Object and reference:** At a breakpoint, the [object diagram](/en/klonk-script/diagrams#object-diagram) shows the existing objects with their attribute values. After an assignment such as `BuildingCrew b = a;`, only one object appears, referenced by both variables – an occasion to discuss the difference between object and reference.
- **Array/list of objects:** `Klonk.all()` returns all characters; an `ArrayList<BuildingCrew>` (Java) or a list (Python) manages several crews. Several characters require a [license](/en/administration/license).
- **Information hiding:** The attribute `placed` is private and can only be read via `getPlaced()`.
- **LK – polymorphism:** abstract class `BuildOrder` with `build()`, subclasses `Wall`, `Tower`, `Stairs`; a list of orders is processed, and each class builds differently.

A detailed Java example with constructor, getter and inheritance can be found on the page [Bavaria, grade 9](/en/teaching/germany/bavaria/gymnasium/grade-9).

## Q1.2 Searching and sorting algorithms

**Reference to the KCGO (short version):** *Linear and binary search, simple sorting algorithms with quadratic running time, running time analysis – LK: an efficient sorting algorithm*

- **Linear search in the world:** The character walks along a row of brick stacks and stops at the first stack of a certain height (`brickCount()`). Counted steps correspond to the comparisons.
- **Sorting:** Read stack heights into an array or list, sort them with selection sort or bubble sort and rebuild the row in sorted order. Optionally, the character actually moves the bricks around – this makes the number of swaps directly tangible.
- **Running time:** Run the same task with 3, 6 and 12 stacks and count the comparisons.

## Q1.3 Recursion

**Reference to the KCGO (short version):** *Termination condition, parameter passing, simple and multiple recursion, visualization; recursion vs. iteration – LK: backtracking*

The KCGO explicitly names **visualization**. In Klonk, every recursive call is a visible step; on the way back, the calls are completed in reverse order. For the 2027 GK, recursion is also the Q4 topic.

```python
from klonk import Klonk


def there_and_back(character):
    """Walks recursively to the wall and counts the cells on the way back."""
    if character.is_wall():                  # termination condition
        character.set_mark()
        character.turn_left()
        character.turn_left()
        return 0
    character.step()
    cells = there_and_back(character)        # recursive call
    character.step()                         # only runs on the way back
    return cells + 1


print(there_and_back(Klonk()), "cells to the wall")
```

- **Recursion vs. iteration:** Solve the same task with a `while` loop; compare in single step which variables exist in each case.
- **Multiple recursion:** `pyramid(n)` builds a level of width `n` and calls itself with `n - 2`; recursively generated patterns of marks as "recursive graphics".
- **LK – backtracking:** The character searches for the path through a maze of blocks, marks visited cells and turns back at dead ends. A separate table `visited[x][y]` (Java) or a `set` (Python) stores the visited cells.

## Q1.4 Lists and Q1.5 Graphs

- **Lists (★):** A self-implemented queue of building orders that the character processes one after the other – the world shows the result, the data structure itself stays in the code.
- **Graphs, LK (★★):** A world is a grid graph – free cells are nodes, neighboring cells without blocks are edges. The character explores a maze (depth-first search), builds an adjacency list and then walks the shortest path found by breadth-first search.

## Q3 Machine models

Klonk is not an automata simulator. However, because a character can only read and write cells, it is suitable for **acting out** machine models:

- **Turing machine (★★):** A row of cells is the tape, marks in different colors are the symbols (read with `isMark(red)`, write with `setMark(blue)`, `removeMark`), the character is the read/write head, and a variable `state` is the state. This can illustrate, for example, a "binary counter" or "doubling a word". However, the tape is limited by the size of the world.
- **Register machine (★★):** Each brick stack is a register: `placeBrick` = increment, `pickBrick` = decrement, `isBrick` = test for zero. A program that adds two registers becomes visible as moving bricks around.
- **Finite automata (★):** A row of colored marks is the input word; the character reads it cell by cell and changes its state according to a transition table – at the end, it accepts (e.g. sets a mark) or not.

Klonk does not cover formal languages, grammars and pushdown automata.

## Q2 Databases and Q4

**Q2 (★★):** Klonk includes SQLite and PostgreSQL in the browser ([Databases](/en/klonk-script/databases)). This makes it possible to implement the schema designed in Q2 with `CREATE TABLE`, primary and foreign keys, and to write and check SQL queries across several tables. Each operation of relational algebra (selection, projection, join) can be compared with an SQL query and traced in the result. From the implemented schema, Klonk generates an [ER diagram](/en/klonk-script/diagrams#er-diagram) in Chen notation (1:n or (min,max)) or crow's foot notation, as well as the relational schema. Not included are an editor in which an ER model is drawn first and tables are generated from it, a web database (access via a web page) and teaching material on data protection.

- **Checking the schema design:** The ER model created on paper is converted into tables; foreign keys are enforced in SQLite as well, so errors in the schema become apparent when test data is inserted. The ER diagram generated by Klonk is compared with the design: do all relationships appear, are the cardinalities correct, is the junction table recognised as an n:m relationship?
- **Database from a program:** A Java or Python program accesses the project database with `Database.open("school")`. Placeholders (`?` in SQLite, `$1` in PostgreSQL) pass values separately from the SQL text – a starting point for discussing SQL injection in web databases.

```java
import klonk.Database;
import klonk.Row;

public class Main {
    public static void main(String[] args) {
        Database db = Database.open("school");   // project file school.sqlite.sql
        String className = "7a";
        String sql = "SELECT s.first_name FROM students s "
                   + "JOIN classes c ON s.class_id = c.id WHERE c.name = ?";
        for (Row s : db.query(sql, className)) {
            System.out.println(s.getString("first_name"));
        }
    }
}
```

**Q4:** Suitability depends on the decree: computer engineering (switching networks) and Prolog "–", recursion or graphs as above.

## Notes for lesson planning

- **Take the Abitur focuses into account:** The choice of topic areas in which Klonk is used should be guided by the Abitur decree in force; for 2027 this concerns in particular Q1.1, Q1.2, Q1.3 (GK in Q4) and Q3.5.
- **Transfer to paper:** Since the exam is written without a PC, it is advisable to regularly also write programs from Klonk by hand, draw structograms and class diagrams, and predict program flows on paper beforehand. The diagrams generated by Klonk are then used for self-checking.
- **Consider licensing:** Tasks with several characters (e.g. lists of building crews) require a [license](/en/administration/license); recursion, searching, sorting and machine models can be implemented with one character.
