## Einordnung

Der Kernlehrplan beschreibt die Kompetenzen am **Ende der Qualifikationsphase** und teilt sie nicht auf Q1 und Q2 auf. Wer vor dem 01.08.2027 in die EF eingetreten ist, wird nach dem Kernlehrplan von 2013 unterrichtet; der neue Kernlehrplan erreicht die Q1 aufsteigend ab 2028/29. Im **Zentralabitur** werden laut den Vorgaben für 2029 **Java** und **SQL** vorausgesetzt, dazu dokumentierte Abiturklassen (u. a. `List`, `Stack`, `Queue`, `BinaryTree`, `DatabaseConnector`); einen Computer gibt es in der schriftlichen Prüfung nicht. Klonk ist daher als Werkzeug für die Erarbeitung im Unterricht zu sehen, nicht als Teil der Prüfungsumgebung. Es eignet sich vor allem für Objekte und Klassen, iterative und rekursive Algorithmen sowie für Projektarbeit.

## Rekursion und Backtracking

**Lehrplanbezug (Kurzfassung):** *Iterative und rekursive Algorithmen; Teilen und Herrschen; Backtracking (LK)*

**Einsatz von Klonk:** Rekursion lässt sich mit Klonk **beobachten**: Jeder Aufruf bewegt die Figur, auf dem Rückweg werden die Aufrufe in umgekehrter Reihenfolge abgeschlossen.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    /** Rekursiv bis zur Wand und denselben Weg zurück; liefert den Abstand zur Wand. */
    static int hinUndZurueck(Klonk figur) {
        if (figur.isWall()) {                 // Abbruchbedingung
            figur.setMark(RED);
            figur.turnLeft();
            figur.turnLeft();
            return 0;
        }
        figur.step();
        int abstand = hinUndZurueck(figur) + 1;   // rekursiver Aufruf
        figur.step();                             // läuft erst auf dem Rückweg
        return abstand;
    }

    public static void main(String[] args) {
        Klonk klonk = new Klonk();
        System.out.println("Abstand zur Wand: " + hinUndZurueck(klonk));
    }
}
```

**Unterrichtsgang:**

- **Rekursiv und iterativ:** Dieselbe Aufgabe wird mit einer Schleife und rekursiv gelöst; beide Lösungen werden im Einzelschritt verglichen.
- **Backtracking im Labyrinth (LK):** Im [Welt-Editor](/de/world/editor) wird ein Labyrinth aus Quadern gebaut. Die Figur probiert rekursiv jede Richtung, merkt sich besuchte Felder in einem zweidimensionalen Feld `besucht[x][y]` (Position über `positionX()`/`positionY()`) und kehrt in Sackgassen um; die Marken bleiben als sichtbare Spur erhalten.
- **Graphen (LK, neuer Lehrplan):** Die Welt wird als Gittergraph aufgefasst – freie Felder sind Knoten, Nachbarfelder ohne Quader sind Kanten. Eine Breitensuche mit einer Schlange ermittelt den kürzesten Weg, den die Figur anschließend abläuft.

## Datenstrukturen und Abiturklassen

Klonk enthält die Klassen des Zentralabiturs (`List`, `Stack`, `Queue`, `BinaryTree` …) **nicht**. Möglich sind:

- **Eigene Implementierung:** Eine einfache Schlange oder ein Stapel als eigene Klasse – im LK verlangt der Lehrplan ohnehin, Operationen dynamischer Datenstrukturen zu implementieren.
- **Als Projektdateien:** Der Quelltext der Abiturklassen wird als eigene `.java`-Dateien in ein [Projekt](/de/klonk-script/projects) gelegt. Mehrere Java-Dateien in einem Projekt erfordern eine Lizenz.

Beispiel: Eine `Queue` von Aufträgen („baue Mauer“, „markiere Reihe“) wird von einer Figur abgearbeitet; mit einem `Stack` merkt sich die Figur ihren Weg und läuft ihn rückwärts zurück.

## Objektorientierte Modellierung

**Lehrplanbezug (Kurzfassung):** *Abstrakte Klassen, Vererbung, Polymorphie, Assoziationen mit Multiplizitäten, Implementationsdiagramme*

Eine abstrakte Klasse `Arbeiter` mit den Unterklassen `Maurer` und `Markierer`, die eine `Baustelle` (1:n) in einer Schleife aufruft, zeigt Polymorphie mit sichtbarem Ergebnis – vgl. das Beispiel unter [Bayern, Klasse 10](/de/teaching/germany/bavaria/gymnasium/grade-10). Die Klasse `Klonk` ist `final`; eigene Hierarchien entstehen über Klassen, die eine Figur als Attribut haben. Mehr als eine Figur erfordert eine Lizenz (siehe [Lizenz](/de/administration/license)).

## Projekte und Entwicklungsumgebung

Der Lehrplan sieht den Einsatz einer **didaktisch orientierten Entwicklungsumgebung** zum Entwerfen, Implementieren und Testen vor. Klonk bietet dafür Haltepunkte, Einzelschritt und Variablenansicht sowie [Projekte](/de/klonk-script/projects) mit Packages. Testwelten als Dateien im Projekt prüfen Sonderfälle (leere Welt, Welt ohne Ausgang, Figur direkt vor der Wand).

## Was Klonk nicht abdeckt

Datenbanken und SQL, Rechneraufbau und Netzwerke, Client-Server-Kommunikation, Verschlüsselung, künstliche neuronale Netze sowie Datenschutz. Für Automaten und Grammatiken ist Klonk nur als Beispiel nutzbar (z. B. die Syntax von Klonk-Script als kleine formale Sprache).

## Hinweise für die Unterrichtsplanung

- **Abiturvorbereitung:** Da in der schriftlichen Prüfung kein Computer zur Verfügung steht, empfiehlt es sich, Klonk-Aufgaben mit Aufgaben ohne Rechner zu verbinden, etwa indem ein rekursiver Ablauf zunächst von Hand nachvollzogen und erst danach im Einzelschritt überprüft wird.
- **Lizenz:** Mehrere Figuren und mehrere Java-Dateien in einem Projekt (z. B. Abiturklassen als Projektdateien) setzen eine Lizenz voraus; dies ist bei der Planung von Projektphasen zu berücksichtigen.
