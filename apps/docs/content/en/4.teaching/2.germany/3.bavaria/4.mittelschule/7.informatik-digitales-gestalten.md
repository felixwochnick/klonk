## 1.1 Object-Oriented Programming

*Object-oriented models in standardised notation (e.g. class diagram, flowchart, structogram, activity diagram); algorithms for methods; implementing, testing and improving object-oriented programs*

**Tool:** [Java](/en/klonk-script/java) or [Python](/en/klonk-script/python). Every character is an object of the class `Klonk`; custom classes use a character as an **attribute**.

| Competence (summary) | Implementation in Klonk |
|---|---|
| Analyse a task, create an object-oriented model | Class diagram for a "bricklayer": attributes `character`, `placed`; methods `wall(color)`, `getPlaced()` |
| Develop solution approaches with algorithms | Structogram for the method `wall` – walk to the wall and place bricks |
| Implement, test, improve | Implement the class, check it with breakpoints, test it in different worlds |

```java
import klonk.Klonk;
import static klonk.Klonk.*;

class Bricklayer {
    private Klonk character;  // attribute: the controlled character
    private int placed = 0;   // attribute: counter

    Bricklayer(String name) { // constructor
        character = new Klonk(name);
    }

    void wall(String color) {
        while (!character.isWall()) {
            character.turnLeft();
            character.placeBrick(color);
            placed++;
            character.turnRight();
            character.step();
        }
    }

    int getPlaced() {
        return placed;
    }
}

public class Main {
    public static void main(String[] args) {
        Bricklayer bricklayer = new Bricklayer("Klonk");
        bricklayer.wall(GREEN);
        System.out.println("Bricks placed: " + bricklayer.getPlaced());
    }
}
```

::tip
The class `Klonk` is `final` – custom classes do not inherit from it, but **have** a character as an attribute (like `Bricklayer` above). With a license, several objects control several characters at the same time, e.g. `new Bricklayer("Klara")`.
::

## 1.2 Software Project

*Planning aids (e.g. requirements specification and functional specification), project phases, tools for teamwork, object-oriented programming language*

A Klonk project is suitable as a manageable team project: the group writes a requirements specification (e.g. "The program builds a house with a door and a roof in any world"), divides the classes among themselves and presents the result at the end. The [project explorer](/en/klonk-script/projects) manages several files and folders; including classes from other files requires a license.

The curriculum also gives applications with a database as examples (digital notice board, guest book) – such projects are not possible with Klonk. Hence ★★.

## 4.2 Robotics

*Structure and functioning of robots, sensors and actuators, closed-loop and open-loop control by evaluating sensors; building and programming a robot (e.g. line following)*

The module requires a **real robot equipped by the learners themselves** – Klonk cannot provide that. Klonk is still useful as a preliminary exercise: the character has "sensors" (`isWall`, `isMark`, `isBrick`) and reacts to them. A **track of marks** in the [world editor](/en/world/editor) becomes the line the character is to follow – this way, the program can be planned and tested before it goes onto the real hardware.
