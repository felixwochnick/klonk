## Algorithms

*Unambiguous instructions; program flowchart (PAP, *Programmablaufplan*) and structogram; statement, sequence, conditional statement, loop; implementation in a visual programming language; modularisation; targeted testing*

**Competence expectations (short version):** formulate instructions and carry them out step by step · convert them into a program flowchart or structogram · recognise basic structures · implement algorithms in a **visual programming language** · modularise · check by testing · determine the result by analysis and evaluate functionality.

**Tool:** [Blocks](/en/klonk-script/blocks) meet the requirement for a visual programming language. With **Show Klonk-Script**, the learners see the same algorithm as text – a good preview of grade 9.

| Step | Competence | Task in Klonk |
|---|---|---|
| 1 | unambiguous instructions, carry out step by step | Unplugged: one child is “the character” and only carries out precise commands; then the same commands as blocks |
| 2 | Sequence | Lead the character to a target cell, place three bricks side by side |
| 3 | Loop | Walk around a square (`repeat 4 times`), walk to the wall (`repeat while not isWall`) |
| 4 | Conditional statement | Place bricks only on marked cells (`if isMark`) |
| 5 | Program flowchart/structogram | First draw the process, then implement it with blocks – or the other way round, represent a finished program as a structogram |
| 6 | Modularisation | A custom procedure (category “My blocks”) for a subtask that occurs several times |
| 7 | Testing, analysis, evaluation | Predict the result of a program, then run it; test the same program in several worlds |

```klonk
// Modularisation: a custom procedure for a subtask
procedure fencePost
  turnLeft
  placeBrick(green)
  turnRight
end

repeat while not isWall
  fencePost
  step
end
fencePost
```

### Tips

- **Predict before starting:** “How many bricks will there be at the end?” – think first and write it down, then run it. This trains *determining the result by analysis*.
- **Step** (F10) and the speed slider show which block is currently running. In case of errors, the block is marked red.
- **Test worlds:** Build several worlds in the [world editor](/en/world/editor) (small, large, with obstacles) and hand them out as files. Does the solution work everywhere? This makes *targeted testing* concrete.
- **Debugging as evaluation:** Provide a faulty program – the learners use breakpoints (right-click on a block) to find the spot and explain why it does not work.

## Calliope mini (example teaching unit 6.2)

The example in the Lehrplannavigator programs a microcontroller here. Klonk does not replace the **hardware** – sensors, LEDs and buttons only exist on the real device. Anyone who teaches the unit without a Calliope or prepares it can practise the same competences (implementing and testing algorithms in a visual programming language) with Klonk: the character also has “sensors” (`isWall`, `isBrick`, `isMark`) and “actions”.

## Automata and encoding

- **Automaton:** The character reacts to its inputs (sensors) with actions. For a short program (e.g. “turn at the wall, otherwise step”), the learners draw a simple flow diagram and compare it with an automaton from their everyday lives.
- **Binary code:** A row of five cells is a “section of a byte”: mark = 1, no mark = 0. The learners lay out numbers with marks and read other people's rows as numbers.

## Computer systems: file management

In the [project explorer](/en/klonk-script/projects), the learners create a browser project with folders (e.g. `worlds/`, `programs/`) – an opportunity to talk about the principles of **structured file management**.

## What Klonk does not cover

Encryption, artificial intelligence (decision trees, neural networks), data awareness and data security are better taught unplugged or with specialised materials such as those linked in the Lehrplannavigator.
