**Subject:** Computer Science (*Informatik*) · **Applies to:** intermediate certificate class 10 (*Mittlere-Reife-Klasse*, compulsory subject, 1 lesson per week) · [Full curriculum text](https://www.lehrplanplus.bayern.de/fachlehrplan/mittelschule/10/informatik)

The M10 subject curriculum consists of **a single learning area**, *Data Processing and Programming* (*Datenverarbeitung und Programmieren*). It focuses on **relational databases**: students model simple everyday examples (e.g. the school library), implement them in a database management system and retrieve information with queries – also across several tables. It concludes with an **application that queries data from a database and outputs it**. M10 thus builds on the programming of grade 9.

| 1 Data Processing and Programming | ★★ |

## 1 Data Processing and Programming

**Content of the competences (summary):** *database systems (structure, tasks, areas of use); ER diagrams; database management system; forms; queries (combined conditions, across several tables, possibly with SQL)*

| Expected competence (summary) | Klonk |
|---|---|

### Use of Klonk

Klonk contains a [database environment](/en/klonk-script/databases) with SQLite that runs entirely in the browser – without a database server and also offline. A database is a file in the [project](/en/klonk-script/projects) (e.g. `library.sqlite.sql`); when it is opened, Klonk shows the tables with their columns and records as well as an SQL console that displays results as a table.

The curriculum leaves open whether queries are written in SQL or "clicked together" in a development environment. Klonk works **exclusively with SQL**; it contains neither a graphical query editor nor forms. This results in the rating ★★. Forms and mail merge require an office database program.

**Data model:** Students design the model on paper, for example as an ER diagram with the entities *book* and *loan*. After implementing it, Klonk generates an [ER diagram](/en/klonk-script/diagrams#er-diagram) from the tables created (Chen notation, crow's foot or relational schema) that can be compared with the students' own design.

```sql
-- School library: two tables connected by a foreign key
CREATE TABLE books (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  author TEXT,
  year INTEGER
);

CREATE TABLE loans (
  id INTEGER PRIMARY KEY,
  book_id INTEGER NOT NULL REFERENCES books(id),
  name TEXT NOT NULL,
  class TEXT,
  returned TEXT -- empty = still on loan
);

INSERT INTO books (id, title, author, year) VALUES
  (1, 'The Island of Dragons', 'K. Berger', 2021),
  (2, 'Learning to Program', 'L. Yilmaz', 2024),
  (3, 'The Secret in the Cellar', 'K. Berger', 2019);

INSERT INTO loans (book_id, name, class, returned) VALUES
  (1, 'Mia', 'M10a', NULL),
  (3, 'Mia', 'M10a', '2026-10-12'),
  (2, 'Jonas', 'M10b', NULL);

-- Which books does Mia currently have on loan? (across two tables, two conditions)
SELECT b.title, b.author
FROM loans l
JOIN books b ON b.id = l.book_id
WHERE l.name = 'Mia' AND l.returned IS NULL;
```

**Application with a database:** [Python](/en/klonk-script/python), which can be introduced in the M class of grade 9, is well suited to the guided application. The program opens the project database, runs a query and outputs the result. The name is passed as a **parameter** (`?`), like an input field in a form – this shows the idea of a parameterised query without a form.

```python
from klonk import Database

db = Database.open("library")
name = "Mia"  # like an input field in a form
rows = db.query(
    "SELECT b.title FROM loans l JOIN books b ON b.id = l.book_id "
    "WHERE l.name = ? AND l.returned IS NULL ORDER BY b.title",
    [name],
)
print(name, "has", len(rows), "book(s) on loan:")
for row in rows:
    print("-", row["title"])
```

## Matching learning modules

The [learning modules](/en/teaching/modules/overview) contain tasks with automatic checking that students can work on independently – in class or at home. The following modules from track S (SQL) match the learning area:

- **S1 The world as a table: SELECT** – table, record and attribute; first queries on the familiar world
- **S2 Changing the world: INSERT, UPDATE, DELETE** – entering and changing records
- **S3 Filtering and sorting** – queries with combined conditions, using a school library as the example
- **S4 Counting and grouping** – evaluations; prerequisite for S5
- **S5 Joining tables** – queries across several tables via primary and foreign keys
- **S6 Creating tables** – implementing simple relationships in a relational database themselves

For the application that queries data from a database and outputs it, the following module from track A matches:

- **A1 Queries in a program** – opening a database in a program, running queries, outputting the results (requires F1 from grade 9)

## Notes for lesson planning

- **Time:** With one lesson per week, it makes sense to use the learning modules for practice and homework and to spend class time mainly on modelling and discussion.
- **Distributing a database:** A prepared database (e.g. `library.sqlite.sql`) can be distributed to the class like any project file via the [Klonk Cloud](/en/klonk-script/cloud); the teacher collects submissions there.
- **Existing databases:** An SQLite file from another program (`.db`, `.sqlite`) can be imported into Klonk and, conversely, downloaded as a `.db` file.
- **Without programming experience:** If the students did not work in Python in grade 9, the module **F1 Switching over: Klonk as an object** is enough as a short introduction for A1.
