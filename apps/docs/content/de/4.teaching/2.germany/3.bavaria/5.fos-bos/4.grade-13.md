### 3 Mechatronik

*Sensoren, Aktoren, Wandler, Schnittstellen; Programmierung einfacher Steuerungs- und Regelungsvorgänge (z. B. Ampelsteuerung)*

Der Lernbereich zielt auf echte Hardware – die ersetzt Klonk nicht. Für die **Steuerungslogik** taugt die Figur als Modell: Sensoren (`isWall()`, `isMark()`, `brickCount()`) liefern Eingaben, Befehle sind die Aktoren. Eine Ampelsteuerung lässt sich z. B. mit Marken in drei Farben und `sleep()` als Zustandsfolge programmieren, bevor sie auf dem Mikrocontroller landet.

### Objektorientierte Analyse und Programmierung

*Anforderungen ermitteln; Objekte, Attribute, Methoden und Assoziationen ableiten; Klassendiagramm; dynamische Modelle in grafischer Form; Basisklasse und abgeleitete Klasse*

**Werkzeug:** [Java](/de/klonk-script/java) oder [C#](/de/klonk-script/csharp).

Klonk eignet sich für den ganzen Weg von der Anforderung zum Programm: Aus „Ein Winterdienst-Fahrzeug fährt eine Straße ab und streut dabei“ entsteht ein Klassendiagramm mit `Fahrzeug` und der Spezialisierung `Streufahrzeug`, aus dem Ablauf ein Sequenzdiagramm – und beides wird umgesetzt und in der Welt überprüft.

| Kompetenzerwartung (Kurzfassung) | Umsetzung in Klonk |
|---|---|
| Objekte, Attribute, Methoden aus Anforderungen ableiten | Fahrzeug *hat* eine Figur und eine gefahrene Strecke, *kann* fahren |
| Klassendiagramm erstellen | `Fahrzeug` – `figur: Klonk`, `strecke: int` – `fahre()`, `getStrecke()` |
| Dynamische Modelle | Sequenzdiagramm: `main` → `Streufahrzeug.fahre()` → `Klonk.setMark()`/`step()` |
| Objekte vorgegebener Klassen nutzen | `new Klonk()` ist die erste Figur der Welt |
| Eigene Klassen ableiten, Spezialisierung | `Streufahrzeug extends Fahrzeug` überschreibt `fahre()` |

```java
import klonk.Klonk;
import static klonk.Klonk.*;

class Fahrzeug {                          // Basisklasse aus dem Klassendiagramm
    protected final Klonk figur;
    protected int strecke = 0;

    Fahrzeug(Klonk figur) { this.figur = figur; }

    void fahre() {
        while (!figur.isWall()) {
            figur.step();
            strecke++;
        }
    }

    int getStrecke() { return strecke; }
}

class Streufahrzeug extends Fahrzeug {    // Spezialisierung
    Streufahrzeug(Klonk figur) { super(figur); }

    @Override
    void fahre() {
        while (!figur.isWall()) {
            figur.setMark(YELLOW);            // streuen
            figur.step();
            strecke++;
        }
        figur.setMark(YELLOW);
    }
}

public class Main {
    public static void main(String[] args) {
        Fahrzeug f = new Streufahrzeug(new Klonk());
        f.fahre();
        System.out.println("Gestreut auf " + (f.getStrecke() + 1) + " Feldern");
    }
}
```

::tip
Die Klasse `Klonk` ist `final` – eigene Unterklassen entstehen über eine **eigene** Basisklasse, die die Figur als Attribut hält. Das passt gut zur Unterscheidung von Assoziation („hat eine Figur“) und Vererbung („ist ein Fahrzeug“).
::
