Der **KI-Assistent** hilft beim Programmieren direkt in der IDE: Er kennt den Code, die Sprache, die Klonk-Befehle und die letzte Fehlermeldung. Er ist Teil der [Lizenz](/de/administration/license).

## Für Lernende und Lehrkräfte

- Rechts neben **Welt | Doku** gibt es den Tab **KI**. Dort stellst du Fragen zu deinem Programm – der aktuelle Code wird automatisch mitgeschickt.
- Bei einem Fehler erscheint im Fehlerkasten **Fehler erklären**: Der Assistent erklärt, was die Meldung bedeutet und woran es liegt.
- Mit **voller Hilfe** lassen sich Codeblöcke aus der Antwort per **Einfügen** (an der Cursorstelle) oder **Alles ersetzen** in den Editor übernehmen – beides lässt sich mit Strg+Z rückgängig machen.
- Im **Tipp-Modus** gibt der Assistent keine fertigen Lösungen, sondern erklärt, stellt Rückfragen und gibt Hinweise für den nächsten Schritt.

KI kann Fehler machen – Antworten immer prüfen.

## Einrichten (Verwaltung → KI-Assistent)

Admins der Organisation wählen das Sprachmodell:

| Einstellung | Bedeutung |
|---|---|
| **Standard der Instanz** | Übernimmt, was der Betreiber eingestellt hat (siehe unten) |
| **Aus** | Kein KI-Assistent |
| **Eigener Server (OpenAI-kompatibel)** | Jeder Dienst mit `/chat/completions`: OpenAI, Azure OpenAI, Ollama, vLLM, LM Studio, LiteLLM … |
| **Im Browser (WebLLM)** | Das Modell läuft auf dem Gerät der Lernenden |

**Lernende bekommen nur Hinweise** (Standard: an) schaltet den Tipp-Modus für Schüler:innen bzw. Mitarbeitende. Lehrkräfte/Ausbildende und Admins bekommen immer volle Hilfe.

### Eigener Server

- **API-Adresse** mit `/v1`, z. B. `https://api.openai.com/v1` oder `http://ollama:11434/v1`.
- **Modell**, z. B. `gpt-4o-mini` oder `qwen2.5-coder:7b`.
- **API-Schlüssel** (optional) – wird verschlüsselt gespeichert und nie an den Browser ausgeliefert.
- **Verbindung testen** schickt eine kurze Anfrage mit den eingegebenen Werten.

Alle Anfragen laufen über den Klonk-Server. Die Regeln (Tipp-Modus oder volle Hilfe) setzt der Server – Lernende können sie nicht umgehen. Mitgeschickt werden die Frage, der bisherige Chat, der Code der geöffneten Datei, die Fehlermeldung und die letzte Ausgabe; Namen und Konten nicht.

### Im Browser (WebLLM)

Mit [WebLLM](https://github.com/mlc-ai/web-llm) läuft ein kleines Sprachmodell direkt im Browser – **es verlassen keine Daten das Gerät**. Voraussetzungen:

- Browser mit **WebGPU** (aktuelles Chrome oder Edge; Safari/Firefox je nach Version).
- Beim ersten Öffnen werden die Modellgewichte einmalig von Hugging Face geladen (ca. 1–2 GB) und im Browser gespeichert.
- Je kleiner das Modell, desto schneller – aber auch einfacher die Antworten. Für Schulrechner empfiehlt sich **Qwen2.5-Coder-1.5B**.

Die Modelle haben eigene Lizenzen (Qwen2.5: Apache 2.0, Phi-3.5: MIT, Llama 3.2: Llama Community License).

## Standard der Instanz (Selbsthosting)

Betreiber legen in `docker/.env` einen Standard für alle Organisationen ohne eigene Einstellung und für Privatkonten fest:

| Variable | Beschreibung |
|---|---|
| `KLONK_AI_MODE` | `server`, `webllm` oder `off` (leer + `KLONK_AI_BASE_URL` gesetzt ⇒ `server`) |
| `KLONK_AI_BASE_URL`, `KLONK_AI_MODEL`, `KLONK_AI_API_KEY` | OpenAI-kompatibler Endpunkt |
| `KLONK_AI_WEBLLM_MODEL` | Modell für `webllm`, z. B. `Qwen2.5-Coder-1.5B-Instruct-q4f16_1-MLC` |
| `KLONK_AI_STUDENTS` | `tutor` (Standard, nur Hinweise) oder `full` |
