## 2 Object-oriented modelling and programming

**Curriculum reference (short version):** *Array (index, element, length); class as a data type; references, cardinalities; method calls between objects, encapsulation; polymorphism*

**Using Klonk:** [Java](/en/klonk-script/java) or [Python](/en/klonk-script/python), several characters in one world.

| Competence expectation (*Kompetenzerwartung*, short version) | Implementation in Klonk |
|---|---|
| Arrays for data of the same kind | `Klonk.all()` returns an array of all characters; control them all at once with a loop |
| Model object relationships and message passing | Class `Site` *has* several `Worker`s (1:n), the site calls their methods |
| Relationships via references, encapsulation | Attributes `private`, access only through methods |
| Management structure with insertion/removal | Add workers to and remove them from the site (`Klonk.create(…)` creates new characters) |
| Polymorphism in inheritance hierarchies | `Mason` and `Marker` override `work()`, the site only calls `work()` |

```java
import klonk.Klonk;
import static klonk.Klonk.*;

abstract class Worker {
    protected final Klonk character;
    Worker(Klonk character) { this.character = character; }
    abstract void work();
}

class Mason extends Worker {
    Mason(Klonk k) { super(k); }
    void work() {               // wall to the left of the path
        character.turnLeft();
        character.placeBrick(RED);
        character.turnRight();
        if (!character.isWall()) character.step();
    }
}

class Marker extends Worker {
    Marker(Klonk k) { super(k); }
    void work() { character.setMark(GREEN); if (!character.isWall()) character.step(); }
}

class Site {
    private final Worker[] workers = new Worker[4];
    private int count = 0;

    void add(Worker w) { workers[count] = w; count++; }

    void shift(int rounds) {
        for (int r = 0; r < rounds; r++)
            for (int i = 0; i < count; i++)
                workers[i].work();              // polymorphism
    }
}

public class Main {
    public static void main(String[] args) {
        Site s = new Site();
        s.add(new Mason(new Klonk()));
        s.add(new Marker(Klonk.create("Kim", "female", 1, 6)));   // new character on cell 1|6
        s.shift(4);
    }
}
```

## 3 Project

**Curriculum reference (short version):** *Project plan in a team, modelling with a class diagram, division of labour in the implementation, testing, documentation*

**Using Klonk:** A [project](/en/klonk-script/projects) with several Java files in packages is suited to teamwork with a division of labour: each person takes on one class (`src/site/Mason.java` …). Possible project topics:

- **City planner:** Several characters build a city together from a saved plan (JSON file with `JsonObject`).
- **Warehouse:** Characters sort bricks into rows by color.
- **Race:** Characters run through a maze following their own strategies – who reaches the goal first?

Testing is done against prepared worlds from the [world editor](/en/world/editor): the program must deliver the correct result in every test world.

## Notes for lesson planning

- **Prepare test worlds:** Teachers provide several worlds for the project and hand them out as files; these can also be used to check the state of the project.
- **Plan for a license:** The examples and project topics for this grade mostly work with several characters and therefore require a [license](/en/administration/license).
- **Assessment:** The project phase can be assessed, for example, on the basis of the class diagram, a program that runs correctly in the test worlds, and the documentation. Klonk has no submission or grading function; projects are exchanged as files.
