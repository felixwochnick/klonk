The learning modules lead in **four tracks** from the first instruction with blocks to your own classes, recursion, SQL queries across several tables and programs that work with a database. They cover the content on algorithms, programming and databases that the state curricula provide from lower secondary to upper secondary (sequence, repetition, branching, modularization, variables, object orientation, data structures, recursion, relational databases). Each module has a **code** made of the letter of its track and a number, e.g. E4, F3 or S5; the grade pages of this documentation use the same codes.

The modules are available in the app under **Learn**. They are suitable for lesson planning as well as for independent practice – in class, as homework or for learners with a private account. Each started module is saved as its own project – depending on what is allowed, in the student's [Klonk Cloud](/en/klonk-script/cloud), in the browser or in a folder on the computer (see [storage locations](#storage-locations)).

## The tracks

| Track | Language | Content | Requires |
|---|---|---|---|
| **E – Easy** | [Blocks](/en/klonk-script/blocks) and [Klonk-Script](/en/klonk-script/introduction) | a start with hands-on worlds (E1–E3), then basic algorithmic structures up to functions, several characters and puzzles | nothing |
| **F – Advanced** | [Python](/en/klonk-script/python), [Java](/en/klonk-script/java), [JavaScript, TypeScript](/en/klonk-script/javascript) or [C#](/en/klonk-script/csharp) | switching to a programming language, data types, methods, objects, lists, your own classes, inheritance, recursion | E4–E7 |
| **S – SQL** | SQL ([databases](/en/klonk-script/databases)) | querying, changing, grouping, joining, creating tables, subqueries | nothing |
| **A – Applications** | programming language as in track F, with a database | programs that query databases and store data, world and database, objects and tables | modules of tracks F and S |

Within a track, the modules build on each other; on the page of each module, Klonk names the modules it requires. A class does not have to work through a track completely or without gaps, though: depending on the curriculum, a grade may fit only E4–E7, for example, or S1–S5 together with F1–F3 (see [Mapping to the curricula](#mapping-to-the-curricula)).

- **Track E** requires no prior knowledge. It starts with three **entry modules** (E1–E3) for primary schools, special schools and learners without any prior experience: short texts, only sequence and – in the last task of each – repetition with a fixed count. All worlds consist of plates with 3 × 3 cells and can be rebuilt as hands-on material with the [print templates](/en/teaching/modules/printing): the children play the character, lay out the task on the printed plate and then solve it with blocks. The basic course (E4–E9) does not require the entry modules; modules E10 to E13 build on your own procedures (E8) and variables (E9).
- **Track F** builds on the control structures from E4–E7: the same character becomes an object of the class `Klonk`, and the commands become methods. Learners without prior knowledge therefore start with E4–E7, for example with blocks. In all languages, the programs use the English robot API (e.g. `step()`, `isWall()`).
- **Track S** requires no programming knowledge. S1 and S2 use the world as a database – queries and changes are visible in the 3D view; from S3 on, the tasks use sample databases from everyday school life.
- **Track A** combines both tracks: A1 requires F1 and S1, A2 additionally S2, A4 your own classes (F6).

## Structure of a module

- **Introduction:** The new topic is explained with a short example; the learning objectives are stated.
- **Tasks:** Each task consists of a task description, one or more start situations and hints that can be expanded one at a time. In track E, students work with **blocks** or in **Klonk-Script**, in tracks F and A in one of the programming languages, in track S with **SQL**.
- **Several start situations:** From E6 on and in tracks F, S and A, a task is usually checked in several start situations – in worlds of different sizes or layouts, or with different data sets. Counted-out solutions or a hard-coded result are then not enough; the program has to react to the sensors, and the query has to be formulated in general terms.
- **Automatic checking:** With **Check**, Klonk runs the solution in all start situations and compares the result with the goal state – depending on the task, e.g. position and direction of the characters, placed bricks and set marks, printed numbers, the result of the SQL query, the contents of tables after the run, or the structure of created tables (columns, data types, `NOT NULL`, primary and foreign keys). Each run starts with a fresh copy of the database. If something differs, Klonk names the start situation and the difference, such as the affected cell or the differing row. Endless loops are detected.
- **Required constructs:** Tasks can require a particular construct, e.g. a conditional loop, a function with a return value, your own class, inheritance, recursion, `GROUP BY` or a subquery. Klonk checks this in Klonk-Script on the syntax tree, in the programming languages on the structure of the code (the same analysis from which Klonk generates structograms and class diagrams), and in SQL on the query. A solution that reaches the goal in a different way is rejected with a corresponding hint.
- **Show goal:** Students can display the goal state of each start situation – the world in the 3D view or the expected result of a query.
- **Sample solution:** For students in a school organization it only appears after the task has been solved. Teachers, administrators and private accounts can see it at any time, in tracks F and A in each of the programming languages. Tasks and sample solutions are not published openly in this documentation.
- **Notes for teachers:** On each module page in the app, teachers and administrators additionally see notes on time needed, prerequisites, typical difficulties, differentiation and assessment.

## Enabling and learning progress

- **Teaching:** Teachers and administrators find their groups ordered by grade in the app under **Teaching**. For this, admins set the state and school type under **Administration → Organization** and assign classes to a grade under **Administration → Groups** (see [Groups](/en/administration/groups)). For each grade, Klonk lists the modules that fit according to the table [Mapping to the curricula](#mapping-to-the-curricula), with a link to the grade page of this documentation. In an overview of modules × classes, modules are enabled for single classes or all classes of the grade – with one click also all matching modules at once; for each class Klonk shows the share of solved tasks. In companies the area is called **Training** and lists the groups without grades.
- **Enabling per group:** The group leader (usually the teacher of a class or course, see [Groups](/en/administration/groups)) decides in the app under **Teaching** which modules the group can work on. Learners of a school or company only see modules enabled in one of their groups. Teachers and administrators see all modules, as do learners with a private account.
- **Language per module:** With each enabled module, the group leader decides which language is used: in track E blocks, Klonk-Script or either; in tracks F and A a particular programming language (Python, Java, JavaScript, TypeScript or C#) or the learners' choice. Track S always uses SQL. A class can, for example, start with blocks and use Klonk-Script from a later module on, or the department sets the language for tracks F and A that is also used in other lessons and in the Abitur. Without a setting (private accounts, teachers), all languages of the track are possible.
- **Learning progress of the group:** For each enabled module, Klonk shows how many tasks each student has solved, when they were last active and what share of the tasks has been solved across the whole group. In the task view of a module, each task shows whether it is solved, started or still open, and how many learners have solved it.
- **Storage locations:** <a id="storage-locations"></a>Under **Administration → Organization**, admins decide where learners may save module projects: in the Klonk Cloud (always included when self-hosted, part of the subscription on the hosted platform), in the device's browser and/or in a folder on the computer (USB stick, network drive; Chrome, Edge and Opera only). The group leader can restrict this further on their group's progress page. If several locations are allowed, learners choose when starting a module. **The group leader only sees progress and programs when they are saved in the Klonk Cloud**; modules saved in the browser or a folder stay on the device.
- **Viewing programs:** Clicking a started or solved task opens that person's program or query – read only. Teachers can run it, follow it step by step and have it checked; changes made by the learners appear as soon as they are uploaded.
- **Own modules:** Teachers can also create their own learning modules with their own tasks, worlds and model solutions; all teachers at the school see them and can enable them (see [Own learning modules](/en/teaching/modules/custom)).
- **Access:** The group leader sees programs and progress only for enabled modules and only for members of their groups. If a module is no longer enabled, access ends as well. Operators of the platform have no access to the learners' projects.

## Notes on use

- **Task folders:** In the project of a module, each task has a folder with the task description, start world(s) or databases, and the student's program or query. If the file is opened in the normal editor, Klonk loads the matching world; checking happens in the learning view.
- **Devices:** If progress is stored in the cloud, students can continue on any device they are signed in on; short interruptions of the network connection are bridged by the local copy. Modules saved in the browser exist only on that device; modules saved in a folder wherever the folder is available.
- **Several characters:** Tasks with several characters (e.g. in E11 and F4) can be solved without a [license](/en/administration/license) as well; the character limit of the license only applies to programs outside the learning modules.
- **Grading:** Klonk shows whether a task has passed the automatic check; Klonk has no grading function. Since the check runs in the student's browser, the status “solved” does not replace an assessment – the solution as a structure chart or flowchart, or a query written by hand, is a suitable addition, for example. Since Klonk generates a [structogram](/en/klonk-script/diagrams#structogram) for every program, such a task should be completed without access to Klonk.
- **Language:** Tasks, blocks and sample solutions follow the selected interface language (German or English). Klonk-Script understands German and English commands; in the programming languages of tracks F and A, the commands of the character are always English. In track S, the names of tables and columns follow the interface (e.g. `bricks` or `ziegel`). Checking does not depend on the language.
- **Your own tasks:** Beyond the learning modules, you can create your own tasks with the [world editor](/en/world/editor) and your own [databases](/en/klonk-script/databases) and distribute them as files.
