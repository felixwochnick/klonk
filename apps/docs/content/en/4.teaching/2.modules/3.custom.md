title: Own learning modules
description: Teachers create learning modules with their own tasks, worlds, databases and model solutions – visible to all teachers at the school and checked automatically like the included modules.
---

Besides the included modules, teachers can create **their own learning modules**: with tasks for their own lessons, the school grounds or a class project. Own modules are enabled, worked on and checked automatically just like the included ones; their progress appears in the same overview.

## Who sees and edits own modules

| | See | Enable for their own groups | Edit and delete |
|---|---|---|---|
| Author | yes | yes | yes |
| Other teachers at the school | yes | yes | no – they continue with a copy |
| Admins of the school | yes | yes | yes |
| Learners | only if the module is enabled in one of their groups | – | – |

Own modules belong to the school (in companies to the company): teachers at other schools do not see them. Private accounts cannot create own modules.

## Creating a module

1. In the app, open **Teaching → Own learning modules** and click **New learning module**.
2. Choose a title and a track. The track determines the languages and the structure of the tasks – as with the [included tracks](/en/teaching/modules/overview#the-tracks):

| Track | Learners’ languages | Starting situation of a task | Model solution |
|---|---|---|---|
| E – Easy | blocks and Klonk-Script | one or more worlds | Klonk-Script (German or English) |
| F – Advanced | Python, Java, JavaScript, TypeScript, C# | one or more worlds | in at least one of these languages |
| S – SQL | SQL | database with one or more data sets | SQL |
| A – Applications | as track F | databases, optionally worlds | as track F |

3. In the editor, add a short description, objectives, an introduction and notes for teachers under **General**. An optional **code** (e.g. “M1”) appears before the title like E4 or S2. Grades chosen under **Fits these grades** are marked as matching in the **Teaching** overview.

You write the texts in one language (**Language of the texts**); learners see them regardless of the interface language. As in the included modules, simple formatting is possible: a blank line for a new paragraph, `- ` for lists, `` `code` ``, `**bold**` and code blocks. If code blocks in several programming languages follow each other directly (e.g. ```` ```python ```` and ```` ```java ````), Klonk shows learners only the block in their language.

## Tasks

Each task consists of:

- **Task description and hints** – learners can reveal the hints one by one.
- **Starting worlds** (tracks E, F, optionally A): the editor offers the same tools as the world editor – place bricks, marks, blocks and characters, turn and name characters. A world can also be loaded from a file (`.klonkworld.json` from the world editor or a Robot Karol world, `.kdw`) or taken from the project that is currently open. **Copy world** adds another starting world as a copy that you then change slightly.
- **Databases** (tracks S and A): as an SQL script (`CREATE TABLE …`, `INSERT …`). In track S, learners query the first database; in track A, programs open it with `Database.open("name")`. Further **data sets** provide the same tables with different data.
- **Model solution**: its result in every starting situation is the **goal** Klonk compares the learners’ programs with. **Run model solution** shows the goal in every starting situation (world at the end, output, query result) and reports errors and endless loops. In tracks F and A one language is enough; JavaScript or else the first available language computes the goal. After solving, learners see the model solution in their language if there is one, otherwise in the available one.
- **Check**: what has to match at the end – the cell of every character, its facing direction, bricks, marks and blocks, the output (only the numbers in it or line by line), in SQL the query result (with or without the order of rows) and the contents or structure of certain tables.
- **Required constructs** (optional): e.g. a conditional loop, a method of one’s own or a subquery. If the construct is missing, the task does not count as solved even if the goal is reached.

::tip
Several slightly different starting worlds or data sets prevent counted solutions: a program that only contains `step(3)` reaches the mark in the first world but not in a second one where it lies one cell further.
::

## Saving, enabling, changing

- **Save** makes the current state available to everyone (button or Ctrl+S); until then, colleagues and learners see the last saved state. If two people (e.g. author and admin) have saved at the same time, Klonk asks which state should apply.
- As long as a task is missing something (text, starting world, model solution, check), the editor marks the module as **not complete**; only a complete module can be enabled.
- **Enable** as with the included modules under **Teaching**: in the modules × classes overview, own modules appear in the section **School’s own modules**, as they do on a group’s progress page. Language choice, storage locations and progress work as described there (see [Enabling and learning progress](/en/teaching/modules/overview#enabling-and-learning-progress)).
- **Changes** take effect as soon as they are saved, also for modules that are already enabled: new tasks appear for learners, changed worlds and solutions apply at the next check. Tasks already solved stay solved. A deleted task disappears from the progress.
- **Deleting** removes the module from all enabled groups. Programs learners have already written stay in their projects.

## Sharing with other schools

**Export** saves a module as a file (`.klonkmodule.json`). Teachers at another school – even on another Klonk installation – create it as their own module under **Own learning modules → Import** and can then adapt it. The file contains texts, worlds, databases and model solutions, but no learner data.
