## Strukturierte und objektorientierte Programmierung

*Variablen, Datentypen, Typumwandlung, Zeichenketten; Klassen, Attribute, Methoden, Referenzen, Zugriffsmodifikatoren, Kapselung, Konstruktoren, Vererbung; Struktogramm, Pseudocode, UML-Klassendiagramm. Nur LF: u. a. Polymorphie, abstrakte Klassen, generische Datentypen, Collections, Lambda-Ausdrücke*

**Werkzeug:** [Java](/de/klonk-script/java) (oder [Python](/de/klonk-script/python), [C#](/de/klonk-script/csharp)). Jede Figur ist ein Objekt der Klasse `Klonk`; eigene Klassen halten eine Figur als **Attribut** (Assoziation), da `Klonk` selbst `final` ist.

- **Klassendiagramm zuerst:** `Bautrupp` *hat eine* `Klonk`-Figur, `Turmbauer` *ist ein* `Bautrupp` – als UML zeichnen, dann implementieren.
- **Kapselung:** Attribute `private`, Zugriff über Methoden; ein Zähler für gelegte Ziegel lässt sich nur über `lege()` ändern.
- **LF – Polymorphie und Collections:** Eine `ArrayList<Arbeiter>` mit verschiedenen Unterklassen, die alle `arbeite()` überschreiben, in einer `for`-Schleife abarbeiten. Mehrere Figuren brauchen eine [Lizenz](/de/getting-started/license).

Ausführliche Beispiele dazu stehen bei [Bayern, Klasse 9](/de/teaching/germany/bavaria/gymnasium/grade-9) und [Klasse 10](/de/teaching/germany/bavaria/gymnasium/grade-10).

## Datenstrukturen: Stack und Queue

*Stack (LIFO), Queue (FIFO); Graph als Adjazenzmatrix und -liste; Knoten, Kanten, Grad, Zyklus*

Ein Ziegelstapel **ist** ein Stack: `placeBrick(farbe)` = *push*, `pickBrick()` = *pop*, `isBrick(farbe)` prüft das oberste Element (*top*), `brickCount()` liefert die Größe. Die Lernenden kapseln das in einer eigenen Klasse `ZiegelStack` und vergleichen sie mit einer Implementierung über ein Array.

Eine Labyrinthwelt wird zum **Graphen**: Felder sind Knoten, begehbare Nachbarfelder Kanten. Die Adjazenzmatrix wird zuerst von Hand aufgestellt, im LF dann von der Figur beim Erkunden erzeugt.

## Algorithmen auf Datenstrukturen

*Lineare und binäre Suche; Bubblesort, Selectionsort, Insertionsort, ein rekursives Sortierverfahren; Laufzeit (O-Notation); Dijkstra von Hand. Nur LF u. a.: Breiten- und Tiefensuche auf Graphen, Spannbäume, Greedy*

- **Sortieren sichtbar:** Eine Reihe von Ziegelstapeln wird nach Höhe sortiert. Die Höhen stehen in einem Array; jede Vertauschung baut die Figur in der Welt nach – Vergleiche und Vertauschungen zählen.
- **Binäre Suche:** In einer sortierten Reihe die erste Stelle mit Höhe ≥ k finden – die Figur läuft nur die Felder ab, die die Suche tatsächlich prüft. Der Unterschied zur linearen Suche wird als Schrittzahl sichtbar.
- **LF – Breitensuche:** Kürzesten Weg durchs Labyrinth berechnen und mit Marken ablaufen.
- **Dijkstra von Hand:** Stapelhöhen als Kantengewichte; danach im LF ggf. implementieren.

## Rekursion

*Rekursionsbasis und Rekursionsschritt, z. B. Türme von Hanoi; Divide and Conquer; Implementierung. Nur LF: Aufrufbaum/Call-Stack, Vergleich iterativ – rekursiv, Backtracking*

Die **Türme von Hanoi** nennt der Bildungsplan ausdrücklich – mit Klonk werden sie zu echten Türmen: Drei Stapel stehen im Osten, Norden und Süden der Figur, die Scheiben sind Ziegel verschiedener Farbe.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    static final String[] SCHEIBE = { YELLOW, GREEN, BLUE };   // klein ... groß
    static Klonk k;
    static int blick = 0;   // Vierteldrehungen nach links: 0 = Osten, 1 = Norden, 3 = Süden

    static void schaueZu(int richtung) {
        while (blick != richtung) {
            k.turnLeft();
            blick = (blick + 1) % 4;
        }
    }

    static void hanoi(int n, int von, int nach, int ueber) {
        if (n == 0) return;                 // Rekursionsbasis
        hanoi(n - 1, von, ueber, nach);     // kleinere Türme aus dem Weg
        schaueZu(von);
        k.pickBrick();                      // oberste Scheibe nehmen
        schaueZu(nach);
        k.placeBrick(SCHEIBE[n - 1]);       // und ablegen
        hanoi(n - 1, ueber, nach, von);
    }

    public static void main(String[] args) {
        k = new Klonk();
        for (int i = SCHEIBE.length - 1; i >= 0; i--) {
            k.placeBrick(SCHEIBE[i]);       // Startturm im Osten aufbauen
        }
        hanoi(SCHEIBE.length, 0, 1, 3);     // von Osten nach Norden über Süden
    }
}
```

- **Call-Stack (LF):** Einen Haltepunkt auf `k.pickBrick()` setzen – bei jedem Halt zeigt die Variablenansicht `n`, `von` und `nach` des aktuellen Aufrufs. Den Aufrufbaum für drei Scheiben vorher auf Papier zeichnen.
- **Iterativ vs. rekursiv (LF):** Bis zur Wand und zurück einmal mit Schleife, einmal rekursiv lösen.
- **Backtracking (LF):** Die Figur sucht rekursiv einen Weg durchs Labyrinth, markiert besuchte Felder und kehrt in Sackgassen zurück.

## Automaten und formale Sprachen

*Endliche Automaten mit und ohne Ausgabe (z. B. Mealy-Automat), Zustandsdiagramm und Übergangstabelle; im LF u. a. weitere Automaten und Grammatiken*

Die Figur als **Mealy-Automat**: Eingaben sind Sensorwerte (`isWall()`, `isMark()`), Ausgaben Aktionen (`step()`, `turnLeft()`, `setMark()`). Ein Zustandsdiagramm „an der rechten Wand entlang“ wird zur Übergangstabelle und dann zu einem Programm mit einer Variable `zustand`. Für Grammatiken eignet sich [Klonk-Script](/de/klonk-script/introduction) als kleine, überschaubare Sprache.
