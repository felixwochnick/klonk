## Q1.1 Classes and objects

*Object as an instance, class as a blueprint; attribute, method, constructor; array/list of objects with library classes; information hiding, get/set; UML class diagram, association, aggregation – LK: inheritance, abstract class, polymorphism*

- **Objects you can see:** `new Klonk("Klara")` is an object that stands in the world; method calls visibly change its state.
- **Association:** A custom class `BuildingCrew` *has* a character as an attribute (the class `Klonk` is `final`, so custom classes use it via association, not inheritance). In the UML class diagram: `BuildingCrew` → `Klonk`.
- **Array/list of objects:** `Klonk.all()` returns all characters; an `ArrayList<BuildingCrew>` (Java) or a list (Python) manages several crews. Several characters require a license.
- **Information hiding:** The attribute `placed` is private and can only be read via `getPlaced()`.
- **LK – polymorphism:** abstract class `BuildOrder` with `build()`, subclasses `Wall`, `Tower`, `Stairs`; a list of orders is processed, and each class builds differently.

A detailed Java example with constructor, getter and inheritance can be found on the page [Bavaria, grade 9](/en/teaching/germany/bavaria/gymnasium/grade-9).

## Q1.2 Searching and sorting algorithms

*Linear and binary search, simple sorting algorithms with quadratic running time, running time analysis – LK: an efficient sorting algorithm*

- **Linear search in the world:** The character walks along a row of brick stacks and stops at the first stack of a certain height (`brickCount()`). Counted steps = comparisons.
- **Sorting:** Read stack heights into an array/list, sort them with selection sort or bubble sort and rebuild the row in sorted order. If you like, let the character actually move the bricks around – then the number of swaps becomes "physically" tangible.
- **Running time:** Run the same task with 3, 6 and 12 stacks and count comparisons.

## Q1.3 Recursion

*Termination condition, parameter passing, simple and multiple recursion, visualization; recursion vs. iteration – LK: backtracking*

The KCGO explicitly names **visualization** – in Klonk, every recursive call is a visible step, and the way back walks through the calls in reverse. For the 2027 GK, recursion is also the Q4 topic.

```python
from klonk import Klonk


def there_and_back(character):
    """Walks recursively to the wall and counts the cells on the way back."""
    if character.is_wall():                  # termination condition
        character.set_mark()
        character.turn_left()
        character.turn_left()
        return 0
    character.step()
    cells = there_and_back(character)        # recursive call
    character.step()                         # only runs on the way back
    return cells + 1


print(there_and_back(Klonk()), "cells to the wall")
```

- **Recursion vs. iteration:** Solve the same task with a `while` loop; compare in single step which variables exist in each case.
- **Multiple recursion:** `pyramid(n)` builds a level of width `n` and calls itself with `n - 2`; recursively generated patterns of marks as "recursive graphics".
- **LK – backtracking:** The character searches for the path through a maze of blocks, marks visited cells and turns back at dead ends. A separate table `visited[x][y]` (Java) or a `set` (Python) remembers the cells.

## Q1.4 Lists and Q1.5 Graphs

- **Lists (★):** A self-implemented queue of building orders that the character processes one after the other – the world shows the result, the data structure itself stays in the code.
- **Graphs, LK (★★):** A world is a grid graph – free cells are nodes, neighboring cells without blocks are edges. The character explores a maze (depth-first search), builds an adjacency list and then walks the shortest path found by breadth-first search.

## Q3 Machine models

Klonk is not an automata simulator. But because a character can only read and write cells, it is well suited to **acting out** machine models:

- **Turing machine (★★):** A row of cells is the tape, marks in different colors are the symbols (read with `isMark(red)`, write with `setMark(blue)`, `removeMark`), the character is the read/write head, and a variable `state` is the state. This makes a "binary counter" or "doubling a word" visible. However, the tape is limited by the size of the world.
- **Register machine (★★):** Each brick stack is a register: `placeBrick` = increment, `pickBrick` = decrement, `isBrick` = test for zero. A program that adds two registers turns into moving bricks around.
- **Finite automata (★):** A row of colored marks is the input word; the character reads it cell by cell and changes its state according to a transition table – at the end, it accepts (e.g. sets a mark) or not.

Klonk does not cover formal languages, grammars and pushdown automata.
