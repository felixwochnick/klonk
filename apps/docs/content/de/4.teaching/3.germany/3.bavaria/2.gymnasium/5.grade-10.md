## 1 Datenmodellierung und relationale Datenbanksysteme

**Einsatz von Klonk:** [Datenbanken](/de/klonk-script/databases) im Projekt – SQLite oder PostgreSQL, beide laufen im Browser ohne Datenbankserver. Das Datenmodell entwerfen die Schülerinnen und Schüler auf Papier oder in einem Modellierungswerkzeug; einen grafischen Editor dafür enthält Klonk nicht. In Klonk wird das Modell als relationales Schema umgesetzt, mit Daten gefüllt und abgefragt. Fremdschlüssel werden dabei auch in SQLite geprüft. Daraus ergibt sich die Einstufung ★★.

- **Schuldatenbank erweitern:** Das Beispiel jeder neuen Datenbank (`klassen`, `schueler` mit Fremdschlüssel) wird um weitere Tabellen ergänzt; Abfragen über mehrere Tabellen verknüpfen sie über ihre Schlüssel.
- **Referentielle Integrität:** Ein Datensatz in `schueler` mit einer nicht vorhandenen `klasse_id` wird abgewiesen – an der Fehlermeldung lässt sich besprechen, wozu Fremdschlüssel dienen.
- **Vorhandene Datenbank übernehmen:** Eine SQLite-Datei (`.db`), etwa aus „DB Browser for SQLite“, lässt sich importieren; umgekehrt kann jede SQLite-Datenbank als `.db` heruntergeladen werden.
- **Datenbank und Programm (Brücke zu Lernbereich 2):** Ein Java-Programm liest das Ergebnis einer Abfrage und lässt die Figur für jede Klasse einen Ziegelstapel in der Höhe der Schülerzahl bauen – ein Säulendiagramm in der Welt.

```sql
SELECT k.name, COUNT(s.id) AS anzahl
FROM klassen k
LEFT JOIN schueler s ON s.klasse_id = k.id
GROUP BY k.id, k.name
ORDER BY k.name;
```

```java
import klonk.Klonk;
import klonk.Database;
import klonk.Row;

public class Main {
    public static void main(String[] args) {
        Klonk k = new Klonk();
        Database db = Database.open("schule");   // Projektdatei schule.sqlite.sql
        String sql = "SELECT k.name, COUNT(s.id) AS anzahl FROM klassen k "
                   + "LEFT JOIN schueler s ON s.klasse_id = k.id "
                   + "GROUP BY k.id, k.name ORDER BY k.name";
        for (Row r : db.query(sql)) {
            System.out.println(r.getString("name") + ": " + r.getInt("anzahl"));
            k.turnLeft();
            for (int i = 0; i < r.getInt("anzahl"); i++) {
                k.placeBrick();
            }
            k.turnRight();
            k.step();
        }
    }
}
```

## 2 Objektorientierte Modellierung und Programmierung

**Lehrplanbezug (Kurzfassung):** *Array (Index, Element, Länge); Klasse als Datentyp; Referenzen, Kardinalitäten; Methodenaufrufe zwischen Objekten, Kapselung; Polymorphismus*

**Einsatz von Klonk:** [Java](/de/klonk-script/java) oder [Python](/de/klonk-script/python), mehrere Figuren in einer Welt.

| Kompetenzerwartung (Kurzfassung) | Umsetzung in Klonk |
|---|---|
| Arrays für gleichartige Daten | `Klonk.all()` liefert ein Array aller Figuren; mit einer Schleife alle gleichzeitig steuern |
| Objektbeziehungen und Nachrichtenaustausch modellieren | Klasse `Baustelle` *hat* mehrere `Arbeiter` (1:n), die Baustelle ruft deren Methoden auf |
| Beziehungen über Referenzen, Kapselung | Attribute `private`, Zugriff nur über Methoden |
| Verwaltungsstruktur mit Einfügen/Entfernen | Arbeiter zur Baustelle hinzufügen und entfernen (`Klonk.create(…)` legt neue Figuren an) |
| Polymorphismus in Vererbungshierarchien | `Maurer` und `Markierer` überschreiben `arbeite()`, die Baustelle ruft nur `arbeite()` auf |

```java
import klonk.Klonk;
import static klonk.Klonk.*;

abstract class Arbeiter {
    protected final Klonk figur;
    Arbeiter(Klonk figur) { this.figur = figur; }
    abstract void arbeite();
}

class Maurer extends Arbeiter {
    Maurer(Klonk k) { super(k); }
    void arbeite() {            // Mauer links neben dem Weg
        figur.turnLeft();
        figur.placeBrick(RED);
        figur.turnRight();
        if (!figur.isWall()) figur.step();
    }
}

class Markierer extends Arbeiter {
    Markierer(Klonk k) { super(k); }
    void arbeite() { figur.setMark(GREEN); if (!figur.isWall()) figur.step(); }
}

class Baustelle {
    private final Arbeiter[] arbeiter = new Arbeiter[4];
    private int anzahl = 0;

    void hinzufuegen(Arbeiter a) { arbeiter[anzahl] = a; anzahl++; }

    void schicht(int runden) {
        for (int r = 0; r < runden; r++)
            for (int i = 0; i < anzahl; i++)
                arbeiter[i].arbeite();          // Polymorphismus
    }
}

public class Main {
    public static void main(String[] args) {
        Baustelle b = new Baustelle();
        b.hinzufuegen(new Maurer(new Klonk()));
        b.hinzufuegen(new Markierer(Klonk.create("Kim", "female", 1, 6)));   // neue Figur auf Feld 1|6
        b.schicht(4);
    }
}
```

::note
Mehr als eine Figur braucht eine Lizenz mit dem passenden Figurenkontingent (siehe [Lizenz](/de/administration/license)).
::

## 3 Projekt

**Lehrplanbezug (Kurzfassung):** *Projektplan im Team, Modellierung mit Klassendiagramm, arbeitsteilige Implementierung, Test, Dokumentation*

**Einsatz von Klonk:** Ein [Projekt](/de/klonk-script/projects) mit mehreren Java-Dateien in Packages eignet sich für arbeitsteilige Teamarbeit: Jede Person übernimmt eine Klasse (`src/baustelle/Maurer.java` …). Mögliche Projektthemen:

- **Stadtplaner:** Mehrere Figuren bauen gemeinsam eine Stadt nach einem gespeicherten Plan (JSON-Datei mit `JsonObject`).
- **Lagerhalle:** Figuren sortieren Ziegel nach Farbe in Reihen.
- **Rennen:** Figuren laufen nach eigenen Strategien durch ein Labyrinth – wer ist zuerst am Ziel?

Getestet wird gegen vorbereitete Welten aus dem [Welt-Editor](/de/world/editor): Das Programm muss in jeder Testwelt das richtige Ergebnis liefern.

## Hinweise für die Unterrichtsplanung

- **Testwelten vorbereiten:** Lehrkräfte stellen für das Projekt mehrere Welten bereit und verteilen sie als Dateien; daran lässt sich auch der Projektstand überprüfen.
- **Lizenz einplanen:** Die Beispiele und Projektthemen dieser Jahrgangsstufe arbeiten überwiegend mit mehreren Figuren und setzen daher eine [Lizenz](/de/administration/license) voraus.
- **Leistungsfeststellung:** Die Projektphase lässt sich z. B. anhand von Klassendiagramm, lauffähigem Programm in den Testwelten und Dokumentation bewerten. Klonk enthält keine Abgabe- oder Bewertungsfunktion; Projekte werden als Dateien ausgetauscht.
