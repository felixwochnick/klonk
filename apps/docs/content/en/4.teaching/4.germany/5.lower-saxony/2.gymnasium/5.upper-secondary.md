## Context

According to the VO-GO (*Verordnung über die gymnasiale Oberstufe*), computer science together with a science or with mathematics can form the **mathematics/science focus** (*mathematisch-naturwissenschaftlicher Schwerpunkt*); the two focus subjects are taught at the **advanced level** (eA, *erhöhtes Anforderungsniveau*). Only students who took part in computer science lessons throughout the introductory phase can choose it as a further course (supplementary subject, *Ergänzungsfach*).

The core curriculum gives no hours per module. The *qualification phase* column applies to all courses, the *eA extension* column (*Erweiterung eA*) additionally to courses at the advanced level. Klonk is suitable above all for the learning field “Algorithms and data structures”, for automata and formal languages, and for project-based teaching; in the learning field “Information and data” it is suitable for the module *Databases* but does not cover the other modules.

## Algorithmics and recursion

**Curriculum reference (short version):** *Analyse algorithms; parameters and return values; local and global variables; object references · eA: design and implement recursive algorithms, “divide and conquer”, efficiency*

**Use of Klonk:** [Java](/en/klonk-script/java) or [Python](/en/klonk-script/python) is used – depending on which language the school has chosen for the Abitur. Klonk makes recursion **visible**: every call moves the character, and on the way back the calls are completed in reverse order.

```java
import klonk.Klonk;
import static klonk.Klonk.*;

public class Main {
    // Walks recursively to the wall and back the same way, returns the number of steps
    static int thereAndBack(Klonk k) {
        if (k.isWall()) {               // base case
            k.setMark(GREEN);
            k.turnLeft();
            k.turnLeft();
            return 0;
        }
        k.step();
        int rest = thereAndBack(k);     // recursive call
        k.step();                       // only runs on the way back
        return rest + 1;
    }

    public static void main(String[] args) {
        Klonk klonk = new Klonk();
        System.out.println("Distance to the wall: " + thereAndBack(klonk));
    }
}
```

**Lesson sequence:**

- **Recursive and iterative:** The same task is additionally solved with a loop; both solutions are compared in single-step mode. The debugger shows how many calls are open at the same time.
- **Efficiency (eA):** Students count the character's steps when the world becomes twice as large and judge whether the effort grows linearly or quadratically.

## Classes and objects

Every character is an object of the class `Klonk` (`new Klonk()`, `new Klonk("Klara")`) and thus a concrete example of **object references**. Custom classes hold a character as an attribute, e.g. `BuildCrew` with `Klonk character`; subclasses such as `TowerBuilder extends BuildCrew` override methods (eA: inheritance, association in the class diagram). The class `Klonk` itself is `final`. Examples are provided on the page [Bavaria, grade 9](/en/teaching/germany/bavaria/gymnasium/grade-9); they can be adopted unchanged.

For every program, Klonk generates a [class diagram](/en/klonk-script/diagrams#class-diagram) with associations and inheritance, which can be compared with the students' own design. At a breakpoint, the [object diagram](/en/klonk-script/diagrams#object-diagram) shows which objects exist and what the references point to; after `BuildCrew b = a;` it contains only one object, referenced by both variables.

## Arrays, stacks and queues

- **Two-dimensional array:** The world is a grid. The character walks through it row by row and stores `bricks[y][x]` with `brickCount()`; then the maximum, sum or a sorted order is computed.
- **Stack:** A pile of bricks is literally a stack – `placeBrick` corresponds to *push*, `pickBrick` to *pop*, `isBrick` to *not isEmpty*. This provides an entry point before students implement their own `Stack` class.
- **Remembering the way back:** The character stores every turn and every step in its own stack and later walks the way back in reverse.

The [supplementary notes on the core curriculum](https://cuvo.nibis.de/index.php?p=download&upload=788) (*Ergänzende Hinweise zum Kerncurriculum*, revised June 2025, binding for the Abitur examinations from 2027) specify the operations of `DynArray`, `Stack`, `Queue` and `BinTree` for the Abitur. Klonk does not include these classes; students implement them themselves as their own classes.

## Automata and formal languages

- **The character as an automaton:** States are, for example, “searching for the wall”, “building”, “done”; inputs are sensor values (`isWall()`, `isMark()`). The state diagram is drawn and implemented with a state variable and `switch`.
- **Mealy machine:** Every transition has an output – here an action of the character (`placeBrick`, `setMark`).
- **Formal languages (eA):** A subset of Klonk-Script (`step`, `turnLeft`, `repeat … times … end`) is described as a grammar. Since the editor reports syntax errors immediately, it can be checked whether a word belongs to the language.

## Project-based teaching

The core curriculum provides for project phases totalling at least eight weeks. [Projects](/en/klonk-script/projects) with several files and packages are suitable for teamwork: each person takes on one class, and test worlds from the [world editor](/en/world/editor) are stored as files in the project. Possible project topics: a maze solver, characters that carry out a construction plan from a JSON file, a small game with several characters.

## Databases

**Curriculum reference (short version):** *relational databases, anomalies, queries across several tables · eA: ER model*

**Use of Klonk:** [Databases](/en/klonk-script/databases) with SQLite or PostgreSQL, running in the browser without a server; databases are files in the project and can be handed out as assignments via [Klonk Cloud](/en/klonk-script/cloud). The ER model (eA) is created on paper or in a modelling tool – Klonk does not include an editor that creates tables from a drawn ER model. Klonk is used to implement and check the model: from the implemented schema, it generates an [ER diagram](/en/klonk-script/diagrams#er-diagram) (Chen, (min,max), crow's foot) and the relational schema.

- **Making anomalies visible:** A non-normalised table (e.g. loans with the student's name and class in every row) is created; `UPDATE` and `DELETE` reveal update and deletion anomalies. The table is then decomposed into several tables with foreign keys; the ER diagram before and after the decomposition makes the new structure visible.
- **Checking the ER model (eA):** The ER model designed on paper is implemented and compared with the ER diagram generated by Klonk. Switching between *Chen (1:n)* and *Chen (min,max)* shows how `NOT NULL` and `UNIQUE` on the foreign key determine the cardinalities.
- **Queries across several tables:** Joins with `JOIN`, grouping and aggregate functions on a school or library database; an existing SQLite file (`.db`) from the teacher can be imported.
- **Database and program:** A Python or Java program reads records with `Database.open(…)` and has a character display the result, for instance as a bar chart made of brick stacks (sample database `school.sqlite.sql`):

```python
from klonk import Klonk, Database

k = Klonk()
db = Database.open("school")
rows = db.query("""
    SELECT c.name, COUNT(s.id) AS number
    FROM classes c LEFT JOIN students s ON s.class_id = c.id
    GROUP BY c.id, c.name ORDER BY c.name
""")
for row in rows:
    print(row["name"], row["number"])
    k.turn_left()
    for i in range(row["number"]):
        k.place_brick()
    k.turn_right()
    k.step()
```
