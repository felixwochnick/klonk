## Context

The core curriculum applies to all secondary school types. At the Gymnasium, the competence expectations (*Kompetenzerwartungen*) printed in *italics* in the curriculum are also compulsory – relevant for the use of Klonk are **program flowchart/structogram**, **modularisation**, **determining the result of an algorithm by analysis** and **evaluating algorithms for their functionality**. Klonk is suitable above all for the content field algorithms; in the other content fields it can at most be used as a supplement.

| Content field (*Inhaltsfeld*) | Content focuses | Klonk |
|---|---|---|
| Information and data | Data and their encoding, information content of data, encryption methods | ★ |
| Algorithms | Algorithms and basic algorithmic concepts, implementation of algorithms | ★★★ |
| Automata and artificial intelligence | simple automata, machine learning with decision trees and (Gymnasium) neural networks | ★ |
| Computer systems (*Informatiksysteme*) | Structure and functioning, use of computer systems | ★ |
| Computer science, people and society | Computer systems in everyday life and the working world, data awareness, data security | – |

The core curriculum does not specify hours per content field. ## Algorithms

**Curriculum reference (short version):** *Unambiguous instructions; program flowchart (PAP, *Programmablaufplan*) and structogram; statement, sequence, conditional statement, loop; implementation in a visual programming language; modularisation; targeted testing*

**Competence expectations (short version):** formulate instructions and carry them out step by step · convert them into a program flowchart or structogram · recognise basic structures · implement algorithms in a **visual programming language** · modularise · check by testing · determine the result by analysis and evaluate functionality.

**Use of Klonk:** [Blocks](/en/klonk-script/blocks) meet the requirement for a visual programming language. With **Show Klonk-Script**, students see the same algorithm as text; this prepares the transition to a text-based language in grade 9.

**Lesson sequence:**

| Step | Competence | Task in Klonk |
|---|---|---|
| 1 | unambiguous instructions, carry out step by step | Unplugged: one child is “the character” and only carries out precise commands; then the same commands as blocks |
| 2 | Sequence | Lead the character to a target cell, place three bricks side by side |
| 3 | Loop | Walk around a square (`repeat 4 times`), walk to the wall (`repeat while not isWall`) |
| 4 | Conditional statement | Place bricks only on marked cells (`if isMark`) |
| 5 | Program flowchart/structogram | First draw the process, then implement it with blocks – or the other way round, represent a finished program as a structogram |
| 6 | Modularisation | A custom procedure (category “My blocks”) for a subtask that occurs several times |
| 7 | Testing, analysis, evaluation | Predict the result of a program, then run it; test the same program in several worlds |

```klonk
// Modularisation: a custom procedure for a subtask
procedure fencePost
  turnLeft
  placeBrick(green)
  turnRight
end

repeat while not isWall
  fencePost
  step
end
fencePost
```

## Calliope mini (example teaching unit 6.2)

In the Lehrplannavigator example, a microcontroller is programmed here. Klonk does not replace the **hardware** – sensors, LEDs and buttons only exist on the real device. If the unit is taught without a Calliope or is being prepared, the same competences (implementing and testing algorithms in a visual programming language) can be practised with Klonk: the character also has “sensors” (`isWall`, `isBrick`, `isMark`) and “actions”.

## Automata and encoding

- **Automaton:** The character reacts to its inputs (sensors) with actions. For a short program (e.g. “turn at the wall, otherwise step”), students draw a simple flow diagram and compare it with an automaton from their everyday lives.
- **Binary code:** A row of five cells forms a “section of a byte”: mark = 1, no mark = 0. Students lay out numbers with marks and read other students' rows as numbers.

## Computer systems: file management

In the [project explorer](/en/klonk-script/projects), students create a browser project with folders (e.g. `worlds/`, `programs/`). This provides an occasion to address the principles of **structured file management**.

## What Klonk does not cover

Encryption, artificial intelligence (decision trees, neural networks), data awareness and data security are better taught unplugged or with specialised materials such as those linked in the Lehrplannavigator.

## Matching learning modules

The [learning modules](/en/teaching/modules/overview) contain tasks in blocks or Klonk-Script with automatic checking that students can work on independently – in class or at home. The following modules fit the content area Algorithms:

- [First steps: instructions](/en/teaching/modules/sequence) – unambiguous instructions and sequence
- [Repetition with a fixed count](/en/teaching/modules/repeat) – loop with a fixed count
- [Conditional repetition](/en/teaching/modules/while) – loop with a condition
- [Branching](/en/teaching/modules/conditions) – branching
- [Your own procedures](/en/teaching/modules/procedures) – modularisation through custom procedures

## Notes for lesson planning

- **Prediction before running:** “How many bricks will there be at the end?” – students think about it and write down their prediction before running the program. This practises the competence expectation *determining the result by analysis*.
- **Single step and speed:** **Step** (F10) and the speed slider show which block is currently being executed. In case of errors, the block concerned is marked red.
- **Test worlds:** Several worlds (small, large, with obstacles) can be prepared in the [world editor](/en/world/editor) and distributed as files. Whether the solution works in all worlds makes *targeted testing* concrete.
- **Debugging for evaluation:** The teacher provides a faulty program; students find the faulty spot using breakpoints (right-click on a block) and explain why the program does not work. This task format is also suitable for assessment.
