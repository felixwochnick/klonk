## 2.6.1 Modelling and Coding Algorithms

**Content related to the competences (summary):** *Concept of an algorithm; notations (structogram, pseudocode, flowchart); syntax and semantics; development environment (syntax highlighting, compilation, debugging); data types (numbers, characters, strings, Boolean values, arrays); functions with parameters and return values; structured debugging with breakpoints and variable values*

**Competence expectations (summary):** model processes – the curriculum gives the *conditional movement of a robot* as an example – with basic algorithmic building blocks · write source code from the model · program clearly with variables, data types, functions and comments · check programs and fix errors.

### Use of Klonk

The curriculum provides for a **modern, text-based programming language**. In Klonk, [Python](/en/klonk-script/python) and [Java](/en/klonk-script/java) are available for this – each with the same world and the same types of tasks as in the foundation course. Klonk-Script can serve as a transition, but has no arrays (lists); Python or Java is required for this content.

| Content according to the curriculum | Implementation in Klonk |
|---|---|
| Algorithm, conditional movement of a robot | The character walks to the wall, avoids bricks, searches for a mark |
| Notations | first a structogram or flowchart, then code – the run in the world shows whether model and program match |
| Syntax and semantics | the editor underlines syntax errors while typing; runtime errors (the character walks into the wall) reveal errors in meaning |
| Development environment | syntax highlighting, suggestions while typing, compilation (Java), debugger – all in the browser |
| Data types | numbers (`brick_count()`), Boolean values (`is_wall()`), strings (`print`), arrays: a list of colors |
| Functions with parameters and return value | `def lay_row(robot, colors)` returns the number of bricks placed |
| Structured debugging | set a breakpoint, single step, variables view – in line with the description in the curriculum |

```python
from klonk import Klonk, red, blue, green

klonk = Klonk()


# Places bricks to the left of the path in the colors of the list
def lay_row(robot, colors):
    placed = 0
    for color in colors:
        if robot.is_wall():
            break
        robot.turn_left()
        robot.place_brick(color)
        robot.turn_right()
        robot.step()
        placed += 1
    return placed


count = lay_row(klonk, [red, blue, green, red])
print("Bricks placed:", count)
```

### Teaching ideas

- **From the foundation course to a text-based language:** A Klonk-Script or block program from module 1.2 is transferred to Python. Students recognise the same control structures with different syntax.
- **Debugging as a task:** The teacher hands out a program with a built-in bug (e.g. a wrong termination condition). Using a breakpoint and the variables view, students identify the point where `placed` or the position is no longer correct.
- **Testing in several worlds:** The same function is run in a small, a large and a cluttered world; students check whether it works correctly in all cases.

## 2.6.2 Object-Oriented Software Development

**Content related to the competences (summary):** *Phases of software development; class diagram, activity diagram, structogram; structuring, modularisation; testing and optimisation*

### Use of Klonk

[Java](/en/klonk-script/java) is the obvious choice of language (alternatively Python). Every character is an object of the class `Klonk` (`new Klonk("Klara")`); this allows the concepts of object, attribute and method to be illustrated directly.

- **Class diagram of a custom class:** e.g. `BuildCrew` with the attributes *character*, *color*, *placed* and the methods `place()` and `build()`. The class `Klonk` is `final`; custom classes therefore hold a character as an attribute.
- **Modularisation:** In a [project](/en/klonk-script/projects), students spread their classes across several files.
- **Phases of software development:** analysis (what should be built?), design (class diagram), implementation, testing in several worlds, optimisation (fewer steps, shorter code).

## 2.7.2 Robotics and Embedded Systems

**Content related to the competences (summary):** *Sensors and actuators; models for planning processes (flowchart, structogram, state transition diagram); closed-loop and open-loop control by evaluating sensors; testing and optimisation*

### Use of Klonk

The module provides for equipping and programming a **real robot** or embedded system with components; Klonk cannot replace this. However, Klonk is suitable as a **simulation for preparation**:

- **State transition diagram:** The behaviour of a character is planned in states (*driving*, *avoiding*, *done*) and implemented as a program.
- **Line following in the simulation:** A track of marks is laid in the world editor; the character follows it with `is_mark()`. This prepares the curriculum's example before work continues with hardware and real sensors.
- **Evaluating sensors:** The wall and brick sensors are discussed as a simplified model of real sensors – including how a real sensor differs (measurement errors, measuring range).

## 2.8.5 IT Project

**Content related to the competences (summary):** *Project phases; teamwork; example topics such as developing learning software*

### Use of Klonk

Possible project topics:

- **Learning course:** A team creates task worlds for younger classes and writes model solutions in Klonk-Script.
- **Construction site:** A program builds a building out of bricks; several groups each take on one construction section.
- **Custom characters:** Characters designed in the [design editor](/en/world/designs) (license feature) appear in a project world.

## Matching learning modules

The [learning modules](/en/teaching/modules/overview) contain tasks in blocks or Klonk-Script with automatic checking that students can work on independently – in class or at home. Before the transition to a textual language in module 2.6.1, they can serve to revise the initial instruction (module 1.2); the tasks themselves are not set in Python or Java:

- [Repetition with a fixed count](/en/teaching/modules/repeat) – repetition with a fixed count
- [Conditional repetition](/en/teaching/modules/while) – conditional movement of a robot with loops and sensors
- [Branching](/en/teaching/modules/conditions) – branching
- [Your own procedures](/en/teaching/modules/procedures) – decomposition and parameters as preparation for functions with parameters
- [Variables and counting](/en/teaching/modules/variables) – variables

## Notes for lesson planning

- **Exam preparation:** Module 2.6.1 is one of the six modules of the voluntary IT final examination. Tasks with Klonk can be used as supplementary preparation.
- **Task worlds:** Small, large and cluttered worlds for testing can be prepared in the [world editor](/en/world/editor) and distributed as files.
- **License:** More than one character at a time requires a [license](/en/administration/license). Without a license, every object works with the same character; this is sufficient for custom classes in module 2.6.2.

## Other modules

Word processing, spreadsheets, database systems, CAD, data networks, logic circuits, artificial intelligence and multimedia are not covered by Klonk. For logic circuits, the operators `and`, `or`, `not` in conditions can at most be mentioned as a cross-reference – Klonk does not simulate circuits.
