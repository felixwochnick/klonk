title: Teamwork in subgroups
description: Teachers divide a class into teams – with a shared project everyone edits at the same time, or a shared world in which everyone programs their own character.
---

Within a class, teachers can form **subgroups** (teams). Each subgroup works together in one of two ways:

| Mode | How students work | Suitable for |
|---|---|---|
| **Shared project** | All members open the same project and edit its files at the same time. The others' changes and cursors appear instantly – much like a document edited together. | Pair programming, team tasks, designing a program together |
| **Shared world** | Everyone programs in their own project. All characters stand in the same world; everyone controls their own character. | Agreements and division of labour (e.g. building something together), competitions, watching programs run at the same time |

## Creating subgroups

In the app under **Teaching** → class → **Progress and release**, section **Subgroups**:

- **New subgroup:** name, mode of collaboration, the language for a shared project (Klonk creates the starter files) and the members from the class.
- **Form random teams:** splits all learners who are not in a subgroup yet evenly into teams of the chosen size.
- **Open project** or **View world:** the teacher opens the shared project in the IDE or watches the shared world without controlling a character – for example on the projector.

Subgroups are managed by the class leader (and the school's admins) without being a member. A person can belong to several subgroups; anyone who leaves the class also leaves its subgroups. Subgroups do not appear as classes of their own in the administration or in the **Teaching** overview.

## Shared project

- Learners find the project under **Projects** → **Klonk Cloud** → **Groups**, e.g. as “Team 1 (7a)”.
- Text programs (Klonk-Script, Python, Java, JavaScript, TypeScript, C#) are merged character by character. The others' cursors and selections appear in colour with their names, and the tabs show who has which file open.
- **Blocks** are merged per block stack: if several people work on different stacks, all changes arrive; on the same stack the most recent change wins.
- Saving works as usual when running and with Ctrl+S. Whoever saves saves the shared state – for the others the unsaved-changes marker disappears.
- Everyone runs the program in their own world.
- If the connection drops, the app keeps working with its own state and merges the changes after reconnecting.
- In the shared folder of a whole class, too, everyone who may write there edits the files together.

## Shared world

- Learners join in the IDE via **Shared world** in the toolbar, or in the explorer via the icon next to the subgroup.
- On first joining, everyone gets a character with their name. The characters of the start world – the world file in the subgroup's shared folder – are **starting places**: position, facing direction and look, in the order people join. The teacher can adjust the start world in the world editor. If there are more people than starting places, the extra characters stand on free cells.
- Programs control their own character: in Klonk-Script and blocks from the start, in the other languages with `new Klonk()` without a name. Other characters can be queried (e.g. their position) but not controlled; sensors such as `isWall` see what the others are doing right now.
- New characters (`create`, `Klonk.create`) belong to the person whose program creates them – within the licence.
- **Reset world** restores the start world for everyone; running programs stop.

## Teaching notes

- **Switch roles:** a shared project lends itself to pair programming – one person writes, the other reads along and checks; switch after a fixed time. The cursors show who is working on what.
- **Make agreements visible:** in the shared world the characters have to share the space. If a character walks onto an occupied cell, its program stops with a message – a good opportunity to talk about agreements and order.
- **Division of labour:** everyone takes on part of a building or a marking; the result emerges together in the world.

## Technology and data protection

- Collaboration runs over a WebSocket connection to the app's server. When self-hosting there is nothing else to set up; the bundled proxy forwards it.
- The shared editing state and the shared world are kept only in the server's memory and disappear a few minutes after everyone has left. Data is stored permanently only via [Klonk Cloud](/en/klonk-script/cloud).
- If several instances of the app run behind a load balancer, all members of a subgroup must reach the same instance.
